# TC-09 控制台（CON）

优先级 **P1** · 约 30 min

三种控制台，链路不同：

| 类型 | 路由 | 后端 | 说明 |
|---|---|---|---|
| 图形（VNC） | `/console/:id` | consoleproxy → QEMU VNC | 自带 `@novnc/novnc` 1.6.0 |
| 文本（串口） | `/serial-console/:id` | consoleproxy(serial) → socat → pty | 只对把串口作为登录终端的系统有效（Ubuntu 云镜像默认开启，**Windows 无输出**） |
| 计算节点终端 | `/host-console/:uuid` | consoleproxy(serial) → socat → root shell | 仅系统管理员，默认**关闭** |

三者共用 consoleproxy（libvirt 官方 `virtconsoleproxyd`）。

## CON-01 图形控制台（VNC）

**P1** · 脚本 `console-e2e.js` / `vnc-check.js`

### 步骤

虚拟机列表或详情 → 「控制台」→ **新窗口**打开 `/console/:id`。

### 检查项

- [ ] 打开的是**自带页面** `/console/:id`，**不是** `https://novnc.com/noVNC/vnc.html?...`
  > **回归点**：原先打开第三方站点，token 泄露到第三方、整台虚拟机的键鼠交给第三方 JS、私有化环境不可用。
- [ ] 全程**无第三方请求**
- [ ] 1–2 秒内连上，收到 `RFB 003.008`
- [ ] 窗口继承 sessionStorage 登录态（链接**不带 noopener**）

### 键盘

脚本 `kbd-e2e.js`（临时 Ubuntu 虚拟机，经控制台粘贴登录后用 guest agent 逐字节比对）：

- [ ] Ctrl / Alt / Win **锁定键**生效
- [ ] Tab / Esc / Ctrl+Alt+Del
- [ ] F1–F12、Ctrl+Alt+F1–F6（期间 `fgconsole` = 对应值）
- [ ] 「粘贴为键入」逐字模拟按键，含全部可打印符号的 heredoc 粘贴后 guest 内**逐字节一致**
- [ ] 锁定 Ctrl 后按 C 能中断 `sleep`

> ⚠️ 以 keysym（不带 code）发送时 **QEMU 不会自动补 Shift**（`A`→`a`、`>`→`.`）。需要 Shift 的字符（大写与 ``~!@#$%^&*()_+{}|:"<>?``）由前端显式按住 `Shift_L`，按美式键盘布局。特殊键与字符走**同一个发送队列**保证顺序。

### 虚拟键盘

脚本 `vk-e2e.js`：

- [ ] 工具栏键盘按钮开关，面板在画面下方，美式布局 80 键（F1–F12 / Ins / Del / Home / End / PgUp / PgDn / 方向键）
- [ ] 虚拟键盘上的 Shift / Ctrl / Alt / Win 是**单次生效**（按下一个键后自动松开）；工具栏上的是**锁定**
- [ ] Caps 在浏览器端模拟，**不改动虚拟机的大写锁定状态**
- [ ] 逐个点击输入含全部 Shift 符号的命令，虚拟机内核对正确
- [ ] Backspace / ← / End 正确

### 布局

- [ ] 打开键盘时整页**不被撑高**、顶部工具栏不被挤出屏幕（`.console-main` 必须 `min-height: 0`）
- [ ] 1400×900 与 iPhone 13 视口下，工具栏和键盘都在屏幕内
- [ ] 窄屏打开键盘时，工具栏里重复的按键组（`key-group-extra`）被隐藏

### 其他

- [ ] `resizeSession=false`（QEMU 拒绝调整分辨率）
- [ ] 剪贴板同步（qemu-vdagent）**未实现**，不要当缺陷

## CON-02 文本控制台（串口）

**P1** · 脚本 `serial-e2e.js` / `serial-check.js`

### 链路

```
POST /instances/{id}/console  {"type":"serial"}     (缺省 vnc)
  → token 声明 consoleType，consoles 表按 (instance, type) 各一条
  → 解析 token 时下发 start_serial_console.sh <id>
     virsh ttyconsole 取模板里已有的 <serial type='pty'>（存量虚拟机无需改 XML / 重启）
     console_bridge.sh 用 socat 在节点内网 IP 的 16000–16999 随机端口做一次性转发（无 fork，单连接）
  → 监听就绪后才回调 start_serial_console.sh '<id>' '<port>' '<ip>'
     clapi 只接受实例所在节点的回调，写 serial_consoles 表
  → resolver 返回 {type: serial, address, insecure: true}
```

### 检查项

- [ ] 虚拟机列表 / 详情菜单有「文本控制台」
- [ ] 打开后拿到登录提示（Ubuntu 云镜像）
- [ ] UTF-8 收发正确（中文与符号写文件后 guest 内核对一致）
- [ ] Ctrl+Shift+C / V 与按钮复制粘贴；`term.paste` 走 **bracketed paste**，多行粘贴**不会逐行执行**
- [ ] Ctrl+C 生效
- [ ] 与图形控制台能互相切换

### 「同步窗口大小」

发送的是 ` stty rows/cols`，**是当作键盘输入打进去的**。曾在登录提示处被当成用户名。

脚本 `sync-e2e.js`：

- [ ] 只在光标所在行以 `$ # % >` 结尾**且不是续行提示 `>`** 时才发送
- [ ] 登录提示处、半输入的命令处、续行处 → **拒绝发送并给黄字提示**
- [ ] 发送时带前导空格（不进 history）
- [ ] 发送后 `stty size` 与窗口一致

### 安全

串口**无密码**，而节点 INPUT 对 10/8、172.16/12、192.168/16 全放行。所以桥接进程在 INPUT 链**最前面**插入：只放行 `CLAND_ENDPOINT` 的 IP、clapi 传来的本机 `INTERNAL_IP`、本机 consoleproxy 容器 IP，其余 DROP。

- [ ] 从**其他计算节点**直连该端口：被拦截
- [ ] 从控制节点：可连
- [ ] 会话结束后端口、iptables 规则、pid 文件**全部清零**
- [ ] **60 秒无人连接自动关闭**

> HA 控制面里 consoleproxy 出去的源地址是节点主地址而不是 keepalived 的 VIP，**只放行 VIP 会全部 DROP**。

### 会话隔离

- [ ] 同一实例**同时打开两次**，两个都能用（最新的一定可用）
  > **回归点**：原先按实例等「任意新记录」，同时打开两次会互拿端口导致**都失败**。现在每次解析生成随机会话 ID 传给脚本并随回调带回，按 (instance, session) 取记录、用完即删。
- [ ] 同一实例再次打开时，先结束旧会话
- [ ] 超过 10 分钟的记录（含已删实例）被顺带清理

### 重连

脚本 `reconnect-e2e.js`：

- [ ] 旧 socket 关闭**不会掩盖**新尝试或其失败

## CON-03 计算节点终端

**P1** · 脚本 `hostconsole-live.js` / `hostconsole-token.js` / `hostconsole-fixes.js`

> ⚠️ 测试前要打开 `HOST_CONSOLE_ENABLED`，**测完必须关回 false**（见 `00-收尾检查.md` C-08）。

### 前置

```bash
# 打开开关（改 HOST_CONSOLE_REQUIRE_PASSWORD 本身必须带密码，这里只开 ENABLED）
ssh work-01 'source /root/alarmtest-env.sh; api PUT /system/settings "{\"HOST_CONSOLE_ENABLED\":true}"'
```

### 链路与权限

- `POST /hypers/:uuid/console`（cpgateway 代理白名单 Admin 路由）
- `apis/host_console.go` 校验请求体 `password` 后**去掉再转发**
- clapi `ConsoleAPI.CreateHost` 要求：`CheckSystemPermission` + 系统设置 `HOST_CONSOLE_ENABLED` + 节点状态 0/1/2
- 签发 **2 分钟、一次性** token
- consoleproxy 解析 token 时 clapi `resolveHost` **再查一次开关**

### 检查项

- [ ] 系统管理员在计算节点列表 / 详情的操作菜单看到「终端」
- [ ] **非系统管理员**看不到 / 点不动
- [ ] 开关关闭时菜单项被禁用并提示原因
- [ ] 输入当前账号密码后 1–2 秒拿到 **root shell**（三个节点都测，含控制节点自身与跨节点）
- [ ] `stty size` 与窗口一致

### 安全

- [ ] shell 以 `env -i` 启动：`GRPC_AUTH_TOKEN` / `NODE_ID` / `CLAND_ENDPOINT` 在 shell 内**均为空**
- [ ] 会话记录落在 `/opt/cloudland/log/host_console/<时间>-<用户>-<session>.log`（目录 700、文件 600）
  - `script -q -f -a` **只记录终端输出，不记录键盘输入** → 不回显的密码不会进记录
  - 启动时删除 180 天前的记录
- [ ] 空闲 `HOST_CONSOLE_IDLE_MINUTES` 分钟后断开（5–240，默认 15）
- [ ] 60 秒无人连接自动关闭
- [ ] 关闭窗口后节点上的端口 / iptables 规则 / 进程 / pid **全部清零**
- [ ] 审计动作 `hyper.console`，组织动态文案「打开了计算节点 X 的终端」

### token

脚本 `hostconsole-token.js`：

- [ ] token **用过一次即失效**
- [ ] **关闭开关后，已签发的 token 也连不上**
- [ ] 关闭开关后再签发直接 403

### 密码与限流

- [ ] 密码错误 → **403**，留在密码框显示原因，cpgateway 记 warning
- [ ] 10 分钟内错 5 次 → 第 6 次**和正确密码都返回 429**
- [ ] 重启 cpgateway 后计数清零（计数在内存）
- [ ] **并发绕过被堵死**：50 个并发 goroutine 只放行 5 个（`go test -race`，见 `TC-01 BUILD-07`）
  > **回归点**：原先「读计数」与「记失败」分两次加锁，中间隔着约 100ms 的 bcrypt，并发请求全读到 0 可绕过限制。现改为「**先占名额再校验密码**」（`reserveHostConsoleAttempt` / `clearHostConsoleAttempts`），超限的尝试不再记录以免无限延长锁定窗口。

### 前端状态机

- [ ] 终端页**每次先不带密码请求**，网关返回 400「Password is required」才显示密码框
  > **回归点**：`status` 初值必须是 `connecting`。设成 `auth` 会被「表单未填密码」的守卫挡住，首次请求发不出去。
- [ ] 只把「**不带 error_code 的** 403/429」当密码错误；clapi 的 403（功能关闭、非系统管理员）显示**错误页**
  > **回归点**：否则会反复要求重输密码。
- [ ] 重新连接必须重新输密码

### HOST_CONSOLE_REQUIRE_PASSWORD

- [ ] 关闭后打开终端不再要密码
- [ ] **改这一项本身必须带密码**：`PUT /system/settings` 的 body 里放 `password`，cpgateway `verifyHostConsoleSettingPassword` 校验，走同一套 5 次/10 分钟限流
- [ ] `password` 不是设置键，会被 `FindSettingMeta` 过滤掉**不落库**
- [ ] 设置页**拨动开关就立刻弹密码框**（不是点「保存」时才弹）
  > 第一版做成点保存时才弹，用户反馈「开关没有提示要密码」。服务端一直是拦着的，只是界面提示时机不对。
- [ ] 确认后**只保存这一项**（其他未保存的改动会在重新加载设置后恢复）
- [ ] 取消则把开关**拨回原位**
- [ ] 密码错误留在弹框里显示

### iptables 打桩

- [ ] `console_bridge.sh` 的 iptables 插入带 `-w 5` 并**检查返回值，失败即 `die`**
  > **回归点**：该规则是端口**唯一的**访问控制。节点上心跳与 LB 守护脚本每 1–20 秒大量调 iptables，撞 xtables 锁会静默失败；之前失败仍会启动 socat，等于把**无认证 root shell 暴露给整个私网**。
- [ ] cleanup 只删**真正插入成功**的规则
- [ ] `start_console_bridge` 连续 3 次进程异常退出就放弃（端口已预检，失败不是端口占用）
- [ ] 打桩让 iptables 失败时：**不开端口、不留规则、请求报错**

### 收尾

```bash
ssh work-01 'source /root/alarmtest-env.sh; api PUT /system/settings "{\"HOST_CONSOLE_ENABLED\":false}"
api GET /system/settings | jq -c "[.settings[]?|select(.key|startswith(\"HOST_CONSOLE\"))|{key,value}]"'
```

- [ ] `HOST_CONSOLE_ENABLED` 回到 **false**

## 历史缺陷回归点汇总

| # | 现象 | 根因 |
|---|---|---|
| 1 | noVNC 控制台**完全不可用**，clapi 轮询 45 秒后 500 | gorm v1.31 的 `Delete` 会把 `DeletedAt` **写回传入的结构体**，之后 `Where(同一结构体)` 会带上 `deleted_at = <删除时间>`，与软删除自动加的 `deleted_at IS NULL` 矛盾，永远查不到。节点回调其实已正常写入。修的是 `rpcs/console_resolve.go` |
| 2 | 同一实例开两个串口控制台，两个都失败 | 按实例等「任意新记录」，互拿端口 |
| 3 | 「同步窗口大小」在登录提示处被当成用户名 | 无条件发送 |
| 4 | 主机终端限流可被并发绕过 | 读计数与记失败分两次加锁 |
| 5 | iptables 插入静默失败仍启动 socat | 未检查返回值、未加 `-w` |
| 6 | 关闭开关后终端页反复要求重输密码 | 把 clapi 的 403 也当密码错误 |
| 7 | 主窗口刷新把控制台窗口的 token 吊销 | `Layout.vue` 每次加载都 `switch-org`，见 `TC-12 UI-07` |
