# TC-09 控制台（CON）

优先级 **P1** · 约 60 min（含建测试虚拟机；CON-03 的限流项要等 10 分钟窗口）· 建资源（一台 `wp-con`），**不占公网 IP**

三种控制台，链路不同：

| 类型 | 路由 | 后端 | 说明 |
|---|---|---|---|
| 图形（VNC） | `/console/:id` | consoleproxy → QEMU VNC | 自带 `@novnc/novnc` 1.6.0 |
| 文本（串口） | `/serial-console/:id` | consoleproxy(serial) → socat → pty | 只对把串口作为登录终端的系统有效（Ubuntu 云镜像默认开启，**Windows 无输出**） |
| 计算节点终端 | `/host-console/:uuid` | consoleproxy(serial) → socat → root shell | 仅系统管理员，受系统设置 `HOST_CONSOLE_ENABLED` 控制 |

三者共用 consoleproxy（libvirt 官方 `virtconsoleproxyd`，`https://consoleproxy:9443`，解析 token 调 clapi 内部口 `http://clapi:5005/consoleresolver/token/<token>`）。浏览器连的是接口返回的 `console_url` = `wss://<console.host>/websockify?token=...`，nginx 把 `/websockify` 转给 consoleproxy。

> **`console.host` 在 work-01 上是公网 IP `169.61.110.83`**（2026-09-28 核对）：`.env` 的 `CONSOLE_HOST` 为空，clapi 读配置文件 `/opt/cloudland/web/conf/config.toml` 的 `[console] host = "${PUBLIC_IP}"`（`deploy/docker/scripts/web-entrypoint.sh` 生成）。所以**不管页面从哪里打开，websocket 都直连 work-01 公网 443**。

## CON-02 文本控制台（串口）

**P1** · 脚本 `serial-e2e.js` / `serial-check.js`

### 链路（2026-09-28 按代码核对）

```
POST /instances/{id}/console  {"type":"serial"}     (no body = vnc; other values 400)
  → token claim consoleType=serial; consoles table keeps one row per (instance, type)
  → consoleproxy resolves the token: clapi relayConsole generates a random 32-hex session and runs
     start_serial_console.sh '<id>' '<session>' '<proxy_source>'      (proxy_source = clapi INTERNAL_IP)
     virsh ttyconsole <domain> (the rescue domain inst-<id>-rescue when it exists)
     console_bridge.sh: socat on the node's address towards cland, random port 16000-16999, single connection
  → once listening: callback start_serial_console.sh '<id>' '<session>' '<port>' '<node ip>'
     clapi accepts it only from the node running the instance, writes serial_consoles (instance, session)
  → clapi waits up to 20 s (40 x 0.5 s) for that session's row, deletes it, returns {type: serial, address, insecure: true}
```

