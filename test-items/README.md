# CloudLand 回归测试套件

本目录是 CloudLand 的回归测试清单。每个文件对应一个功能域，内含可直接执行的步骤、明确的检查项、涉及的接口，以及**历史缺陷回归点**（曾经真实出过问题、必须每轮复查的地方）。

## 怎么用

1. 先读 [`00-环境与前置.md`](00-环境与前置.md)，把环境准备好（登录函数、Playwright 容器、配额、**保留资源禁改清单**）。
2. 按下表顺序执行。`P0` 必跑；`P1` 建议跑；`P2` 仅在改动涉及该域时跑。
3. 每个用例做完按「清理」小节收尾，最后跑 [`00-收尾检查.md`](00-收尾检查.md) 确认环境回到基线。

## 用例编号

`<域缩写>-<两位序号>`，例如 `LB-04`。编号一经分配不复用，废弃的用例标注「已废弃」保留占位，便于对照历史执行记录。

## 通过标准

一轮回归判定为**通过**，需同时满足：

- 所有 P0 用例的检查项全部通过，无 `FAIL`。
- P1 用例的失败项都有对应的缺陷记录，且经确认不是本次改动引入。
- 收尾检查全绿：测试资源清零、保留资源（`rb-*` 一整套）完好、三节点在线。

任何一条 P0 失败即判定**不通过**，不允许以「与本次改动无关」为由放行 —— 先定位是谁引入的。

## 记录方式

每轮执行在 `runs/` 下建一个 `YYYY-MM-DD-<被测版本 commit>.md`，逐条记 `PASS` / `FAIL` / `SKIP` 与证据（命令输出、截图路径）。`FAIL` 必须附上定位结论。

## 维护约定

- **修一个 bug，就往对应文件的「历史缺陷回归点」加一条**，写清现象、根因、判定方法。这是本套件最有价值的部分。
- 新增接口或页面时补对应用例；删除功能时把用例标注「已废弃」而不是删掉。
- 自动化脚本统一放在 work-01 的 `/root/console-test/`（浏览器）与 `/root/*.sh`（API），文件名在用例里注明。**脚本是用例的实现，不是替代**：脚本跑通不等于用例通过，检查项仍需逐条确认。
