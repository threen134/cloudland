# TC-06 负载均衡（LB）

优先级 **P0** · 会在计算节点上起 keepalived / haproxy 进程 · 约 40 min

> 🚫 **测试必须建在临时 VPC 里，不要在 `rb-vpc` 里加 LB。** 同一 VPC 的多个 LB 共用 VRRP 子网网卡 `ns-<vni>`，在保留环境里加 LB 有破坏 `rb-lb` 的风险。
> 全程每做完一步都回头确认 `rb-lb` 仍是 10/10。

## 设计约定（判定预期的依据）

- 每个 LB 一个 VRRP 实例，主备各在一个节点（zone 内 `select=` 调度，第二个节点排除主节点）。
- VPC 路由器 netns 内跑 **keepalived**（浮动 IP 挂在 `te-<router>-<vlan>`）和 **haproxy**（`source` 用本端 VRRP 地址访问后端）。
- 配置目录：`/opt/cloudland/cache/router/router-<N>/{vrrp-<id>,lb-<id>}/`
- keepalived 两端都以 `state BACKUP` + `nopreempt` 启动，按角色给优先级（MASTER 110 / BACKUP 100）。**写 `state MASTER` 时 nopreempt 不生效**，进程重启会抢回主。
- haproxy 的 server 名是 `be-<backend ID>`。
- 计算节点必须装 haproxy，且**系统自带的 `haproxy.service` 要禁用**。

### ⭐ 最容易误判的一点

**创建 LB 时节点上只建 VRRP 网卡与地址，不起 keepalived / haproxy。**

`create_keepalived_conf.sh` 收到的 `floating_ips` 为空时，会**删掉 `vrrp-<id>` 目录并退出**。所以「LB 状态 `available`，但节点上既没有 `vrrp-<id>` 目录也没有进程」是**正常的**。要**绑定浮动 IP 之后**两个进程才起来。

（`create_haproxy_conf.sh` 也要先有 `vrrp-<id>/keepalived.conf`，否则报 `No such file or directory`。）

排查顺序：`vrrp_instances` 的 `hyper`/`peer` 是否落库 → 节点上有没有 `ns-<vrrp vlan>` 与地址 → 有没有浮动 IP。

## LB-06 haproxy 重载不丢请求

**P1**

对一个**有真实后端**的 LB（可用 `rb-lb`，但**只做只读的流量压测，不要改它的配置**；或在临时 LB 上挂一个真后端）反复改后端触发重载，同时打流量。

```bash
ssh work-01 'ok=0; fail=0
for i in $(seq 1 400); do
  curl -s -m 3 -o /dev/null http://<浮动IP>/ && ok=$((ok+1)) || fail=$((fail+1))
done; echo "成功 $ok 失败 $fail"'
```

- [ ] 重载期间失败数为 **0**
  > **回归点**：haproxy 重载必须带 `-x <lb 目录>/admin.sock`（stats socket 已开 `expose-fd listeners`）接管旧进程的监听 socket。只用 `-sf` 时实测 6 次重载丢 4 个请求；加 `-x` 后 0 个。

## LB-07 进程守护与并发

**P1**

```bash
# 杀掉备节点的 haproxy，等下次心跳（1–20 秒随机）拉起
ssh work-0X 'ip netns exec router-<N> pkill -9 haproxy; sleep 25; ip netns exec router-<N> pgrep -c haproxy'
```

- [ ] haproxy 被杀后下次心跳拉起（最坏中断近 20 秒）
- [ ] 主节点 keepalived 父进程 `kill -9` → 子进程随之退出并**自行摘除浮动 IP**，丢 1 个请求
- [ ] 主节点全部进程同时 `kill -9` → 对端**立即接管、0 失败**，残留浮动 IP 约 15 秒后由守护脚本摘除
- [ ] 被拉起的 keepalived **即使优先级更高也不抢主**

### 并发互斥

「判断存活 → 替换配置 → 启动/重载」用 `flock $run_dir/lb_process.lock` 互斥；守护脚本拿不到锁就跳过本轮。

```bash
ssh work-0X 'for i in $(seq 1 15); do /opt/cloudland/scripts/backend/check_lb_process.sh & done; wait
ip netns exec router-<N> pgrep -c haproxy'
```

- [ ] 15 个并发守护脚本之后，haproxy 进程数仍是 **1**
  > **回归点**：无锁时实测起出 15 个 haproxy。另外，**持锁时启动的 keepalived / haproxy 必须带 `9>&-`**，否则守护进程继承描述符、锁永远不释放。

## 手工起 keepalived 的注意事项

`notify_master`（`set_route_table.sh`）依赖环境变量 `ROUTES_FILE` / `KEEPALIVE_CONF` 恢复 fip 路由表的默认路由。浮动 IP 被摘除时该默认路由随之消失，**手工启动 keepalived 必须带上这两个变量**（用 cloudrc 的 `start_keepalived`），否则切换后回包出不去。

## 从路由器 netns 验证后端

必须用 `curl --interface <VRRP 地址>`。VPC 网关与 VRRP 子网网关都是 anycast，默认源地址的回包会落到本地路由器。
