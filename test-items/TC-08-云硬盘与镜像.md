# TC-08 云硬盘与镜像（VOL）

优先级 **P1** · 会创建卷与镜像 · 约 25 min

## 设计约定 — 本地数据卷

> **2026-09-22 起卷归属存储池**，池本身的用例在 [`TC-16-本地存储池.md`](TC-16-本地存储池.md)。本文件只管卷与镜像。

- **创建时不落盘**：`volumes.hyper=0`，直接 `available`；建卷时可以选存储池，不选就是内置池 `local`
- **路径由 clapi 下发**，`volumes.path` 是**相对池根**的相对路径：内置池数据盘 `volume/volume-<id>.disk`，其他池 `volumes/volume-<id>.disk`（池根 `/opt/cloudland/pools/<池UUID>`）
- **首次挂载时**才由 `attach_volume_local.sh` 在**虚拟机所在节点**创建，并记录 `hyper`；clapi 下发 `new` / `existing`，**`existing` 时文件不在就报错**，不再新建空盘
- 已落盘的卷只能挂给**同节点、且该节点有这个池**的虚拟机
- **删除是异步的**：接口返回 **202**，卷进 `deleting`，节点回调 `clear_volume` 才删记录；节点离线直接拒绝；30 分钟没回调转 `delete_failed`（可以重删）
- 卸载成功后节点上的磁盘描述文件会被删除
- 迁移完成后随虚拟机更新 `hyper` 与池
- 删除虚拟机时卷变 `available`、`instance_id` 清空，**卷文件保留**（`lost` / `orphaned` 的卷不动）

> `GET /volumes` 默认**只列数据盘**，要含系统盘得带 `type=all`。配额对账用的是 `type=all`。

## VOL-01 创建与挂载

**P1**

```bash
ssh work-01 'source /root/alarmtest-env.sh
cat > /tmp/v.json <<JEOF
{"name":"wp-vol","size":5}
JEOF
V=$(curl -sk -X POST "$B/volumes" -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d @/tmp/v.json | jq -r .id)
echo "卷=$V"
api GET /volumes/$V | jq -c "{name,size,status,hyper}"

I=$(api GET /instances | jq -r ".instances[]|select(.hostname==\"wp-vm\")|.id")
cat > /tmp/a.json <<JEOF
{"instance":{"id":"$I"}}
JEOF
curl -sk -X PATCH "$B/volumes/$V" -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d @/tmp/a.json | jq -c "{name,size,status}"
sleep 15; api GET /volumes/$V | jq -c "{name,status,hyper,target}"'
```

### 检查项

- [ ] 创建后直接 `available`，`hyper=0`（未落盘）
- [ ] 挂载后 `status` 经 `attaching` → `in_use`
- [ ] 挂载后 `hyper` 变成虚拟机所在节点的 hostid
- [ ] 节点上出现磁盘文件（路径 = 池根 + `volumes.path`）
  ```bash
  ssh work-0X 'ls -la /opt/cloudland/cache/volume/'                      # 内置池
  ssh work-0X 'ls -la /opt/cloudland/pools/<池UUID>/volumes/'            # 其他池
  ```
- [ ] 实例详情的 `volumes` 数组里这一项**带 `size`**
- [ ] 盘符是下一个空闲 vdX
  > **回归点**：第二块本地数据卷曾总是分到 vdb（原按 WDS 的 `type='network'` 计数）。挂第二块时确认是 **vdc**。

## VOL-04 卸载与删除

**P1**

- [ ] 卸载后 `status` 回到 `available`、`instance_id` 清空，节点上的磁盘描述文件被删
- [ ] 删除返回 **202**，卷经 `deleting`，节点回调后记录消失、磁盘文件被删
- [ ] 未落盘的卷删除时只改记录，立即消失
- [ ] 节点离线时删除被**直接拒绝**（不是静默丢弃）
- [ ] 人为丢掉回调，30 分钟后变 `delete_failed`，不能挂载，再次删除成功
- [ ] 删除 202 时网关**立即释放**磁盘配额

## VOL-06 镜像导入

**P1**

```bash
ssh work-01 'source /root/alarmtest-env.sh
cat > /tmp/img.json <<JEOF
{"name":"wp-img","download_url":"http://<可达地址>/cirros-0.6.2-x86_64-disk.img",
 "os_code":"cirros","os_family":"linux","os_version":"0.6.2","user":"cirros","boot_loader":"bios"}
JEOF
curl -sk -X POST "$B/images" -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d @/tmp/img.json | jq -c "{id,name,status}"'
```

必填：`name` / `download_url` / `os_code` / `os_family` / `os_version` / `user` / `boot_loader`。

- [ ] 创建后状态经 `pending` → `available`
- [ ] 格式自动识别正确（qcow2 / raw）
- [ ] `available` 后能用于创建虚拟机

### URL 校验

```bash
for bad in "http://x/a b.img" "http://x/a$(printf '\n')b" "http://x/a -o /root/.ssh/authorized_keys"; do ... done
```

- [ ] `download_url` **禁止空白与控制字符**，非法返回 400
  > **回归点**：`http_url` 校验允许空格，曾可拼出 `curl ... -o /root/.ssh/authorized_keys`。见 `TC-13 SEC-02`。

## VOL-08 从虚拟机创建镜像（capture）

**P2** — 需要 S3 可用 · 界面上没有入口，只能调接口

```bash
ssh work-01 'source /root/st-env.sh >/dev/null
api_code PATCH /instances/<uuid> "{\"power_action\":\"hard_stop\"}"    # 必须先关机
api_code POST /images "{\"name\":\"wp-cap\",\"os_code\":\"linux\",\"download_url\":\"http://capture.invalid/x\",
 \"os_version\":\"0.6.2\",\"user\":\"cirros\",\"boot_loader\":\"bios\",\"os_family\":\"linux\",\"instance_uuid\":\"<uuid>\"}"'
```

`download_url` 是必填校验项，capture 时随便给个合法 URL；真正读的是节点上的系统盘。

- [ ] 系统盘在**非内置池**里时也能被找到（clapi 下发绝对路径 `<池根>/<volumes.path>`）
- [ ] 转换出的镜像回报了虚拟大小；节点 `$cache_tmp_dir` 里不留临时文件
- [ ] 🔴 **已知缺陷（既有，未修）**：`CLAPI_INTERNAL_URL` 为空时 clapi 默认拼成 `http://<clapi 主机名>:8255/api/v1`，而 8255 只提供 **HTTPS**，节点 `curl` 收到 400，镜像停在 `error`。work-01 上从来没有成功过的 capture。修的时候要一并决定节点怎么信任自签证书
- [ ] `.env` 里是 `CAPTURE_UPLOAD_SECRET=`，**不是** `SCI_SHARED_SECRET=`
  > ⚠️ 改名后没同步 `.env` 的话，启用 S3 时上传**全部 401**
- [ ] HA 部署下，`CAPTURE_UPLOAD_SECRET` 由 MASTER 生成、BACKUP 同步（上传凭证可能由一台 clapi 签发、另一台校验）

## 历史缺陷回归点汇总

| # | 现象 | 根因 |
|---|---|---|
| 1 | 实例详情看不到云硬盘容量 | `VolumeInfoResponse` 缺 `size`（2026-09-21 修） |
| 2 | 第二块本地数据卷盘符重复为 vdb | 按 WDS 的 `type='network'` 计数 |
| 3 | 迁移后 `volumes.hyper` 没更新 | `inst_status` 只修 instances 与 interfaces |
| 4 | 启用 S3 后 capture 上传 401 | `.env` 没同步改名 |
| 5 | 镜像 `download_url` 可注入 | `http_url` 校验允许空格 |
| 6 | 卷文件丢失后挂载出一块空盘 | 挂载不区分 `new` / `existing`（2026-09-22 修） |
| 7 | 只改名却把已挂载的卷卸载了 | `PATCH /volumes` 分不清「没传 instance」和「instance: null」 |
| 8 | 迁移把陈旧的磁盘描述文件带到目标 | 卸载成功后没删描述文件（2026-09-22 修） |
| 9 | capture 上传必然失败 | 默认上传地址用 `http://`，clapi 8255 是 HTTPS（**未修**） |

## 清理

```bash
ssh work-01 'source /root/alarmtest-env.sh
for v in $(api GET "/volumes?type=all" | jq -r ".volumes[]|select(.name|startswith(\"wp-\"))|.id"); do
  api PATCH /volumes/$v "{\"instance\":null}" >/dev/null; sleep 5; api DELETE /volumes/$v >/dev/null
done
sleep 10   # 删除是异步的（202），等节点回调
for m in $(api GET /images | jq -r ".images[]|select(.name|startswith(\"wp-\"))|.id"); do api DELETE /images/$m >/dev/null; done
api GET "/volumes?type=all" | jq -r ".volumes[].name"; api GET /images | jq -r ".images[].name"'
```

- [ ] 无 `wp-` 残留
- [ ] 保留镜像 `cirros-0.6.2`、`ubuntu-24.04-minimal` 完好
