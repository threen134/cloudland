## 设计约定（判定预期的依据）

- **分布式**：S(T) = 有任一成员 VPC 的云服务器网卡（`interfaces.type = 'instance'`）的节点，加上成员云服务器进行中迁移的目标节点。S(T) 里每台节点都有 `tgw-<ID>`，每个成员 VPC 的路由器各有一条 `tr-<挂载 ID>`（`169.254.254.(2×槽位+1)/31`），`tgw-<ID>` 里对应 `ta-<挂载 ID>`（`.(2×槽位)`）。
- **路由器侧**：表 252（`tgw`）+ `ip rule pref 100 lookup tgw`；表里是可达前缀（`via <ta> dev tr-<att>`）、`blackhole`（成员网段但关联表里没有的、静态黑洞）、`throw`（本 VPC 子网、`192.168.196.0/24` 与本 VPC VPN 网关的对端网段 / 客户端地址池）。可达前缀进 `nonat`，记在 `/opt/cloudland/cache/router/router-<N>/tgw.nonat`；归属记在同目录 `tgw.owner`（`<网关 ID> <挂载 ID>`）。FORWARD 最前面 9 条 DROP：`tr+` 与 `ti-+` / `te+` / `wg+` / `ipsec+` 双向，加 `-i tr+ -o tr+`。删 `nonat` 条目时跳过本 VPC 网段、VPN 网段和 `vpn-*/nonat.current` 里的。
- **网关侧**：`ip rule iif ta-<att> lookup <1000 + 路由表槽位>`，每张表末尾 `blackhole default`；`rp_filter` 全为 0（反向路径查找不带入接口，按 `iif` 选表的规则匹配不上）；`INPUT` 默认 DROP。
- **期望状态**：所有节点一份，带代次号（`transit_gateways.generation`），节点在 `/opt/cloudland/cache/tgw/<ID>/generation` 记收到过的最大代次（一拿到就记，清空后也保留），更小的丢弃；`state.json` 只在应用成功后写。节点离开 S(T) 也让代次 +1。超过 64 KiB 的状态以 `gz:` 前缀压缩下发。节点回报 `apply_tgw.sh '<ID>' '<代次>' 'ok|error' '<原因>' '<挂载数>'`，clapi 写 `tgw_node_states`。
- **节点状态**：`ok` / `error` / `pending`（落后于当前代次）/ `leaving`（已离开 S(T)、还没确认空状态）。没确认的节点由看护循环每 15 秒检查一次、按 1、2、4… 分钟（最长 10 分钟）退避重发，离线节点等它回来。
- **挂载状态**：所有在线的 S(T) 节点回报 `代次 ≥ 挂载那一代` 且 ok → `available`；任一节点 error → `error`；5 分钟没收齐 → `error`（原因列出没回报的节点）。解绑：`detaching`，收齐后软删除；失败时保持 `detaching` 带原因，再解绑一次重试。
- **挂载时交换转发条目**：每个 S(T) 节点收到所有成员云服务器网卡（在别的节点上的）的 fdb / neigh 条目（`add_fwrule.sh` 顺带建出路由器、网关口和 VXLAN 口）。之后新网卡落地时 `SendFdbRules` 按整个网关的范围扩散。
- **错误码**：133001 网关不存在 404、133002 重名 409、133003 还有挂载 409、133011 挂载不存在 404、133012 VPC 已挂过 409、133013 超过 10 个 409、133014 网段冲突 400、133015 挂载在解绑中 409、133021/133031/133041 路由表 / 路由 / 传播不存在 404、133022/133032/133042 已存在或超上限 409、133023 路由表在用（或是默认表）409、133051 删 VPC 时还挂着 409。
- **默认安全组**放行任意来源的 ICMP、22、3389，TCP/UDP 只放行本 VPC 子网：**挂上后 ping 和 22 端口能通，其他 TCP 不通**，安全组用例必须用 TCP 判定。

### ⭐ 最容易误判的几点

- **ping 通不代表安全组放行了**：默认安全组对 `0.0.0.0/0` 放行 ICMP。
- **挂载一直是 `attaching`**：先看 `GET /transit_gateways/<id>` 的 `nodes`（系统管理员能看到节点名），哪台是 `pending`；节点上 `cat /opt/cloudland/cache/tgw/<ID>/generation`，脚本没部署或没有可执行位时节点不会回报。
- **节点上多出别的 VPC 的路由器是正常的**：挂上中转网关后，S(T) 里每台节点都有所有成员 VPC 的路由器（即使该 VPC 在这台节点上没有云服务器）。
- **路由器里有 `pref 100` 的规则、表 252**：只在挂了中转网关的 VPC 路由器里有；解绑后应该消失。
- **单向路由**：A 的关联表有 B、B 的关联表没有 A 时，A→B 的包在 B 的路由器入口就被丢（反向路径检查），不是网关的问题。
