## ⭐ 跨服务身份传递（判定预期的依据）

clapi **不掌握用户身份**。`authorize.go` 只从 cpgateway 传来的请求头构造 `MemberShip`，**不查库**。

转发的头：`X-User-ID`、`X-User-Name`、`X-Org-ID`、**`X-Org-UUID`**、`X-Org-Name`、`X-Org-Role`、`X-System-Role`、`X-Is-Owner`、`X-Forwarded-Secret`。

**跨服务只用 UUID 对应，两侧的自增主键各自独立**：

- 组织：`POST /internal/orgs/sync` 传 `{uuid, name, slug}`，clapi 按 UUID upsert、**本地 ID 由自己分配**
- 用户：**完全不同步**，两边 `users` 表各自自增

### ⚠️ 最容易踩的坑

**cpgateway 所有直接调用 clapi 的地方都必须带 `X-Org-UUID`。** 只带 `X-Org-ID` 时 clapi 当作不属于任何组织、**列表全空**。

改造时曾漏了用量对账（`consumption_sync.go`），后果是：每次登录把组织用量**覆盖成 0** → 概览页资源使用率为 0 → **配额限制失效**。

```bash
ssh work-01 'cd /opt/cloudland/cpgateway && grep -rn "X-Org-UUID" src/ | wc -l
grep -rn "X-Org-ID" src/ | grep -v "X-Org-UUID" | head'
```

- [ ] 每处设置 `X-Org-ID` 的地方旁边都有 `X-Org-UUID`

## ORG-06 配额

**P1**

7 项：CPU 核数、内存 GB、磁盘 GB（系统盘 + 数据盘）、公网 IP、VPC、负载均衡、镜像。后 4 项是**按个数计的整数，0 表示禁止创建**。

- 配额行 `org_resource_quotas`，用量行 `org_resource_consumptions`
- 记账在网关 `services/quota.go`：`quotaRules` 按「方法 + 路由模板」**整条匹配**到 `{动作, 资源类型}`（**不从 URL 猜字段**）
- 创建前**预扣**（超额 429 `quota_exceeded`），后端成功才结算、失败回滚
- 删除 / 变更规格前先 GET 该资源算出要释放的量，删除成功才释放

```bash
ssh work-01 'source /root/alarmtest-env.sh
docker exec cloudland-postgres psql -U postgres -d cloudland_cpgateway -c "select * from org_resource_quotas;"
docker exec cloudland-postgres psql -U postgres -d cloudland_cpgateway -c "select * from org_resource_consumptions;"'
```

### 检查项

- [ ] 创建资源前用量 +N，创建失败后**回滚**
- [ ] 删除资源后用量 -N
- [ ] 超额返回 **429**，`error_code` = `quota_exceeded`
- [ ] 前端创建虚拟机 / VPC / 负载均衡 / 镜像 / 弹性 IP 遇到 429 时，统一走 `utils/quotaError.ts` 显示**本地化的超额原因**
- [ ] 概览页 7 条进度条；配额为 0 或已超额**标红**；拿不到配额数据才显示 `-`

### 跨组织不误释放

- [ ] 系统管理员删**别的组织**的资源时，**不释放调用方的配额**
  > clapi 各资源返回 `owner_uuid`（组织名不唯一，不能按名字判断）。与调用方 `X-Org-UUID` 不一致时不释放，留给该组织下次登录对账修正。

### 登录对账

对账结果会**覆盖**逐次记账的用量，所以必须取**全量**：

- 计数类资源只请求 `limit=1` 读 `total`
- 虚拟机、云硬盘需要**求和**，按 `offset` 翻页（clapi 列表默认每页 50 条）
- 云硬盘带 **`type=all`**（默认只列数据盘，而逐次记账的硬盘用量含系统盘）

- [ ] 登录一次后用量与实际资源吻合
- [ ] 资源数超过 50 时对账结果**不被截断**

> 已知遗留：对账与正在进行的创建之间**没有协调**，窗口内预扣可能被覆盖（需要单独设计）。

### 新增可计费资源的改动清单

新增一种要同时改：`quotaRules`、`QueryResourceAmount` / `PrepareQuota` 的资源分支、`QuotaResourceFields` 与 `integerQuotaFields`、两张表的模型、`schemas.go`、`DeleteRegion` 用量检查、`consumption_sync.go`、`DEFAULT_*` 系统设置（含 `settingRanges`）与 `conf/config.toml`，前端 `api/quota.ts` 的 `QUOTA_ROWS`、`useQuota.ts`、概览 `buildUsageBars`、系统设置 `numberRanges` 与三种语言文案。

- [ ] 若本次改动新增了计费资源，逐项核对上表

### 模型注意

- [ ] 字段名含连续大写要显式写列名（`VPCs` 会被 GORM 转成 `vp_cs`，已用 `column:vpcs`）
- [ ] 配额列的 `default:0` **不能去掉**（AutoMigrate 给有数据的表加 NOT NULL 列必须带默认值；默认值等于零值所以不会替换有意设置的 0）

## ORG-07 审计日志与组织动态

**P1**

同一张 `audit_logs` 表两个视图：

| 接口 | 可见性 | 字段 | 分页 |
|---|---|---|---|
| `GET /audit_logs` | **仅系统管理员** | 全量（路径、耗时、trace_id、失败响应体） | offset |
| `GET /activities` | **所有成员** | 精简，只含 `action` 非空的记录 | **游标**（`next_cursor`） |

`/activities` 的**组织范围只取自身份、不接受参数**；默认最近 7 天、跨度上限 90 天；另支持 `success=true|false`。

### 检查项

- [ ] 非系统管理员访问 `/audit_logs` → 403
- [ ] `/activities` 普通成员可见，只看得到自己组织的
- [ ] 改动型操作都进了动态（创建 / 删除 / 电源操作 / 改名 / 打开终端…）
- [ ] 资源名是**操作执行前**按 UUID 查表的快照（删除后资源会软删改名）
- [ ] 创建类接口的新资源 ID / 名称从**成功响应体**解析（截取上限 64KB；批量创建**只有一个元素时才取**）
- [ ] 失败记录用 `activityActionsFailed` 文案（成功文案「删除了…」接「失败」自相矛盾）
- [ ] 未翻译的动作显示**通用文案**，不是键名

### 动态页查询约定

- [ ] 预设范围也**显式传 `end`**
  > 只传 `start` 时服务端以自身当前时间作 end，「最近 90 天」会略超上限**被拒**。
- [ ] 「加载更多」沿用当次刷新时固定的查询条件
- [ ] 筛选变化即**作废在途请求**（generation 计数）
- [ ] **不做页码跳转** —— 新记录持续插入，页码翻页会重复或漏条目

### 保留策略

- [ ] `AUDIT_LOG_RETENTION_DAYS` 默认 365，范围 90–3650
- [ ] cpgateway 保存时校验；clapi 读镜像越界回退默认值（**两边的默认值与范围要同步改**）
- [ ] clapi 启动 30 秒后及每 24 小时物理删除过期记录，每批 5000 条、批间停 200ms

### 覆盖范围

- [ ] 只覆盖 **clapi** 的操作；登录、邀请、配额等 cpgateway 内的操作**不在其中**（这是已知范围，不是缺陷）
- [ ] 不加区域参数（每个区域的 clapi 只有本区域数据，cpgateway 按 token 区域转发）

### 待办

资源详情页的「操作记录」标签页（复用 `ActivityEntry` + `resource_uuid` 过滤）**未实现**。
