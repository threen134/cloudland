# TC-16 本地存储池（STO）

优先级 **P1** · 会建池 / 建卷 / 建虚拟机，建池类用例只能用 loop 设备 · 全量约 90 min（STO-12 的启动失败约 6 分钟）

2026-09-22 按 `docs/architecture/plan/local-multi-disk-storage-plan.md` 实施 L0a–L4 时的测试用例，已在 work-01/02/03 全量跑通。方案的 §14 记了实施中的偏差与当时没覆盖的项，§14.7 是 2026-09-23 第二轮审查修掉的 12 条。

## 设计约定

- **两层模型**：`storage_pools` 是区域级的池（内置池 `local` 固定存在，`builtin=true`）；`hyper_storage_pools` 是「某台机器上的这个池」；`hyper_disks` 是扫描出来的盘。
- **同一台机器上一个池只有一个目录**：内置池 `/opt/cloudland/cache`，其他池 `/opt/cloudland/pools/<池UUID>`。
- **路径由 clapi 下发**，`volumes.path` 是相对池根的相对路径：内置池数据盘 `volume/volume-N.disk`、内置池系统盘 `instance/inst-N.disk`、其他池一律 `volumes/volume-N.disk`；UEFI 的 NVRAM 跟着系统盘走（其他池在 `<池>/nvram/inst-N_VARS.fd`）。
- **准入按「机器 × 池」**：`容量 × 超分比例` 对已分配量（卷容量 + 未过期预留）；占用率 ≥ 90%、或池上有因空间不足暂停的虚拟机时一律拒绝（409，`122003`）。只有系统盘（`boot`）与迁移（`migration`）写预留（`storage_reservations`，24 小时过期）。
- **内置池的容量**：心跳与 clapi 都按 `(own + avail) × disk_over_ratio` 算（`own` = `instance/` + `volume/` 的实际占用，探测进程 `du` 出来写在 `builtin.state`；`avail` = `df` 空闲），**不是**文件系统大小。系统盘放内置池、不指定宿主机时由 **cland** 按磁盘维度选机器（需求 `disk=<字节>`，只算落在内置池的部分）；指定宿主机时走 `inter=`、cland 不检查，由 clapi 写 `boot` 预留。
- **删卷是异步的**：接口返回 **202**，卷进 `deleting`，节点回调 `clear_volume` 才删记录；节点回报失败时卷回到 `available`（`reason` 以 `delete failed:` 开头）；节点离线直接拒绝；30 分钟没回调转 `delete_failed`。
- **节点侧**：改池目录一律经 `pool_enter`（池锁 + `pool_guard` 挂载校验 + 路径用 `realpath -m` 规范化后必须在池根内）；回调里的空参数用 `-` 占位；探测进程每池一个，心跳只读结果；磁盘清单是**上一次扫描的快照**，建池 / 删池 / 加盘都不自动重扫。

## STO-01 磁盘扫描与安全拒绝

**P1** · 脚本：原 `/root/st-l1.sh` 已不在 work-01 上，按下面的命令手工做

```bash
ssh work-01 'source /root/st-env.sh >/dev/null; source /root/st-lib.sh
U=$(hyper_uuid work-03)
api_code POST /hypers/$U/disks/scan; sleep 12
api GET /hypers/$U/disks | jq -c ".disks[]|{id,disk_id,name,size_bytes,media,state,pool_name,owner_hostid,scanned_at}"'
```

建池请求体（`POST /hypers/$U/storage_pools`）：`{"storage_pool":{"id":"<池>"},"layout":"single|linear|raid1","disks":["<disk_id>"],"wipe":false,"allow_media_mismatch":false,"confirm":"work-03"}`。

### 检查项

- [ ] 扫描返回 **202**，约 10 秒后清单刷新（`scanned_at` 更新）
- [ ] 系统盘识别为 `system`；本机池里的盘是 `in_use` 并带 `pool_name`；其余按 `free` / `dirty` / `cloudland_pool`（别的 hostid 留下的 CloudLand 池，可接管）/ `unknown_member` / `shared` 分类（2026-09-28 核对：原用例漏了 `in_use`；返回字段是 `size_bytes` / `pool_name`，不是 `size` / `pool`）
- [ ] 已属于某个池的盘带池名（8 位前缀也要能对上池）
  > **回归点**：磁盘列表曾只显示池 UUID 前缀、查不到池名（`PoolByRef` 修）
- [ ] 用系统盘建池 → 400，`error_code` 122005（`Disk X can not be used: system (...)`）
- [ ] 用 `dirty` 盘且不带 `wipe` → 400 `Disk X has data on it; choose to wipe it`（loop 盘上先 `mkfs.ext4` 一下就是 dirty）
- [ ] 机器名确认串不符 → 400 `StorageConfirmMismatch`（`error_code` 122008）
- [ ] 盘数与布局不符（如 `single` 给两块、`raid1` 给奇数块）→ 400 `Layout single can not be built from 2 disks`
- [ ] 介质与池不一致且不带 `allow_media_mismatch` → 400 `StorageMediaMismatch`（122006）；带了则成功
- [ ] 扫描结果超过 24 小时的盘 → 400 `The scan result of disk X is too old; scan the disks again`；不在扫描结果里的盘 → 400 `... scan the disks first`
- [ ] 对内置池 `local` 建池 → 400；同一台机器上已有这个池 → 400（122007）；这台机器上另一个建池 / 加盘 / 删池还在进行 → 400 `Another storage operation is running on this host`
- [ ] ⚠️ **与方案不一致（待确认）**：方案 §8.4 要求审计记「是否放行了介质不一致、盘的标识、是否清除」，但审计中间件成功时只记动作（`hyper.storage_pool_create`）和状态码，**不记请求体**（2026-09-28 核对 `apis/audit.go`）。原用例写的「审计里注明放行」现在做不到，只核对有这条动作记录

## STO-02 建池与删池（单盘）

**P1** · 用 loop 盘（没有空闲物理盘）· 参考脚本 `/root/st-rmtmp.sh`（1 GB loop 池 `wp-tmp`，自带清理）

```bash
ssh work-01 'source /root/st-env.sh >/dev/null; source /root/st-lib.sh
U=$(hyper_uuid work-03)
cat > /tmp/wp-pool.json <<JEOF
{"name":"wp-pool","media":"hdd"}
JEOF
R=$(api POST /storage_pools @/tmp/wp-pool.json | jq -r .id)
cat > /tmp/wp-hp.json <<JEOF
{"storage_pool":{"id":"$R"},"layout":"single","disks":["loop:/var/lib/cl-looptest/wp1.img"],"wipe":true,"confirm":"work-03"}
JEOF
api_code POST /hypers/$U/storage_pools @/tmp/wp-hp.json
wait_pool $R 3 ready; pool_row $R 3'
```

### 检查项

- [ ] 建池返回 **202**（`{"raid1_pairs": null}`），节点状态 `creating` → `ready`，容量按盘的实际大小上报
- [ ] 节点上 `/opt/cloudland/pools/<uuid>` 已挂载，`volumes/`、`nvram/`、`tmp/` 三个目录都在
- [ ] `/etc/fstab` 里有该池一行且带 **`nofail`**（缺了会导致盘坏时开不了机）
- [ ] 池根有标记文件 `.cloudland-pool`（`driver=local`、`pool_uuid=`、`hostid=`），VG 带 `cloudland_pool=` / `cloudland_host=` 标签
- [ ] 新建 XFS 池 `df` 已用约占 2%（1.8 TB 盘约 36 GB，reflink/rmapbt 元数据预留），**不是 0**，属正常
- [ ] 池里还有**卷记录**时删池被拒：409，`error_code` 122004（`Storage pool X on H still holds N volumes`），**带 `force=true` 也一样**；有未过期预留时同样 409
- [ ] 池里没有卷记录、只剩文件（比如 `tmp/.incoming-<迁移ID>` 占位）时普通删除被节点拒绝，**池保持 `ready`**、原因为 `remove refused: pool is not empty: <文件清单>`，仍然挂载可用；带 `&force=true` 删掉残留文件后成功
  > **回归点**：被拒后池曾一律置为 `error`，而周期上报从不改写 `error` 的行，一个完好的池就永久不可用了（2026-09-23 修）。脚本 `/root/st-rmtmp.sh`
- [ ] ⚠️ **与方案不一致（待确认）**：方案 §8.4 要求「删掉的残留文件清单」进审计，实际只在节点回调里（cloudlet / cland 日志），审计只有 `hyper.storage_pool_delete` 与状态码
- [ ] 确认参数走**查询串**：`DELETE /hypers/<uuid>/storage_pools/<池>?confirm=work-03[&force=true]`（网关转发 DELETE 时丢请求体）；确认串不符 400
- [ ] 删池后 fstab 行、挂载、VG、`mdadm.conf` 条目全部清零，`hyper_storage_pools` 的这一行被删
- [ ] 各节点都删掉后才能 `DELETE /storage_pools/<池>`（否则 409 `is still set up on N hosts`）；内置池删不掉（400）

## STO-03 池上的数据卷

**P1** · 脚本 `bash /root/st-volume.sh`（先把 `st-vm1` 换成 `wp-st1`、`net-a` 换成另一台机器上的 `wp-` 虚拟机）

覆盖：建卷 → 首次挂载 → 写入 → 在线扩容 → 卸载重挂 → 跨节点拒绝 → 删除。

### 检查项

- [ ] 建卷时选池（`"storage_pool":{"id":"$P"}`），创建后直接 `available`、`hyper=0`（未落盘），`path=volumes/volume-N.disk`；池被停用（`status=disabled`）时建卷 400（`122002`）
- [ ] 首次挂载在虚拟机所在节点按 `new` 建文件，落在 `<池>/volumes/volume-N.disk`，**根分区上没有**
- [ ] 建出来的 qcow2 是 **2 MiB 簇**（`qemu-img info` 的 `cluster_size`）
- [ ] 虚拟机内能读写，数据在卸载重挂后完好
- [ ] 在线扩容：虚拟机不重启，guest 内 `lsblk` 立即看到新容量
- [ ] 卸载后再挂载走 `existing`，**不会新建空盘**
  > **回归点**：文件丢失时曾静默新建一块空盘。人为 `mv` 走文件再挂载，必须失败：卷回到 `available`，`reason` 为 `volume file ... not found`，而不是给一块空盘
- [ ] **已落盘**的卷挂给**另一台机器**上的虚拟机 → 400，`error_code` 121007，`Local volume X is on A, it can not be attached to an instance on B`（2026-09-28 核对：原用例写的「提示该机器没有这个池」是另一种情况）
- [ ] **未落盘**的卷挂给没有这个池（或池不可用）的机器上的虚拟机 → 400，`error_code` 122002，`<host> has no storage pool <池>` / `Storage pool X on H is not usable (...)`。三台都有 `local-hdd`，这条用只建在一台上的 loop 池（如 STO-02 的 `wp-pool`）做
- [ ] 删除返回 **202**，卷经 `deleting` 后记录消失，节点上文件被删
- [ ] 从未落盘的卷删除返回 204、立即消失（不经节点）
- [ ] 节点回报删除失败（文件 `chattr +i`）→ 卷回到 **`available`**，`reason` 以 `delete failed:` 开头；只有 30 分钟没有回调才是 `delete_failed`（不能挂载，只能再删），模拟方法见 TC-08 VOL-04（2026-09-28 核对 `HandleClearVolume`：原用例写的「回报失败 → `delete_failed`」不对）
- [ ] 卸载成功后节点上的磁盘描述文件被删除
  > **回归点**：陈旧的描述文件曾被迁移带到目标机器

## STO-06 池快满与写满

**P2** · 需要 loop 小池 · 脚本 `/root/st-full.sh`（work-01 上 3 GB `t1` + 4 GB `t2`；先替换虚拟机名）

在 3 GB 的 loop 池上建 8 GB 卷（靠超分比例放行），在虚拟机里 `dd` 写满。

### 检查项

- [ ] 占用跨过 80% / 85% / 90% 时立即上报（不等 5 分钟周期）
- [ ] 写满时虚拟机被**暂停**而不是把错误抛给 guest，界面显示「存储空间不足」（原因 `storage_full`）
  ```bash
  ssh work-0X 'virsh domstate --reason inst-N; virsh domblkerror inst-N'   # expect vdX: no space
  ```
