# TC-16 本地存储池（STO）

优先级 **P1** · 会建池 / 建卷 / 建虚拟机，部分用例用 loop 设备 · 约 60 min

2026-09-22 按 `docs/architecture/plan/local-multi-disk-storage-plan.md` 实施 L0a–L4 时的测试用例，已在 work-01/02/03 全量跑通。方案的 §14 记了实施中的偏差与当时没覆盖的项。

## 设计约定

- **两层模型**：`storage_pools` 是区域级的池（内置池 `local` 固定存在，`builtin=true`）；`hyper_storage_pools` 是「某台机器上的这个池」；`hyper_disks` 是扫描出来的盘。
- **同一台机器上一个池只有一个目录**：内置池 `/opt/cloudland/cache`，其他池 `/opt/cloudland/pools/<池UUID>`。
- **路径由 clapi 下发**，`volumes.path` 是相对池根的相对路径：内置池数据盘 `volume/volume-N.disk`、内置池系统盘 `instance/inst-N.disk`、其他池一律 `volumes/volume-N.disk`；UEFI 的 NVRAM 跟着系统盘走（其他池在 `<池>/nvram/inst-N_VARS.fd`）。
- **准入按「机器 × 池」**：`容量 × 超分比例` 对已分配量；占用率 ≥ 90%、或池上有因空间不足暂停的虚拟机时一律拒绝。只有系统盘与迁移用预留（`storage_reservations`）。
- **删卷是异步的**：接口返回 **202**，卷进 `deleting`，节点回调 `clear_volume` 才删记录；节点离线直接拒绝；30 分钟没回调转 `delete_failed`。

## 测试环境

三台机器的空闲盘 `sdb` 已建成池 **`local-hdd`（单盘）**，保留作测试环境（见 `00-环境与前置.md` 第 4 节）。

API 与断言助手在 work-01：`/root/st-env.sh`（`api` / `api_code` / `psql_c` / `hyper_uuid`，401 自动重登）、`/root/st-lib.sh`（`on <hostid>` 远程执行、`q` 查库、`vol_row` / `pool_row` / `wait_vol` / `wait_inst` / `wait_mig` / `reservations`，`$P` = `local-hdd` 的 uuid）。各用例的脚本是 `/root/st-*.sh`。

## STO-01 磁盘扫描与安全拒绝

**P1** · 脚本 `/root/st-l1.sh`

```bash
ssh work-01 'source /root/st-env.sh; source /root/st-lib.sh
U=$(hyper_uuid work-03)
api_code POST /hypers/$U/disks/scan; sleep 12
api GET /hypers/$U/disks | jq -c ".disks[]|{disk_id,size,media,state,pool}"'
```

### 检查项

- [ ] 系统盘识别为 `system`，数据盘按 `free` / `dirty` / `cloudland_pool` / `unknown_member` / `shared` 分类
- [ ] 已属于某个池的盘带池名（8 位前缀也要能对上池）
  > **回归点**：磁盘列表曾只显示池 UUID 前缀、查不到池名（`PoolByRef` 修）
- [ ] 用系统盘建池 → 400
- [ ] 用 `dirty` 盘且不带 `wipe` → 400 `Disk X has data on it; choose to wipe it`
- [ ] 机器名确认串不符 → 400 `StorageConfirmMismatch`
- [ ] 盘数与布局不符（如 `single` 给两块）→ 400
- [ ] 介质与池不一致且不带 `allow_media_mismatch` → 400 `StorageMediaMismatch`；带了则成功且审计里注明放行

## STO-02 建池与删池（单盘）

**P1**

```bash
ssh work-01 'source /root/st-env.sh; source /root/st-lib.sh
U=$(hyper_uuid work-03)
R=$(api POST /storage_pools "{\"name\":\"wp-pool\",\"media\":\"hdd\"}" | jq -r .id)
api_code POST /hypers/$U/storage_pools "{\"storage_pool\":{\"id\":\"$R\"},\"layout\":\"single\",\"disks\":[\"<disk_id>\"],\"wipe\":true,\"confirm\":\"work-03\"}"
wait_pool $R 3 ready; pool_row $R 3'
```

### 检查项

- [ ] 节点状态 `creating` → `ready`，容量按盘的实际大小上报
- [ ] 节点上 `/opt/cloudland/pools/<uuid>` 已挂载，`volumes/`、`nvram/`、`tmp/` 三个目录都在
- [ ] `/etc/fstab` 里有该池一行且带 **`nofail`**（缺了会导致盘坏时开不了机）
- [ ] 池根有标记文件 `.cloudland-pool`（含 pool uuid 与 hostid），VG 带 `cloudland_pool=` / `cloudland_host=` 标签
- [ ] 新建 XFS 池 `df` 已用约占 2%（1.8 TB 盘约 36 GB，reflink/rmapbt 元数据预留），**不是 0**，属正常
- [ ] 删池：池里有卷时被拒并列出文件；`force` 后成功，文件清单进审计
- [ ] 池里只剩文件（没有卷记录，比如 `tmp/.incoming-<迁移ID>` 占位）时普通删除被拒，**池保持 `ready`**、原因为 `remove refused: pool is not empty: ...`，仍然挂载可用
  > **回归点**：被拒后池曾一律置为 `error`，而周期上报从不改写 `error` 的行，一个完好的池就永久不可用了（2026-09-23 修）。脚本 `/root/st-rmtmp.sh`
- [ ] 删池后 fstab 行、挂载、VG、`mdadm.conf` 条目全部清零

## STO-03 池上的数据卷

**P1** · 脚本 `/root/st-volume.sh`

覆盖：建卷 → 首次挂载 → 写入 → 在线扩容 → 卸载重挂 → 跨节点拒绝 → 删除。

### 检查项

- [ ] 建卷时选池，创建后直接 `available`、`hyper=0`（未落盘）
- [ ] 首次挂载在虚拟机所在节点按 `new` 建文件，落在 `<池>/volumes/volume-N.disk`，**根分区上没有**
- [ ] 建出来的 qcow2 是 **2 MiB 簇**（`qemu-img info` 的 `cluster_size`）
- [ ] 虚拟机内能读写，数据在卸载重挂后完好
- [ ] 在线扩容：虚拟机不重启，guest 内 `lsblk` 立即看到新容量
- [ ] 卸载后再挂载走 `existing`，**不会新建空盘**
  > **回归点**：文件丢失时曾静默新建一块空盘。人为 `mv` 走文件再挂载，必须报错而不是给一块空盘
- [ ] 挂给**另一台机器**上的虚拟机 → 拒绝，提示该机器没有这个池
- [ ] 删除返回 **202**，卷经 `deleting` 后记录消失，节点上文件被删
- [ ] 从未落盘的卷删除后立即消失（不经节点）
- [ ] 节点回报删除失败 → 卷变 `delete_failed`，不能挂载，再次删除成功
- [ ] 卸载成功后节点上的磁盘描述文件被删除
  > **回归点**：陈旧的描述文件曾被迁移带到目标机器

## 历史缺陷回归点汇总

| # | 现象 | 根因 |
|---|---|---|
| 1 | 关机换池迁移后虚拟机起不来 | libvirt 12 的 `--offline` 忽略 `--persistent-xml`，目标定义了源端旧路径 |
| 2 | 删池后 `mdadm.conf` 留下陈旧条目、接管找不到阵列 | `mdadm --*-scan` 输出不带 `name=`，按名字匹配失效；改按阵列 UUID |
| 3 | 删池的 `confirm` 不生效 | cpgateway 转发 DELETE 时**丢弃请求体**，改为查询参数 |
| 4 | 加盘后池一直显示 `single` | 布局没有在节点重算并回写 |
| 5 | 盘修好后池无法恢复 | `lost` 的池不允许退出维护 |
| 6 | 迁移把陈旧的磁盘描述文件带到目标 | 卸载成功后没有删除描述文件 |
| 7 | 磁盘列表不显示所属池名 | 只拿到 8 位前缀，没按前缀反查池 |
