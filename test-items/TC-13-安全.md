## SEC-01 SQL 注入

**P0**

### 背景

原先**十几个列表接口**把请求参数格式化进 SQL：`name like '%%%s%%'`、安全组直接把 `query` 当 WHERE。构造 `%') OR 1=1 OR ('` 可以**跳出 GORM 加的括号、绕过组织过滤**。而且 `CLError` 把数据库原始报错返回给前端，可以逐字读出任意表。

### 约定

- 名称搜索用 `dbs.Contains(value, 列...)`（转义 `%` / `_` / `\`）
- 其他过滤写成 `Where("col = ?", v)` 或 `Scopes`
- 服务层 List 接收**结构化参数**（如 `SubnetAdmin.List(name, groupID, ipGroupType)`、`DictionaryFilter`），不是 SQL 片段
- `dbs.NewOrders` 只接受标识符形式的排序列
- `ErrorResponse` 遇到 `*pgconn.PgError` **只返回业务消息**，原始报错只进日志

```bash
  -v /root/go-mod:/go/pkg/mod -v /root/go-cache:/root/.cache/go-build -w /src \
  golang:1.26-bookworm go test ./src/dbs -run TestSQLLiteral -v 2>&1 | tail -10'
```

## SEC-02 Shell 注入

**P0**

### 背景

下发到计算节点的命令在节点上以 **root** 经 `bash -c` 执行。原先 `fmt.Sprintf("x.sh '%s'", v)` 直接放入用户输入（设置虚拟机密码的用户名 / 密码、LB 后端地址等），**带单引号即可执行任意命令**；`<<EOF` 未加引号时内容里的 `$(...)` 同样会执行。

### 约定

- 单引号内的 `%s` / `%v` 参数**一律包 `ShellEscape(...)`**（`common/shell.go`，只需转义单引号）
- heredoc **一律 `<<'EOF'`**

### 静态守门

```bash
ssh work-01 'cd /opt/cloudland/api && docker run --rm -v /opt/cloudland/api:/src \
  -v /root/go-mod:/go/pkg/mod -v /root/go-cache:/root/.cache/go-build -w /src \
  golang:1.26-bookworm go test ./src/common -run TestShell -v 2>&1 | tail -10'
```

- [ ] `common/shell_test.go` 通过（AST 检查所有含 `.sh` / `<<` 的 `Sprintf` 模板，漏包 `ShellEscape` 即失败）

### 动态验证

脚本 `/root/sectest-node.sh`：建虚拟机 → 带注入载荷改密码并在 guest 内校验 shadow → 浮动 IP → 热迁移 → 删除。

```bash
ssh work-01 'bash /root/sectest-node.sh 2>&1 | tail -30'
```

- [ ] 含 `'` 和 `$(id)` 的密码**原样设入虚拟机**（guest 内 `shadow` 比对一致）
- [ ] **三个节点上均无注入痕迹**（不存在被执行留下的文件 / 进程）

### 接口层校验（`apis/input_validation.go`）

```bash

I=<实例 id>
echo "--- 用户名非法字符"

  -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d "{\"user_name\":\"a;b\",\"password\":\"Abc12345\"}"'
```

- [ ] 设置密码的**用户名**限 `[A-Za-z0-9._-]`，非法 → 400
- [ ] 设置密码的**密码**限可打印 ASCII，非法 → 400
- [ ] LB **后端地址**必须 `IPv4:端口`，否则 400（原先原样写进 haproxy 配置，可**注入配置行**）
- [ ] 镜像 **`download_url`** 禁止空白与控制字符 → 400
  > `http_url` 校验允许空格，曾可拼出 `curl ... -o /root/.ssh/authorized_keys`

### 脚本侧

- [ ] `async_exec` 与各 `async_exec ./async_job/... "$@"` 保留参数边界（原 `$*` 会按空格拆分）
- [ ] `create_image.sh` 的 `"$url"` 加了引号
- [ ] `set_user_passwd.sh` 的变量加了引号

### 遗留（已知未修）

- 脚本把参数回显进 `|:-COMMAND-:|` 回调行时**未转义**，含单引号的值会打乱 clapi 的回调参数解析（**不能执行命令**，只是解析错乱）
- 未加引号的 `%s` 只剩配置项（`volume.driver`、脚本路径），不是用户输入

## SEC-06 集群共用 SSH 密钥（已知风险，未修）

**P2** — 只做记录，不做回归

控制节点生成的 `cland.key`，其**私钥**经 cland `NodeAdd` 下发到每个计算节点：

- `/root/.ssh/id_rsa`
- `/home/cland/.ssh/cland.key`
- `/opt/cloudland/deploy/.ssh/cland.key`

所有节点 root 与 cland 的 `authorized_keys` 都信任其公钥。

**后果**：

- 任一计算节点被攻破即可 **root 登录全部节点**（含控制节点）
- 持有 `GRPC_AUTH_TOKEN`（**明文**在每个节点 `/etc/sysconfig/cloudlet`）并知道任一已注册 hostid，即可调用 `NodeAdd` **取走私钥**

**上线前需改为每节点独立密钥或 SSH 证书（CA）。**

- [ ] 该风险仍在待办列表里（没有被误认为已解决）
