## SEC-01 SQL 注入

**P0**

### 背景

原先**十几个列表接口**把请求参数格式化进 SQL：`name like '%%%s%%'`、安全组直接把 `query` 当 WHERE。构造 `%') OR 1=1 OR ('` 可以**跳出 GORM 加的括号、绕过组织过滤**。而且 `CLError` 把数据库原始报错返回给前端，可以逐字读出任意表。

### 约定

- 名称搜索用 `dbs.Contains(value, 列...)`（转义 `%` / `_` / `\`）
- 其他过滤写成 `Where("col = ?", v)` 或 `Scopes`
- 服务层 List 接收**结构化参数**（如 `SubnetAdmin.List(name, groupID, ipGroupType)`、`DictionaryFilter`），不是 SQL 片段
- `dbs.NewOrders` 只接受标识符形式的排序列
- `ErrorResponse` 遇到 `*pgconn.PgError` **只返回业务消息**，原始报错只进日志

### 静态守门

```bash
  -v /root/go-mod:/go/pkg/mod -v /root/go-cache:/root/.cache/go-build -w /src \
  golang:1.26-bookworm go test ./src/dbs -run TestSQLLiteral -v 2>&1 | tail -10'
```

- [ ] `dbs/sql_literal_test.go` 通过（扫描 apis/services/rpcs/common 的字符串字面量，出现 `col = '%s'`、`like '%%%s%%'` 即失败）

## SEC-02 Shell 注入

**P0**

### 背景

下发到计算节点的命令在节点上以 **root** 经 `bash -c` 执行。原先 `fmt.Sprintf("x.sh '%s'", v)` 直接放入用户输入（设置虚拟机密码的用户名 / 密码、LB 后端地址等），**带单引号即可执行任意命令**；`<<EOF` 未加引号时内容里的 `$(...)` 同样会执行。

### 约定

- 单引号内的 `%s` / `%v` 参数**一律包 `ShellEscape(...)`**（`common/shell.go`，只需转义单引号）
- heredoc **一律 `<<'EOF'`**

### 静态守门

```bash

  -v /root/go-mod:/go/pkg/mod -v /root/go-cache:/root/.cache/go-build -w /src \
  golang:1.26-bookworm go test ./src/common -run TestShell -v 2>&1 | tail -10'
```

- [ ] `common/shell_test.go` 通过（AST 检查所有含 `.sh` / `<<` 的 `Sprintf` 模板，漏包 `ShellEscape` 即失败）

### 动态验证

```bash

```

- [ ] 含 `'` 和 `$(id)` 的密码**原样设入虚拟机**（guest 内 `shadow` 比对一致）
- [ ] **三个节点上均无注入痕迹**（不存在被执行留下的文件 / 进程）

### 🔴 历史缺陷：alarm-rules-manager 无鉴权暴露公网（2026-09-21 发现并修复）

`docker-compose.yml` 里 alarm-rules-mgr 写的是 `- "8256:8256"`（绑 `0.0.0.0`），而 clapi 写的是 `- "${INTERNAL_IP:-127.0.0.1}:8255:8255"`。

**后果**：从公网**无需任何凭据**即可调用它的 `/api/v1/rules/{file,symlink,chown,reload,delete}` —— 读取、写入、建软链、改属主、删除 Prometheus 主机上的任意文件。实测公网 `POST /api/v1/rules/file {"operation":"read","file_path":"/etc/hostname"}` 直接返回了文件内容。

修法：改成 `- "${INTERNAL_IP:-127.0.0.1}:8256:8256"`。clapi 是通过 compose 网络用容器名 `alarm-rules-mgr` 访问它的，**根本不需要发布宿主机端口**；保留内网绑定只为 CLAUDE.md 里记录的内网 Swagger UI。

- [ ] `docker port cloudland-alarm-rules-mgr` 输出的是 `8256/tcp -> <内网IP>:8256`，**不是** `0.0.0.0:8256`
- [ ] 从外网机器连 8256 不可达
- [ ] 内网 `https://<INTERNAL_IP>:8256/swagger/api/v1/index.html` 仍 200
- [ ] 建 / 删一条 VM 告警规则，规则文件能正常下发与清除（验证 clapi→alarm-rules-mgr 链路没断）

### 🔴 历史缺陷：监控栈多个端口暴露公网（2026-09-21 一并修复）

同一轮扫描还查出 `prometheus 9090`、`alertmanager 9093`、`grafana 3000`、`nginx 4000` 都绑在 `0.0.0.0`：

| 端口 | 暴露了什么 |
|---|---|
| 9090 Prometheus | **无鉴权**。匿名 `GET /api/v1/query?query=up` 返回全部指标 = 主机 / 虚拟机 / UUID / 资源用量的完整清单 |
| 9093 Alertmanager | **无鉴权**。`GET /api/v2/status` 返回接收器配置；`GET /api/v2/silences` 返回 200，意味着能**静默所有告警** |
| 4000 nginx | `/opt/cloudland/cache/image` 的目录服务，公开提供 qcow2 镜像下载 |
| 3000 Grafana | 有登录（不是默认 admin/admin），但没必要对外 |

全部改为绑 `${INTERNAL_IP}`。

- [ ] `grep -nE '^\s+- "[0-9]+:[0-9]+"' deploy/docker/docker-compose.yml` **只剩 80 和 443**
- [ ] 内网 `9090/-/healthy`、`9093/-/healthy`、`3000/login` 都 200
- [ ] Prometheus 采集目标全 up、无 `loading groups failed`
- [ ] Grafana 改后经内网或 SSH 隧道访问：`ssh -L 3000:<INTERNAL_IP>:3000 work-01`

**新增服务时一律检查 `ports:` 有没有绑到 `${INTERNAL_IP}`。**

> ⚠️ 改 compose 的端口行**不要用 `perl -0pi -e` 做替换**：替换串里的 `127` 会被当成八进制转义（`\127` = `W`），写出 `"W.0.0.1:9090:9090"` 这种，`docker compose up` 报 `invalid IP address: W.0.0.1`。用编辑器逐行改，改完先 `docker compose config` 验证语法。

## SEC-06 集群共用 SSH 密钥（已知风险，未修）

**P2** — 只做记录，不做回归

控制节点生成的 `cland.key`，其**私钥**经 cland `NodeAdd` 下发到每个计算节点：

- `/root/.ssh/id_rsa`
- `/home/cland/.ssh/cland.key`
- `/opt/cloudland/deploy/.ssh/cland.key`

所有节点 root 与 cland 的 `authorized_keys` 都信任其公钥。

**后果**：

- 任一计算节点被攻破即可 **root 登录全部节点**（含控制节点）
- 持有 `GRPC_AUTH_TOKEN`（**明文**在每个节点 `/etc/sysconfig/cloudlet`）并知道任一已注册 hostid，即可调用 `NodeAdd` **取走私钥**

**上线前需改为每节点独立密钥或 SSH 证书（CA）。**

- [ ] 该风险仍在待办列表里（没有被误认为已解决）
