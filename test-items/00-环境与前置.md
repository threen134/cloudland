## 2. API 调用环境

work-01 上已有 `/root/alarmtest-env.sh`，`source` 之后得到 `$B`（base URL）、`$T`（token）和 `api` 函数：

```bash
ssh work-01
source /root/alarmtest-env.sh
api GET /instances | jq -r '.instances[].hostname'
api POST /vpcs '{"name":"wp-vpc"}'
```

脚本内容（region uuid 是 work-01 的 `default` 区域，换环境要改）：

```bash
cd /opt/cloudland/deploy/docker
PW=$(grep "^ADMIN_PASSWORD=" .env | cut -d= -f2-); B=https://127.0.0.1/api/v1
T=$(curl -sk -X POST $B/auth/token -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"$PW\"}" | jq -r .access_token)
T=$(curl -sk -X POST $B/auth/switch-region -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d "{\"region\":\"49fce7f0-0ae3-49e1-8ffb-02c816b26bb1\"}" | jq -r .access_token)
api(){ curl -sk -X "$1" "$B$2" -H "Authorization: Bearer $T" -H 'Content-Type: application/json' ${3:+-d "$3"}; }
```

**token 有效期 120 分钟**，跑长用例中途重新 `source` 一次。

存储用例（`TC-16`）另有一套助手：`/root/st-env.sh`（同样给 `$B` / `$T` / `api`，另有 `api_code` 带状态码、`psql_c` 查库、`hyper_uuid`，**401 会自动重登**——别的会话登录会吊销 token）与 `/root/st-lib.sh`（`on <hostid>` 到节点执行、`q` 查库、`vol_row` / `pool_row` / `wait_vol` / `wait_inst` / `wait_mig` / `reservations`，`$P` 是 `local-hdd` 的 uuid）。

### 引号陷阱

经 `ssh work-01 '...'` 传一层引号时，`api POST` 的 JSON 里嵌套引号极易炸。**请求体一律写成文件再 `-d @file`**：

```bash
cat > /tmp/body.json <<'JEOF'
{"hostname":"wp-vm","image":{"id":"..."},"flavor":"vmtest-small"}
JEOF
curl -sk -X POST "$B/instances" -H "Authorization: Bearer $T" -H 'Content-Type: application/json' -d @/tmp/body.json
```

另：本地 Git Bash 的 heredoc 会把 `\\` 吞成一个反斜杠，需要字面反斜杠时用 `printf '\x5c'` 或用编辑器直接写文件。

## 3. 浏览器（UI）测试环境

Playwright 跑在容器里，脚本放 work-01 的 `/root/console-test/`：

```bash
ssh work-01
cd /opt/cloudland/deploy/docker && PW=$(grep "^ADMIN_PASSWORD=" .env | cut -d= -f2-)
docker run --rm --network host \
  -v /root/console-test:/work -w /work \
  -e ADMIN_PASSWORD="$PW" \
  mcr.microsoft.com/playwright:v1.55.0-noble node <脚本>.js
```

从本地上传脚本时**必须转 LF**（本地检出是 CRLF）：

```bash
sed 's/\r$//' local.js > local.lf.js && scp -q local.lf.js work-01:/root/console-test/x.js
```

### ⚠️ 对线上环境做 UI 测试必须兜底拦截写请求

曾经出过事故：拦截规则写成 `**/api/v1/system/settings`，没匹配到带 `?region=` 的请求，测试脚本真的把 `DNS_UPSTREAM` 改成了 9.9.9.9、默认 CPU 配额从 4 改成 8。

**只读类脚本一律在 context 上加这段兜底**（按 pathname 匹配，放行 auth 与遥测）：

```js
await page.route('**/*', (r) => {
    const req = r.request()
    const p = new URL(req.url()).pathname
    if (req.method() !== 'GET' && p.startsWith('/api/') &&
        !p.startsWith('/api/v1/auth/') && !p.startsWith('/api/v1/telemetry') && !p.includes('/metrics/')) {
        return r.abort()
    }
    return r.continue()
})
```

写入类用例（本套件里明确标注「建资源」的）才允许放开，且只对本用例要写的路径放开。

## 5. 测试资源命名与清理

- **所有**测试产物统一用 `wp-` 前缀（`wp-vm`、`wp-vpc-12345`、`wp-lb-...`）。这样收尾检查可以一把捞干净，也不会误伤 `rb-` / `mig-` / `pgtest-` 保留资源。
- 建议带时间戳后缀避免同名冲突：`wp-vpc-$(date +%s | tail -c 6)`。
- 用例里的「清理」小节是用例的一部分，不做完不算通过。
