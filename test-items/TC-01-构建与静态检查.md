
### ⚠️ 必须用 `vue-tsc`，不能用 `tsc`

`tsc` **根本不解析 `.vue` 文件**（SFC 被 `vite-env.d.ts` 的 `declare module '*.vue'` 兜成 `DefineComponent`）。`package.json` 的 `build` 脚本曾经是 `tsc -b && vite build`，导致模板和 `<script setup>` 里的类型错误从项目开始就一次都没被检查过，积累到 94 条才被发现（2026-09-21）。

**回归点**：任何人改了 `web/package.json` 的 `build` / `typecheck` 脚本，先确认它用的是 `vue-tsc`：

```bash
grep -E '"(build|typecheck)"' web/package.json
# expect: "build": "vue-tsc -b && vite build"   "typecheck": "vue-tsc -b --force"
```

- [ ] `build` 与 `typecheck` 都用 `vue-tsc`

| 现象 | 根因 | 判定 |
|---|---|---|
| 创建虚拟机页面直接显示 `marketplace.cancel` 这种键名 | 误判为「无用残留」把文案键删了 | **vue-i18n 找不到键时把键名当文案显示，既不报错也不抛异常**。所以 `t('a') \|\| t('b')` 这种回退写法永远不会生效（`t('a')` 返回的键名是真值）。删任何文案键前先 grep 引用点 + 跑本检查 |

## 失败时怎么办

| 现象 | 大概率原因 |
|---|---|
| 类型检查报一堆你没碰过的文件 | `web/node_modules` 是旧的，重新 `npm ci` |
| `Cannot find package 'typescript'` / `vue-tsc: command not found` | 没装依赖（`npm ci`），或终端的 PATH 里没有 Node |
| `go-sqlite3 requires cgo to work. This is a stub` | 本机 `CGO_ENABLED=0`，这些测试去 BUILD-07b 跑 |
| PG 测试全是 SKIP | `CLAPI_TEST_DB_URI` 没传进容器 |
| cpgateway `TestPythonParityFlows` 停在 169 或 206 行 | 2026-09-30 之前的既有问题（206 行测试过时、169 行 SQLite 表锁），已修；现在再停在这两处说明测试库没换成临时文件 SQLite（`cpgateway/src/dbs/db.go`、`src/apis/main_test.go`），或测的不是工作区的代码，见 BUILD-07b |
| `TestNodeAlarmRulesLabelOwnerAndRuleGroup` 等节点告警测试报 `open ../../../deploy/roles/monitor/templates/...: no such file or directory` | 打包时没带 `deploy/roles/monitor/templates`（BUILD-07b 的 `tar` 要带上它），或 `.j2` 还是 CRLF（`sed` 也要覆盖 `*.j2`） |
| 本机能编译、1.26 容器里编译失败 | 用了 Go 1.27 才有的东西，见 BUILD-06 |
| Go 测试报数据库相关失败 | cpgateway 测试默认用内存 SQLite，注意不要漏了 CGO；跑 PostgreSQL 版要显式给 `CPGATEWAY_TEST_DB_URI` 且必须是**空库** |
| 某个测试因为别的测试留下的数据而失败 | 新增测试污染了全局断言的用例。清理要用**原始 SQL**，GORM 的 `Delete(&X{}, id)` 会 panic（`reflect.Value.Field on int64 Value`） |
| `ssh work-01` 报 `Connection closed by ... port 22` | 短时间内开了太多 SSH 连接被限流，等一分钟，把命令合并 |
