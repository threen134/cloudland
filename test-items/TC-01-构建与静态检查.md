## BUILD-01 前端类型检查（vue-tsc）

**P0**

```bash
ssh work-01 'cd /tmp/wc2 && docker run --rm -v /tmp/wc2:/app -w /app node:22 npm run typecheck 2>&1 | tail -30'
```

检查项：

- [ ] 退出码 0，无 `error TS` 输出

### ⚠️ 必须用 `vue-tsc`，不能用 `tsc`

`tsc` **根本不解析 `.vue` 文件**（SFC 被 `vite-env.d.ts` 的 `declare module '*.vue'` 兜成 `DefineComponent`）。`package.json` 的 `build` 脚本曾经是 `tsc -b && vite build`，导致模板和 `<script setup>` 里的类型错误从项目开始就一次都没被检查过，积累到 94 条才被发现（2026-09-21）。

**回归点**：任何人改了 `web/package.json` 的 `build` / `typecheck` 脚本，先确认它用的是 `vue-tsc`：

```bash
ssh work-01 'grep -E "\"(build|typecheck)\"" /tmp/wc2/package.json'
# 期望： "build": "vue-tsc -b && vite build"   "typecheck": "vue-tsc -b --force"
```

- [ ] `build` 与 `typecheck` 都用 `vue-tsc`

## BUILD-02 文案校验（i18n）

**P0**

```bash
ssh work-01 'cd /tmp/wc2 && docker run --rm -v /tmp/wc2:/app -w /app node:22 npm run i18n:check 2>&1 | tail -30'
```

校验三件事：三个语言包（`en` / `zh` / `zh-TW`）键对齐、代码里 `t('x.y')` 用到的键都存在、模板与代码里没有写死的用户可见文案。

- [ ] 退出码 0

### 历史缺陷回归点

| 现象 | 根因 | 判定 |
|---|---|---|
| 创建虚拟机页面直接显示 `marketplace.cancel` 这种键名 | 误判为「无用残留」把文案键删了 | **vue-i18n 找不到键时把键名当文案显示，既不报错也不抛异常**。所以 `t('a') \|\| t('b')` 这种回退写法永远不会生效（`t('a')` 返回的键名是真值）。删任何文案键前先 grep 引用点 + 跑本检查 |

- [ ] 页面上没有出现形如 `dashboard.xxx.yyy` 的原始键名（UI 冒烟时一并看，见 `TC-12`）

### ⚠️ `semi: false` 的坑

prettier 配置是 4 空格 / 无分号 / 单引号 / 120 列。`semi: false` 会把模板里 `@click="a(); b()"` 这种**两句的内联事件处理器**拆成两行并去掉分号，Vue 模板解析器直接报错。

- [ ] 内联事件处理器只写一句；多于一句必须抽成方法

## 失败时怎么办

| 现象 | 大概率原因 |
|---|---|
| 类型检查报一堆你没碰过的文件 | `/tmp/wc2/node_modules` 是旧的，重新 `npm ci` |
| `Cannot find package 'typescript'` | 在没装依赖的目录（如 `/opt/cloudland/web`）跑了检查 |
| Go 测试报数据库相关失败 | cpgateway 测试默认用内存 SQLite，注意不要漏了 CGO；跑 PostgreSQL 版要显式给 `CPGATEWAY_TEST_DB_URI` 且必须是**空库** |
| 某个测试因为别的测试留下的数据而失败 | 新增测试污染了全局断言的用例。清理要用**原始 SQL**，GORM 的 `Delete(&X{}, id)` 会 panic（`reflect.Value.Field on int64 Value`） |
