# TC-05 安全组（SG）

优先级 **P0** · 会在计算节点上下发 iptables 链 · 约 25 min

## 设计约定

- **只有系统自动创建的默认组**（系统默认组、组织默认组、VPC native 组）预置对全网开放的 22/3389（`SecgroupAdmin.Create` 的 `withLoginRules`）。用户经 API 创建的组，**无论 `is_default` 是什么都不预置**。
- 实例的「登录端口」只改虚拟机内 sshd/RDP 的端口，**不自动放行安全组**。前端留空时后端按镜像类型取 22/3389。
- 规则端口语义：
  - tcp / udp：端口范围。API 显式传入必须 1–65535；**不传表示全部端口**。
  - icmp：复用 `port_min` / `port_max` 存 **type(0–254) / code(0–255)**，`-1` 表示任意。
  - PATCH 不传端口沿用原值；协议在「端口类」与「非端口类」之间切换时，改为 tcp/udp 必须传端口。
- VPC 子网上的安全组必须属于该 VPC。

## SG-01 列表页

**P0**

列表页是标准表格：名称/ID、VPC、入站/出站规则数、关联网卡数、创建时间、编辑/删除。服务端分页 20 条 + 名称搜索（`query`）+ VPC 筛选（`vpc_id`）。**规则管理只在详情页**。

```bash
ssh work-01 'source /root/alarmtest-env.sh
api GET "/security_groups?limit=1"          | jq -c "{total, n:(.security_groups|length)}"
api GET "/security_groups?query=rb"         | jq -c "{total, names:[.security_groups[].name]}"
V=$(api GET /vpcs | jq -r ".vpcs[]|select(.name==\"rb-vpc\")|.id")
api GET "/security_groups?vpc_id=$V"        | jq -c "{total, names:[.security_groups[].name]}"'
```

### 检查项

- [ ] 返回 `{total, security_groups}`，`limit=1` 只回 1 条
- [ ] `query` 按名称过滤生效，`total` 随之变化
- [ ] `vpc_id` 过滤生效（**按 VPC 过滤，不是按名称模糊匹配**）
- [ ] 列表里每行的 `vpc` 显示的是**这一行自己的** VPC
  > **回归点**：`SecgroupAdmin.List` 曾复用列表语句查路由器（GORM Statement 复用），列表返回的 `vpc` 实际是另一条安全组的 UUID 和名称。详情接口正常，只有列表错。修法是取新会话查询。
- [ ] 超过 50 个组时能翻到第 51 个以后
  > **回归点**：前端曾不传 `limit`，后端默认只回 50 条且前端本地过滤。

### 布局

- [ ] 1600 / 1400 / 1280 / 1100 px 宽度下无横向溢出
- [ ] 视口 < 1280px 时「描述」列隐藏
- [ ] 400px 宽时表格在容器内横向滚动（页面本身不横向滚动）

## SG-02 创建安全组与规则

**P0** · 脚本 `write-paths-e2e.js`（含安全组 + 规则）

### 步骤

界面：安全组页 → 新建 → 名称 `wp-sg` + 选 VPC → 提交 → 进详情页 → 添加规则。

```bash
ssh work-01 'source /root/alarmtest-env.sh
V=$(api GET /vpcs | jq -r ".vpcs[]|select(.name==\"rb-vpc\")|.id")
cat > /tmp/sg.json <<JEOF
{"name":"wp-sg","vpc":{"id":"$V"}}
JEOF
G=$(curl -sk -X POST "$B/security_groups" -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d @/tmp/sg.json | jq -r .id)
echo "组=$G"
api GET /security_groups/$G | jq -c "{name, rules:[.security_rules[]?|{direction,protocol,port_min,port_max,remote_cidr}]}"'
```

### 检查项

- [ ] 创建成功
- [ ] **用户创建的组不预置 22/3389**（`rules` 为空）
- [ ] 详情页能加入站 / 出站规则
- [ ] tcp 规则不传端口 → 表示全部端口
- [ ] icmp 规则 `port_min=8` / `port_max=0` 存的是 type/code，`-1` 表示任意
- [ ] 协议从 icmp 改成 tcp 时，不传端口被拒绝

## SG-04 编辑与删除

**P1**

```bash
ssh work-01 'source /root/alarmtest-env.sh
G=$(api GET /security_groups | jq -r ".security_groups[]|select(.name==\"wp-sg\")|.id")
echo "--- 只改描述"
api PATCH /security_groups/$G "{\"description\":\"hello\"}" | jq -c "{name,description,is_default}"
echo "--- 清空描述"
api PATCH /security_groups/$G "{\"description\":\"\"}"      | jq -c "{name,description}"
echo "--- 改名"
api PATCH /security_groups/$G "{\"name\":\"wp-sg-renamed\"}" | jq -c "{name,description}"'
```

### 检查项

- [ ] 只改描述时**名称不被清空**
- [ ] **描述能被清空**（改成空字符串后确实是空）
  > **回归点**：`SecurityGroupPatchPayload` 的字段原先是值类型（`string`/`bool`），分不清「没传」和「传了空值」。改成指针（`*string` / `*bool`）后才能表达「显式清空」。同时 `is_default` 的守卫只在**显式传 false** 时才触发。
- [ ] 改名后描述保持不变
- [ ] 默认安全组的删除按钮禁用，提示「默认安全组不能删除」
- [ ] 删除规则失败时**有提示**（不是静默失败）
  > **回归点**：详情页曾用原生 `confirm()` / `alert()`，删除规则失败时无任何提示。现在统一用组件。

## SG-05 规则在节点上真正生效

**P0**

这是安全组最关键的一条 —— 数据库里有规则不等于流量被拦住。

### 步骤

在测试虚拟机所在节点上：

```bash
ssh work-0X 'iptables -S FORWARD | head -10'
ssh work-0X 'iptables -S | grep secgroup-in-tap | head'
```

从外部访问虚拟机上**未放行**的端口：

```bash
timeout 5 nc -vz <虚拟机浮动IP> <未放行端口>; echo "退出码=$?"
```

### 检查项

- [ ] 三个节点上都下发了 `secgroup-in-tap<xxx>` / `secgroup-out-tap<xxx>` 链
- [ ] 访问未放行端口的结果是**超时**（被安全组 DROP）
  - 若是**立刻 connection refused**，说明安全组被**绕过**了 —— 见下方回归点 1
- [ ] 放行后立刻可访问
- [ ] 删除规则后恢复超时

### ⚠️ 回归点 1：FORWARD 链顺序

安全组是否生效取决于 FORWARD 链的顺序：

- 安全组跳转由 `apply_fw` 插在**第 3 条**
- 网桥内部放行（`-i brX -o brX -j ACCEPT`）**必须排在它之后**

`report_rc.sh` 的 `sync_instance` 曾用 `iptables -I FORWARD 2` 插入，导致**节点重启后，开机时已存在的网桥（如 br756）上所有虚拟机的安全组被完全绕过**。（来自上游 `77e1b809` + `d788855e`，分叉时带入。）

修法：`sync_instance` 与 `apply_bridge` 都改为**追加到链尾**，再把兜底 REJECT 移到最后。

```bash
ssh work-0X 'iptables -S FORWARD'
```

- [ ] `-j secgroup-*` 或 `apply_fw` 的跳转在 `-i brX -o brX -j ACCEPT` **之前**
- [ ] 兜底 REJECT 在**最后**

**节点重启后必须重跑这一条**（见 `TC-14`）。

## 历史缺陷回归点汇总

| # | 现象 | 根因 |
|---|---|---|
| 1 | 节点重启后 br756 上所有虚拟机的安全组被绕过 | FORWARD 链插入位置，见 SG-05 |
| 2 | 列表页 `vpc` 列显示别的安全组的 VPC | GORM Statement 复用 |
| 3 | 超过 50 个组看不到 | 前端不传 limit |
| 4 | 清空描述无效 | Patch payload 用值类型而非指针 |
| 5 | 删除规则失败无提示 | 用了原生 `confirm()`/`alert()` |
| 6 | `query` 参数可注入绕过组织过滤 | 安全组列表曾把 `query` 直接当 WHERE 拼进 SQL。见 `TC-13 SEC-01` |
| 7 | 上游 PET-1344「安全组规则重叠检查」**有意未合入**（上游自己 revert 了） | 不要把「允许重叠规则」当 bug |
