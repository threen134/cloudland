## 发现并修掉的问题（TC-24 回归点 9–13）

1. **GPFS 隔离永远失败**：`gpfs_expelled` 只拿 `mmexpelnode -l` 的第一列（地址）比节点名。改为地址或括号里的节点名对上都算，读不出列表时隔离与解除都失败（`gpfs_cluster.sh`）
2. **刚对账完就解除 GPFS 隔离**：开机约 60 秒解除，GPFS 加入撞上开机同步，节点内核网络锁卡死（sshd `Exceeded MaxStartups`、cloudlet 卡住、hung task 全在等 `rtnl_lock`），其他节点等它的 RPC，work-01 被系统卸载 fs1、work-02 元数据操作卡住。缓解：对账完成 5 分钟后才自动解除带命令的隔离（`storage_fence.go` 的 `storageUnfenceSettle`）。根因没查清
3. **驱逐活着的节点后文件系统冻结约一分钟**，紧接着的疏散失败。`do_fence` 驱逐后等本机 GPFS 文件系统重新响应（最长 5 分钟）
4. **`create_link.sh` 的 VXLAN 上联口 NM 激活失败后不补救**（S6 之前就有）：work-01 的 `v-11120682` 从 2026-10-02 起一直 DOWN、不在网桥里，它上面的云服务器和其他节点二层不通。改为最后都确保在网桥里且 UP；修好后 work-01 ↔ work-02 的云服务器互通
5. **再疏散时原因还是上次的「疏散失败」**：认领时清空原因（`evacuate.go`）

## 排查手段（这次用上的）

- **节点 sshd 拒连、cloudlet 只剩保活时进不去**：经 cland 下发命令要排在 cloudlet 的串行队列后面，队列卡住时也发不出去；只能断电重启。之后看上一次开机的日志：`/var/adm/ras/mmfs.log.<时间>.<主机>`（`mmfs.log.previous`）、`journalctl -b -1 -k` 里的 hung task 栈、`journalctl -b -1 -u cloudlet-go` 最后执行到哪条命令
- **复现时先开一个不断的 SSH 会话**：会话里每 2 秒 `timeout 3 ip -br link`，卡住就 `echo t > /proc/sysrq-trigger` 把所有任务的内核栈写进 dmesg（已建立的会话不受 MaxStartups 影响）
- **GPFS 被一个卡住的节点拖住时**：在管理节点上 `mmdiag --waiters` 看等谁的 RPC，`mmexpelnode -N <它>` 先驱逐，其他节点几十秒内恢复；被系统卸载的节点 `mmmount`，上面开着文件的云服务器要强制重启
- work-03 的公网 22 端口一直有人在试密码（77.239.124.69），sshd 的 MaxStartups 本来就紧，节点一卡就立刻拒连

**发现并修掉的问题（TC-24 回归点 14–15）**

6. **升级时停掉文件系统管理节点，所有节点上 gp1 的写停一分钟左右**：节点离开后 GPFS 要等它的租约过期才恢复（每次都是 56–64 秒「delay for safe recovery」），这段时间如果离开的正是文件系统管理节点，新管理节点在恢复里，需要分配块的写全部卡住。`gpfs_upgrade.sh` 在 `mmshutdown` 之前把本节点的文件系统管理节点与集群管理节点角色交给另一台挂着文件系统的仲裁节点（`move_managers`，`mmchmgr <fs> <节点>`、`mmchmgr -c <节点>`）。找「另一台活着的节点」要问守护进程（`mmlsmount all -L -Y` + `mmlscluster -Y`），**不能用 `mmgetstate -a`**：它经 ssh 问其他节点，只有管理节点有集群密钥，在别的节点上全部是 `unknown`（第一版就是这样，一个角色都没移）。验证（在 work-01 上照升级的做法停 GPFS 100 秒，先迁走它上面用 gp1 的云服务器）：不移角色时其他节点上的云服务器停 25、26、80 秒，移角色后 4–5 秒
7. **完成升级没有把文件系统格式升上去**：`mmchfs -V full` 要在标准输入上确认（「Do you want to continue?」），没有输入时什么也不改、照样退出 0，任务报成功。改为 `printf 'yes
' |` 给它确认，之后用 `mmlsfs -V -Y` 核对 `filesystemVersion` 等于 `filesystemHighestSupported`，不等就失败
