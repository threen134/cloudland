## FAIL 明细

都是**既有问题**，不是放置组引入的。

### FAIL-1 新组织在 clapi 里被解析成组织 ID 0（严重）

- **现象**：管理员新建的组织同步到 clapi 后，这个组织的所有请求在 clapi 里都是 `OrgID=0`，建出来的资源 owner=0。另一个新组织（同样是 0）能列出、能读取它的资源：实测组织 C 列出并读到了组织 B 建的放置组。响应里 owner 还显示成「Admin」（见 FAIL-3）。
- **定位**：`services/org.go` 的 `UpsertOrgByUUID`，新建分支 `db.Create(&model.Organization{...})` 建的是另一个结构体，之后 `orgIDByUUID.Store(uuID, org.ID)` 存进缓存的 `org.ID` 是 0；`GetOrgIDByUUID` 先查缓存，于是一直返回 0，直到 clapi 重启或同一组织再同步一次。clapi 日志里有证据：`EXIT OrgAdmin.UpsertOrgByUUID: ok id=0`。
- **影响**：
  - 从 2026-09-16 按 UUID 同步组织起就存在。
  - 不是所有资源都拦得住：放置组、密钥这类只查角色的创建会以 owner=0 建成；VPC 碰巧被拦下，因为建默认安全组时 `CheckResourceOrg` 看到 owner=0 拒绝了。
  - 审计里的 `org_id` 也是 0。
- **处理**：未修。测试后用内部同步接口重推了 B、C 两个组织（缓存改正为 33、34），owner=0 的那条放置组直接在库里软删。

### FAIL-2 自助注册的组织从不同步到区域

- **现象**：注册 → 管理员启用用户 → 审批组织后，这个组织调任何区域接口都返回 404（`OrgNotFound`）；cpgateway 的用量对账每次也 404。
- **定位**：cpgateway 只有 `CreateOrg`（管理员建组织）调 `SyncOrgToAllRegions`；注册、审批都不同步，要等区域重新上线才全量推送。
- **处理**：未修。

### FAIL-3 `GetOrgName(0)` / `GetOrgUUID(0)` 返回第一条组织

- **现象**：owner=0 的资源在响应里显示 owner「Admin」、`owner_uuid` 是 Admin 的。
- **定位**：`&model.Organization{Model: model.Model{ID: id}}` 再 `Take`，ID 为 0 时 GORM 不带主键条件，取到第一行。
- **处理**：未修。

### FAIL-4 救援期间状态不是 `rescuing`（VM-11）

- **现象**：救援后十秒内状态就变成 `shut_off`。第二次救援请求也返回 204，界面显示「已关机」。
- **定位**：`rescue_vm.sh` 的回调没有 handler（clapi 记 `no command rescue_vm found`，CLAUDE.md 已记）；心跳按主域 inst-N「已关机」把状态改了。于是「已在救援中」的判断、「救援时拒绝扩容」（CLAUDE.md 记为已修）都拦不住。
- **处理**：未修。

### FAIL-5 卡住的创建被删除后，`boot` 预留不释放（PG-25 发现）

- **现象**：管理员指定宿主机建的成员命令丢失，删掉后 3 号节点内置池上 10 GB 的 `boot` 预留还在，要等 24 小时过期。
- **定位**：`boot` 预留只在创建下发失败（`launchNotSent`）、`create_volume` 回调、`launch_vm` 回调三处释放；删除实例和 `clear_vm` 回调都不释放。
- **处理**：未修，测试后手动删了这条。

### FAIL-6 改名不校验 2–32（VM-04）

- **现象**：接口接受 1 个字符和 33 个字符的名字。
- **定位**：`InstancePatchPayload.Hostname` 只有 `hostname|fqdn`；详情页、列表页的改名弹窗只判非空（创建弹窗用了 `isValidName`）。
- **处理**：未修。

### FAIL-7 列表规格列没有规格名（VM-08）

- **现象**：规格列只有「2C / 2G」。
- **定位**：接口返回 `flavor: ""`。创建接口只把 cpu、内存、磁盘传给服务层，不传规格，库里 135 条实例的 `flavor_id` 全是 0。
- **处理**：未修。

### FAIL-8 创建云服务器弹窗的下拉超过 50 条会缺项（VM-01）

- **现象**：取资源列表时不带 `limit`，后端默认只回 50 条（CLAUDE.md 早已记着未修）。现在资源都不到 50 条，没实际缺项。
- **处理**：未修。

### FAIL-9 迁移列表把已结束的回滚显示成「回滚中」（MIG-06）

- **现象**：`rollback` 是终态，列表文案看起来像还在进行。
- **处理**：未修。
