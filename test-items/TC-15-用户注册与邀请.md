除 REG-04 外全部是 **cpgateway** 侧的接口，不经 clapi、不涉及区域。

## 前置

- 有一个可登录的管理员账号（`source /root/alarmtest-env.sh` 得到 `$B` / `$T` / `api`）
- Admin 组织 uuid `305fcaf9-c76a-4ed5-a1ae-eddb8d8fc64e`（系统组织，`org_type` 2，属主是 `admin`）
  > 多条执行线并行时，邀请与成员管理（INV-* / MEM-01）改在管理员新建的 `wp-*` 组织上做，把下文的 `ADMIN_ORG` 换成它（2026-09-28 晚这样跑过，判定口径不变）；INV-07 10.3 仍要用「非系统组织」。

### ⚠️ 测试数据必须每轮换名字

**用户名全局唯一、注销后也不能复用**（`DELETE /users/:uuid` 只改邮箱，用户名永久占着）。所以测试用户名、组织 slug 一律带本轮后缀，旧版用例里固定的 `functest_reg_user` 跑过一次就再也注册不了。界面注册只允许字母和数字、字母开头，用户名按这个规则取（接口本身只校验非空）。

每轮开始先生成本轮的名字，之后每一步都 `source /tmp/wp-reg.env`：

```bash
ssh work-01 'S=$(date +%s | tail -c 6); cat > /tmp/wp-reg.env <<EOF
S=$S
REG_EMAIL=wp-reg-$S@example.com
REG_USER=wpreg$S
REG_PASS=FuncTest123
REG_ORG=wp-reg-$S
INV_NEW=wp-inv-$S@example.com
INV_CANCEL=wp-cancel-$S@example.com
INV_ACCEPT=wp-accept-$S@example.com
ACC_USER=wpacc$S
ADMIN_ORG=305fcaf9-c76a-4ed5-a1ae-eddb8d8fc64e
EOF
cat /tmp/wp-reg.env'
```

用普通用户身份调接口时用下面两个函数（放在每段命令开头；`login` 走表单登录，不吊销别的 token）：

```bash
login(){ curl -sk -X POST "$B/auth/token/form" --data-urlencode "username=$1" --data-urlencode "password=$2"; }
uapi(){ curl -sk -X "$1" "$B$2" -H "Authorization: Bearer $UT" -H "Content-Type: application/json" ${3:+-d "$3"}; }
```

请求体一律写成文件再 `-d @file`（`api` / `uapi` 的第三个参数可以直接写 `@/tmp/x.json`）。

步骤编号沿用旧版的 1–13（执行记录里按它对照），2026-09-28 新增的接在后面：INV-08 是 14.x，REG-04 是 15.x。执行顺序按本文件从上到下。

### 角色码与状态码

| 值 | 组织角色 | 邀请状态 | 组织状态 | 用户 `status` |
|---|---|---|---|---|
| 0 | — | Pending | PENDING（注册待审批） | invited（邀请占位用户） |
| 1 | Reader（观察者） | Accepted | ACTIVE | active |
| 2 | Writer（编辑者） | Expired | SUSPENDED | dormant（已激活但不属于任何组织 / 刚注册） |
| 3 | Admin（管理员） | Cancelled | DISABLED | disabled |

### ⚠️ 列表返回体形状（2026-09-20 起）

网关侧列表**已改为服务端分页**（`offset` / `limit` 默认 50 上限 500 / `query`），返回的是对象不是裸数组：

| 接口 | 返回 |
|---|---|
| `GET /orgs` | `{"orgs": [...], "total": N}` |
| `GET /users` | `{"total": N, "users": [...]}` |
| `GET /orgs/:uuid/members` | `{"members": [...], "total": N}`（含邀请中的记录） |
| `GET /regions`、`GET /notification-channels` | `{"total", "regions"}`、`{"total", "channels"}` |
| `GET /orgs/:uuid/invitations` | `[...]` ← **仍是裸数组**，只列 Pending |
| `GET /auth/me/orgs` | `[...]` ← **裸数组，不分页**（组织切换器用它） |

- [ ] 任何解析这些列表的地方都按上表取值

参数或请求体格式不对（邮箱不合法、缺字段、slug 不符合 `^[a-z0-9][a-z0-9-]*[a-z0-9]$`）一律 **422**（FastAPI 风格的 `{"detail": [{loc, msg, type}]}`），业务错误是 400 / 401 / 403 / 404 + `{"detail": "..."}`。

## INV-08 接受邀请（2026-09-28 新增）

**P1** · 建用户（`ACC_USER`，用户名之后永久占用）

```bash

acc(){ printf "{\"token\":\"%s\",\"username\":\"%s\",\"password\":\"%s\"}" "$TK" "$1" "$2" > /tmp/wp-acc.json
  curl -sk -w " %{http_code}\n" -X POST $B/auth/invitation/accept -H "Content-Type: application/json" -d @/tmp/wp-acc.json; }
acc admin FuncTest123; acc "$ACC_USER" ""; acc "$ACC_USER" FuncTest123; acc "$ACC_USER" FuncTest123'
```
