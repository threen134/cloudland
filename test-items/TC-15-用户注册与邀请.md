# TC-15 用户注册与邀请（REG / INV / MEM / USR）

优先级 **P1** · 会创建用户、组织、邀请 · 约 20 min

全部是 **cpgateway** 侧的接口，不经 clapi、不涉及区域。

## 前置

- 有一个可登录的管理员账号
- 先跑「预清理」把上次残留的测试用户 / 组织 / 邀请删掉，否则唯一约束会让用例假失败

### 测试数据

| 用途 | 值 |
|---|---|
| 注册用户 | `functest_reg@example.com` / `functest_reg_user` / `FuncTest123` |
| 注册时建的组织 | `FuncTest Org` / slug `functest-org` |
| 邀请新邮箱 | `functest_invite_new@example.com` |
| 取消邀请用 | `cancel_test@example.com` |

### 角色码

| 值 | 角色 |
|---|---|
| 1 | Reader（观察者） |
| 2 | Writer（编辑者） |
| 3 | Admin（管理员） |

邀请状态：`0` = Pending。

### ⚠️ 列表返回体形状（2026-09-20 起）

网关侧列表**已改为服务端分页**，返回的是对象不是裸数组：

| 接口 | 返回 |
|---|---|
| `GET /orgs` | `{"orgs": [...], "total": N}` |
| `GET /users` | `{"total": N, "users": [...]}` |
| `GET /orgs/:uuid/members` | `{"members": [...], "total": N}` |
| `GET /orgs/:uuid/invitations` | `[...]` ← **仍是裸数组** |

- [ ] 任何解析这些列表的地方都按上表取值

## 历史缺陷回归点

| # | 现象 | 根因 |
|---|---|---|
| 1 | 用已注销用户的用户名注册报 **500** | 查重没用 `Unscoped` |
| 2 | 非管理员改名返回 403（应为 400） | 改名规则调整后，所有角色统一 400 |
| 3 | 组织列表接口 500（`COUNT(organizations.*)`） | GORM 计数复用了带 `Select("organizations.*")` 的语句 |
| 4 | 解析 `/orgs`、`/users`、`/members` 的地方按裸数组处理会直接崩 | 2026-09-20 网关列表改服务端分页，返回体变成 `{资源, total}` |

## 范围说明

- 这些都是 **cpgateway 内部的操作**，**不进 clapi 的审计日志与组织动态**（`TC-11 ORG-07` 只覆盖 clapi 的操作）。这是已知范围，不是缺陷。
- 注册接口的 `language`：繁体仍传 `zh`（邮件模板只有中英文）。
- 激活 token 是 **HS256**（对称 `SECRET_KEY`），24 小时过期，与访问 token 的 RS256 不同。
