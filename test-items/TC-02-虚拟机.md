# TC-02 虚拟机（VM）

优先级 **P0** · 会真实创建虚拟机 · 约 30 min

## 设计约定

### IP 是怎么配进虚拟机的

IP 由 clapi 分配（`addresses` 表），下面两种方式**只负责把这个地址配到虚拟机里**：

| 方式 | 适用 | 机制 |
|---|---|---|
| config drive | **所有子网** | `build_meta.sh` 生成 `network_data.json`（静态 IP / 网关 / DNS / MTU），由镜像内 cloud-init 应用。Windows 由 qemu-guest-agent 执行 netsh/PowerShell |
| DHCP | **仅 VPC 内部子网**（VNI > 4095） | 路由器 netns 内每 VNI 一个 dnsmasq，按 `dhcp_hosts` 做 MAC→IP 静态绑定（`dhcp-ignore=tag:!known`）。给不支持 cloud-init 的镜像兜底 |

**普通 VLAN 子网（public / private）按设计不提供 DHCP**。不带 cloud-init 的镜像（如 cirros）在这类子网拿不到 IP，**是预期行为，不是 bug**。

### 创建请求体

```json
{
  "hostname": "wp-vm",
  "image": {"id": "<uuid>"},
  "flavor": "<规格名，不是 uuid>",
  "zone": "zone0",
  "hypervisor": "<hyper uuid，可省略由调度选择>",
  "keys": [{"id": "<uuid>"}],
  "login_port": 22,
  "primary_interface": {"subnets": [{"id": "<uuid>"}], "security_groups": [{"id": "<uuid>"}]},
  "secondary_interfaces": []
}
```

约束：

- 子网与虚拟机 VPC 一致
- VPC 子网上的安全组须属于该 VPC
- 同一网卡的子网同 VLAN；**辅助网卡 VLAN 须不同**
- `hypervisor` 要求是 **uuid**，传 hostid 会返回 `Field validation for 'Hypervisor' failed on the 'uuid' tag`

## VM-01 界面创建虚拟机

**P0** · 脚本 `create-vm-e2e.js`

### 步骤

云服务器页 → 新建 → 镜像 / 规格 / VPC / 子网 / 密钥 / 安全组 → 提交。

### 检查项

- [ ] 创建弹窗所有必填下拉**都有可选项**（见 `TC-12 UI-02`）
- [ ] 规格下拉显示形如 `vmtest-small (2 vCPU, 2 GB RAM, 10 GB 磁盘)`，数字不为 0
- [ ] 提交后状态 `provisioning` → `running`（约 1–2 分钟）
- [ ] 分配到的 IP 落在所选子网网段内
- [ ] 无 4xx/5xx，`pageerrors: none`

### 资源列表不应被 50 条截断

- [ ] 安全组 / VPC / 子网超过 50 条时，下拉里仍能找到第 51 个以后的
  > **回归点**：创建虚拟机页取这三个列表时不传 `limit`，后端默认只回 50 条会缺项。

### 涉及接口

| 方法 | 路径 |
|---|---|
| POST | `/api/v1/instances`（返回**数组**，支持 `count` 批量） |
| GET | `/api/v1/instances`（`offset`/`limit`/`query`/`order`） |
| GET | `/api/v1/instances/:id` |
| PATCH | `/api/v1/instances/:id`（`power_action` / 改名） |

## VM-02 内部子网 DHCP 与 DNS

**P0**

```bash
RT=<router 编号>
ssh work-0X "ip netns exec router-$RT grep DHCPACK /var/log/dnsmasq.log | tail -3"
ssh work-0X "ip netns exec router-$RT ssh -o StrictHostKeyChecking=no ubuntu@<虚拟机IP> 'ip -4 -br addr; cat /etc/resolv.conf'"
```

- [ ] dnsmasq 日志里有该虚拟机 MAC 的 `DHCPACK`
- [ ] 虚拟机内 IP 与接口返回一致
- [ ] DNS 指向路由器网关，能解析
- [ ] VPC 虚拟机的 Ubuntu 登录用户名是 **`ubuntu`**（不是 root）；cirros 是 `cirros`

> **注意**：VPC 网关是 anycast，「从 A 节点的 netns ping B 节点上的虚拟机」必然不通。验证要在虚拟机所在节点做。

## VM-03 电源操作

**P0**

```bash
ssh work-01 'source /root/alarmtest-env.sh
I=<实例 id>
for a in stop start restart; do
  echo "--- $a"; api PATCH /instances/$I "{\"power_action\":\"$a\"}" | jq -c "{status}"
  sleep 20; api GET /instances/$I | jq -c "{status}"
done'
```

- [ ] `stop` → `shut_off`
- [ ] `start` → `running`
- [ ] `restart` → 回到 `running`
- [ ] 每个操作都进**审计日志与组织动态**（`PATCH /instances/:id` 由 `SetAuditAction` 按 `power_action` 细化）

## 历史缺陷回归点汇总

| # | 现象 | 根因 |
|---|---|---|
| 1 | 详情页云硬盘容量不显示 | 后端 `VolumeInfoResponse` 缺 `size` |
| 2 | 规格参数区的 flavor 对象分支永不成立 | `flavor` 是字符串 |
| 3 | 创建页资源下拉缺项（>50 条） | 不传 `limit` |
| 4 | 节点重启后安全组被绕过 | FORWARD 链顺序，见 `TC-05 SG-05` |
| 5 | 删除虚拟机后数据卷没回到 available | `clear_vm` 回调 |
| 6 | 计算节点上 `NODE_ID` 丢失导致回调主机 ID 为空、clapi 返回 400 | 节点用了 sudo-rs（忽略 `sudo -E`）。必须切回经典 sudo |
