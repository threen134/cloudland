# TC-02 虚拟机（VM）

优先级 **P0** · 会真实创建虚拟机 · 约 40 min（VM-12–VM-15 另约 20 min，VM-14 要停 cland-go）

## 设计约定

### IP 是怎么配进虚拟机的

IP 由 clapi 分配（`addresses` 表），下面两种方式**只负责把这个地址配到虚拟机里**：

| 方式 | 适用 | 机制 |
|---|---|---|
| config drive | **所有子网** | `build_meta.sh` 生成 `network_data.json`（静态 IP / 网关 / DNS / MTU），由镜像内 cloud-init 应用。Windows 由 qemu-guest-agent 执行 netsh/PowerShell |
| DHCP | **仅 VPC 内部子网**（VNI > 4095） | 路由器 netns 内每 VNI 一个 dnsmasq，按 `dhcp_hosts` 做 MAC→IP 静态绑定（`dhcp-ignore=tag:!known`）。给不支持 cloud-init 的镜像兜底 |

**普通 VLAN 子网（public / private）按设计不提供 DHCP**。不带 cloud-init 的镜像（如 cirros）在这类子网拿不到 IP，**是预期行为，不是 bug**。

### 创建请求体

```json
{
  "hostname": "wp-vm",
  "image": {"id": "<uuid>"},
  "flavor": "<规格名，不是 uuid>",
  "zone": "zone0",
  "count": 1,
  "hypervisor": "<hyper uuid，仅系统管理员，可省略由调度选择>",
  "storage_pool": {"id": "<存储池 uuid，可省略 = 默认池 local>"},
  "placement_group": {"id": "<放置组 uuid，可省略，见 TC-18>"},
  "keys": [{"id": "<uuid>"}],
  "login_port": 22,
  "vpc": {"id": "<uuid>"},
  "primary_interface": {"subnets": [{"id": "<uuid>"}], "security_groups": [{"id": "<uuid>"}]},
  "secondary_interfaces": []
}
```

约束（以 `apis/instance.go` 的 `InstancePayload` 与 `services/instance.go` 的 `Create` 为准，2026-09-28 核对）：

- 子网与虚拟机 VPC 一致；VPC 子网上的安全组须属于该 VPC
- 同一网卡的子网同 VLAN；**辅助网卡 VLAN 须不同**；网卡里 `subnet`（单个）和 `subnets`（数组）都认，界面发的是 `subnet`
- `hypervisor` 要求是 **uuid**，传 hostid 会返回 `Field validation for 'Hypervisor' failed on the 'uuid' tag`；**非系统管理员带这个字段一律 403**（VM-13）
- `count` 1–16；`count > 1` 时不能带公网地址（`public_addresses`），主机名依次是 `<hostname>-1 … -N`
- 镜像的文件大小超过规格磁盘时 400（111906 `DiskTooSmall`）：`ubuntu-24.04-minimal` 是 3.5 GB，只能用 `vmtest-small` / `vmtest-large`；`vmtest-tiny`（1 核 / 512 MB / 1 GB）只配 `cirros-0.6.2`
- 成功返回 **200 + 数组**；命令在事务提交**之后**才下发（`executeCommandList`）

## 前置：临时 VPC、子网与密钥

```bash
ssh work-01 'source /root/st-env.sh; source /root/wp-lib.sh
ssh-keygen -t ed25519 -N "" -q -f /root/wp-key <<<y >/dev/null
jq -n --arg k "$(cat /root/wp-key.pub)" "{name:\"wp-key\",public_key:\$k}" > /tmp/wp-key.json
api_code POST /keys @/tmp/wp-key.json >/dev/null; ws key $(jq -r .id $BODY)   # api_code reads -d @file too
api_code POST /vpcs "{\"name\":\"wp-vpc\"}" >/dev/null; ws vpc $(jq -r .id $BODY)
cat > /tmp/wp-net.json <<JEOF
{"name":"wp-net","network_cidr":"192.168.183.0/24","gateway":"192.168.183.1","type":"internal","vpc":{"id":"$(wl vpc)"}}
JEOF
api_code POST /subnets @/tmp/wp-net.json >/dev/null; ws subnet $(jq -r .id $BODY); cat /root/wp-e2e.state'
```

> `api_code` 的第三个参数原样交给 `curl -d`，写成 `@文件` 就是读文件。`gateway` 只能是纯 IP（带 `/24` 返回 400）。
