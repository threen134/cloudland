# CloudLand API 功能测试 — 用户 & 邀请流程

对应脚本：`test_user_invitation_api.sh`

## 前置条件

- 系统中已有一个管理员账户（admin）
- 管理员可以正常登录并获取 token
- 清理历史残留的测试数据（用户、组织、邀请）

## 测试用例

### 1. 用户自主注册

**1.1 正常注册新用户**
- 使用邮箱 `functest_reg@example.com`、用户名 `functest_reg_user`、密码 `FuncTest123` 注册，同时创建组织（名称 `FuncTest Org`，slug `functest-org`）
- 预期：返回 HTTP 201，响应体包含 `user.uuid` 字段

**1.2 重复组织 slug 注册**
- 使用不同的邮箱和用户名，但使用与 1.1 相同的 org slug `functest-org` 注册
- 预期：返回 HTTP 400，拒绝注册

**1.3 未激活用户尝试登录**
- 使用 1.1 注册但尚未激活的用户凭据登录
- 预期：返回 HTTP 401，登录被拒绝

### 2. 用户激活

**2.1 管理员激活用户**
- 管理员调用 `PUT /users/{uuid}/enable` 激活 1.1 注册的用户
- 预期：返回 HTTP 200

**2.2 激活后用户可以登录**
- 使用已激活用户的凭据登录
- 预期：返回 HTTP 200，响应体包含 `access_token` 字段

**2.3 已激活用户重复注册**
- 使用已激活用户的邮箱，搭配不同用户名和新组织信息再次注册
- 预期：返回 HTTP 400，拒绝重复注册

### 3. 用户信息 & 组织访问

**3.1 获取当前用户信息**
- 已登录用户调用 `GET /auth/me`
- 预期：返回 HTTP 200，`username` 字段与注册时一致

**3.2 获取用户所属组织列表**
- 已登录用户调用 `GET /auth/me/orgs`
- 预期：返回 HTTP 200

**3.3 访问未加入的组织**
- 普通用户尝试访问管理员的组织 `GET /orgs/{admin_org_uuid}`
- 预期：返回 HTTP 403，无权限

### 4. 邀请已有用户加入组织

**4.1 邀请已注册用户**
- 管理员向已注册用户的邮箱发送邀请，角色为 Writer（2）
- 预期：返回 HTTP 201，邮箱正确，角色为 2，状态为 Pending（0）

**4.2 列出待处理邀请**
- 管理员调用 `GET /orgs/{uuid}/invitations` 获取邀请列表
- 预期：返回 HTTP 200，列表中至少包含 1 条记录

**4.3 通过 token 获取邀请信息**（跳过）
- 需要邀请 token，当前测试环境无法直接从数据库获取，跳过

### 5. 邀请新用户加入组织

**5.1 邀请全新邮箱用户**
- 管理员向一个系统中不存在的邮箱 `functest_invite_new@example.com` 发送邀请，角色为 Reader（1）
- 预期：返回 HTTP 201，邮箱正确，角色为 1

### 6. 重复邀请（覆盖旧邀请）

**6.1 对同一邮箱再次发送邀请（不同角色）**
- 管理员再次向 `functest_invite_new@example.com` 发送邀请，角色改为 Admin（3）
- 预期：返回 HTTP 201，角色更新为 3，且新邀请的 UUID 与旧邀请不同（旧邀请被覆盖）

### 7. 邀请已是成员的用户

**7.1 邀请组织现有成员**
- 管理员尝试邀请自己（已是组织成员）加入组织
- 预期：返回 HTTP 400，拒绝邀请

### 8. 取消邀请

**8.1 取消一个待处理邀请**
- 先创建一个邀请（发给 `cancel_test@example.com`），然后调用 `DELETE /orgs/{uuid}/invitations/{inv_uuid}` 取消
- 预期：返回 HTTP 204

**8.2 取消后邀请不在列表中**
- 取消后重新获取邀请列表
- 预期：列表中不再包含已取消的邀请

**8.3 重复取消同一邀请**
- 再次尝试删除同一个已取消的邀请
- 预期：返回 HTTP 404

### 9. 无效 Token 接受邀请

**9.1 使用无效 token 接受邀请**
- 使用伪造的 token 调用 `POST /auth/invitation/accept`
- 预期：返回 HTTP 400

**9.2 使用无效 token 查询邀请信息**
- 使用伪造的 token 调用 `GET /auth/invitation/info`
- 预期：返回 HTTP 400

### 10. 非管理员无权发送邀请

**10.1 普通用户尝试向别人的组织发送邀请**
- 使用普通用户的 token，尝试向管理员的组织发送邀请
- 预期：返回 HTTP 403，无权限

### 11. 成员管理

**11.1 管理员直接添加成员**
- 管理员调用 `POST /orgs/{uuid}/members` 将测试用户添加为 Reader（1）
- 预期：返回 HTTP 201

**11.2 修改成员角色**
- 管理员调用 `PATCH /orgs/{uuid}/members/{user_uuid}` 将角色改为 Writer（2）
- 预期：返回 HTTP 200，`org_role` 为 2

**11.3 列出成员**
- 管理员获取组织成员列表
- 预期：返回 HTTP 200，成员数 >= 2

**11.4 移除成员**
- 管理员调用 `DELETE /orgs/{uuid}/members/{user_uuid}` 移除测试用户
- 预期：返回 HTTP 204

**11.5 不能移除组织 Owner**
- 管理员尝试移除自己（组织 Owner）
- 预期：返回 HTTP 400，拒绝操作

### 12. 用户管理

**12.1 获取用户列表**
- 管理员调用 `GET /users`
- 预期：返回 HTTP 200

**12.2 获取用户详情**
- 管理员调用 `GET /users/{uuid}` 查看测试用户详情
- 预期：返回 HTTP 200，`username` 正确

**12.3 禁用用户**
- 管理员调用 `PUT /users/{uuid}/disable`
- 预期：返回 HTTP 200

**12.4 被禁用用户尝试登录**
- 使用被禁用用户的凭据登录
- 预期：返回 HTTP 403，登录被拒绝

**12.5 重新启用用户**
- 管理员调用 `PUT /users/{uuid}/enable`
- 预期：返回 HTTP 200

**12.6 启用后可以登录**
- 使用重新启用的用户凭据登录
- 预期：返回 HTTP 200

### 13. 清理测试数据

- 删除注册的测试用户
- 删除注册用户创建的组织
- 取消所有测试中创建的待处理邀请
