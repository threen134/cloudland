# VPN 网关

VPN 网关把一个 VPC 与外部网络接通，提供两种接入，可以只开一种，也可以同时开：

- **站点到站点（IPsec）**：与机房防火墙、路由器、公有云的 VPN 网关或另一个 CloudLand VPC 建立加密隧道，两边的网段互通。路由可以是静态的，也可以用 BGP 动态交换。
- **客户端到站点（WireGuard）**：个人电脑、手机用 WireGuard 客户端接入 VPC，访问 VPC 里的云服务器。

每个 VPC 最多一个 VPN 网关。设计与实现细节见 [VPN 网关设计](../architecture/plan/vpn-gateway-plan.md)。

---

## 概念

| 对象 | 说明 |
|---|---|
| **VPN 网关** | 挂在一个 VPC 上，有一个或多个公网地址，跑在两个计算节点上互为备份 |
| **站点连接** | 一个远端站点：远端网段、路由方式（静态 / BGP）、IKE / ESP 参数 |
| **隧道** | 站点连接下的一条 IPsec 隧道：我方一个公网地址对对端一个公网地址。一条连接可以有多条隧道，互为备份或分担流量 |
| **客户端** | 一个 WireGuard 接入设备，从客户端地址池里分到一个地址 |

「主」「备」在三个层级上都会出现，意思不同，界面与本文统一按下表称呼：

| 层级 | 名称 | 含义 |
|---|---|---|
| 网关 | 高可用模式：**主备 / 双活** | 两个网关节点之间怎么分工 |
| 站点连接 | 流量分配：**主隧道优先 / 负载分担** | 一条连接的多条隧道之间怎么分流 |
| 隧道 | **主隧道 / 备隧道** | 主隧道优先时，哪条隧道承载流量 |

::: tip 主备网关 ≠ 主隧道 / 备隧道
主备网关说的是**节点**：平时所有隧道都在主节点上，主节点故障时在备节点上重建。主隧道 / 备隧道说的是**一条连接里的隧道**：备隧道平时已经建好，主隧道断开时只切换路由。双活网关上的连接同样可以是「主隧道优先」。
:::

## 选择高可用模式

创建网关时选定，**创建后不能修改**。

| | 主备 | 双活 |
|---|---|---|
| 工作方式 | 主节点跑全部隧道，公网地址是浮动地址，主节点故障时随备节点接管 | 两个节点各有一个固定公网地址，各跑自己的隧道，两个节点都承载流量 |
| 公网 IP | 1 个，可以再加第 2 个 | 2 个（节点 1、节点 2），开客户端 VPN 再加 1 个 |
| 我方节点故障时的中断 | 隧道在备节点上重建：BGP 计时器 3 / 9 秒时约 9 秒，默认计时器约 30 秒 | 切到另一个节点上已建好的隧道：BGP + BFD 约 1–2 秒 |
| 对端要求 | 没有特别要求 | 对端要能同时接受我方两个地址的连接，并能快速发现隧道失效 |
| 一条连接的隧道数 | 1–4 条 | 1–2 条（每个节点一条） |
| 可用区里的可用计算节点 | 至少 1 个；只有 1 个时单节点运行、没有高可用 | 至少 2 个 |

**怎么选**：对端是另一个 CloudLand 网关或支持 BFD 的路由器时，双活切换更快。对端是 IBM Cloud VPN 这类「一条连接只认一个对端地址、不能跨连接分担流量」的设备时，用**主备网关加一条连接**更好（见[与 IBM Cloud VPN 对接](#与-ibm-cloud-vpn-对接)）。

## 创建网关

在左侧菜单「网络 → VPN 网关」点「创建」：

1. **VPC**：已有 VPN 网关的 VPC 不能选。
2. **可用区**：默认自动。主备网关在可用区只有一个可用计算节点时也能建，但只在这一个节点上运行、**没有高可用**（界面标「单节点」），可用区有了第二个可用节点后会自动补上备节点；双活网关需要两个可用节点。可用节点不够时创建直接报错。
3. **高可用模式**：主备或双活。
4. **公网地址**：选公网子网后从空闲地址里挑，也可以留空自动分配。主备填 1 个；双活要填节点 1、节点 2 各一个，开客户端 VPN 时再填客户端地址。
5. **能力**：站点到站点 VPN（IPsec）、客户端 VPN（WireGuard），至少开一个。开客户端 VPN 时填客户端地址池（默认 `10.8.0.0/24`，不能与 VPC 子网重叠）和监听端口（默认 51820）。

节点准备好后，网关从「创建中」变成「可用」，通常在 1 分钟内。

**配额**：每个组织在每个区域能建的 VPN 网关数单独计算（默认 1 个）；网关的每个公网地址计入公网 IP 配额。

**加减公网地址**：详情页「概览」里，主备网关可以加第 2 个公网地址（有隧道用着时不能删），双活网关可以加减客户端地址。

## 添加站点连接

详情页「站点连接」点「添加连接」。

### 基本参数

| 参数 | 说明 |
|---|---|
| 预共享密钥 | 两端必须一致。8–128 个可打印 ASCII 字符，不能含引号和反斜线 |
| 本地网段 | 允许远端访问的 VPC 网段，多个用逗号分隔；留空表示 VPC 的全部内部子网 |
| 远端网段 | 对端站点后面的网段 |
| 路由方式 | 静态路由，或 BGP |

**网段不能冲突**：远端网段不能是 `0.0.0.0/0`，不能与本 VPC 的子网、VRRP 子网 `192.168.196.0/24`、`169.0.0.0/8`、同一网关上其他连接的远端网段、客户端地址池重叠。

### 隧道

- **数量**：主备网关 1–4 条。我方两个公网地址各连对端两个地址时是 4 条「全连接」，能扛住两边各坏一处的交叉故障。双活网关 1–2 条，每个节点一条。
- **每条隧道**：本端公网地址（双活时是节点）、对端公网地址、对端 IKE 标识。对端地址留空表示**只响应**对端发起的连接，这时必须填对端 IKE 标识。
- **流量分配**（两条及以上时）：
  - **主隧道优先**（默认）：流量走主隧道，主隧道断开时备隧道按顺序接管。
  - **负载分担（ECMP）**：所有在线的隧道按数据流分担流量。对端也要支持在多条隧道上分担，否则回程只走其中一条。

### BGP 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| 本端 ASN / 对端 ASN | — | 必填 |
| 隧道内地址 | — | 每条隧道一对，同一个 /30，例如 `169.254.10.1` / `169.254.10.2`（可以用 `169.254.0.0/16`，AWS、Azure 就要求这个范围） |
| 远端汇总网段 | — | **必填**。只接受对端通告的、落在这些网段内的前缀，其余一律拒绝 |
| 最大前缀数 | 1000 | 超出只记告警，不断开会话 |
| Keepalive / Hold | 10 / 30 秒 | 节点故障时要等 Hold 到期才切换，**建议两端都改成 3 / 9 秒**或开 BFD |
| BFD | 关闭；开启后 1000 毫秒 × 3 | 需要对端也支持 BFD |
| AS 路径前置次数 | 2 | 备隧道通告路由时把本端 ASN 重复这么多次，让对端优先走主隧道 |

我方通告给对端的网段就是本地网段。

### 高级参数

| 参数 | 默认 |
|---|---|
| IKE 提议 / ESP 提议 | `aes256-sha256-modp2048`（AES-256、SHA-256、DH 组 14） |
| IKE / ESP 生存时间 | 86400 / 3600 秒 |
| 对端失效检测（DPD） | restart，每 10 秒 |
| 本端 IKE 标识 | 本端公网地址 |
| 由本网关主动发起隧道 | 是。对端在 NAT 之后等必须由对端发起的情况下取消 |

提议支持的算法：`aes128`、`aes192`、`aes256`、`aes128gcm16`、`aes256gcm16`、`chacha20poly1305`；`sha1`、`sha256`、`sha384`、`sha512`；`prfsha256`、`prfsha384`、`prfsha512`；`modp1024`、`modp2048`、`modp3072`、`modp4096`、`ecp256`、`ecp384`、`ecp521`、`curve25519`。多个提议用逗号分隔。

::: warning 安全组
隧道建立后，远端站点访问云服务器的流量仍要经过云服务器的安全组。记得在安全组里放行远端网段。
:::

## 配置对端设备

在连接那一行点「对端配置」，弹窗列出对端设备要配的全部参数：

- 每条隧道两端的公网地址、IKE 标识、预共享密钥，BGP 连接的隧道内地址；
- IKE / IPsec 参数（提议附常见写法）、生存时间、DPD、由谁发起、NAT 穿越、隧道 MTU；
- 路由：静态路由列出每一对网段（每对一个子 SA），BGP 列出两端 ASN、计时器、BFD、我方通告与接受的范围；
- 哪条是主隧道、对端该怎么配合；
- 按这条连接的实际配置给出的建议，例如 BGP 计时器太长、双活网关对对端的要求、主隧道该对着对端哪个地址。

可以「复制全部」或「下载 .txt」交给对方管理员。**内容里有明文的预共享密钥和 BGP 口令，请通过安全的渠道发送**。平台只给通用参数，不生成特定品牌设备（Cisco、FortiGate 等）的配置片段。

对端配置要点：

- 只支持 **IKEv2 + 预共享密钥**。
- BGP 连接、以及有多条隧道的连接，对端要用**基于路由的 VPN**（VTI / 隧道接口）。
- 我方把经过隧道的 TCP MSS 钳制到 1320，对端最好也做同样的钳制。
- 我方不主动发起时，对端必须配置为主动发起。

## 查看预共享密钥与 BGP 口令

- **编辑者及以上角色**：连接展开行和对端配置里能看到预共享密钥和 BGP 口令，默认打码，点眼睛图标显示、点复制图标复制。
- **观察者**：只能看到「已设置 / 未设置」，对端配置里也不含密钥。
- **修改密钥**：编辑连接，填入新的预共享密钥；留空表示保留当前密钥。两端都要改，改的时候隧道会重建。

平台代生成的 WireGuard 客户端私钥**不保存**，只在创建时显示一次。

## 客户端 VPN（WireGuard）

详情页「客户端」点「添加客户端」：

- **密钥对**：
  - **使用我自己的公钥**（推荐）：在设备上生成密钥对，只把公钥粘贴进来，私钥不离开设备。
  - **由平台生成**：私钥只在创建完成时显示一次，平台不保存，请立即下载配置。
- **附加预共享密钥**：默认勾选，在密钥对之上再加一层对称密钥。

创建后下载配置导入 WireGuard 客户端即可。之后再下载的配置不含私钥，要把 `<your private key>` 换成设备上的私钥。

- **客户端能访问的网段**由网关的「客户端路由」决定，留空表示 VPC 的全部内部子网。不支持全流量（`0.0.0.0/0`）。
- **DNS**：默认不下发，客户端用自己的 DNS。需要时在网关设置里填「客户端 DNS」，写进客户端配置的 `DNS =` 一行：
  - 要解析 VPC 内部名称，填 VPC 子网里自建的 DNS 服务器地址，并在它的安全组里放行来自客户端地址池的 53 端口（UDP / TCP）。只有落在「客户端路由」里的地址才走隧道。
  - 填 8.8.8.8 这类公网地址也可以，但查询走客户端本地网络、不经 VPN，解析不了 VPC 内部名称，只是替换了客户端的系统 DNS（可能影响客户端所在内网的域名解析）。
  - 子网网关地址不提供 DNS，填了解析不了。
- **停用 / 启用**：单个客户端可以随时停用，几秒内生效；重新启用后客户端要等自己重新握手，十几秒恢复。
- **客户端与站点不互通**：客户端只能访问 VPC，不能经网关访问远端站点，这是有意的限制。

## 状态与监控

**连接状态**（「站点连接」列表的状态列）：

| 状态 | 含义 |
|---|---|
| 等待中 | 配置正在下发 |
| 已连接 | 主隧道在线（负载分担时全部隧道在线） |
| 降级 | 只有备隧道在线（负载分担时部分隧道在线） |
| 未连接 | 没有隧道在线 |
| 错误 | 配置下发失败 |
| 已停用 | 网关已停用 |

**隧道列**：每条隧道一行，行末的圆点是这条隧道的状态（鼠标悬停显示文字）；BGP 连接还有一个 BGP 标签，绿色表示会话已建立，黄色表示未建立，灰色表示还没有上报，悬停显示 BGP 与 BFD 状态。点开一行可以看到每条隧道的详细信息：建立时间、流量、BGP 收到 / 通告 / 被拒绝的前缀等。

**监控**：详情页「监控」标签有流量曲线，可选 1 小时到 30 天，可以按隧道拆分。隧道建立约 1 分钟后开始有数据，数据保留 30 天。

**网关状态为「错误」**时，详情页顶部的红色提示条写明原因（例如哪个节点没建成），列表里鼠标悬停在状态上也能看到。排除原因后对网关做任意一次修改（例如改描述），就会重新下发配置。

**告警**：单条隧道断开触发 `VpnTunnelDown`（警告），整条连接断开触发 `VpnConnectionDown`（严重），恢复后自动解除。配置了通知渠道时会发送通知。

**重建**：连接那一行的重启按钮可以重建整条连接，或只重建其中一条隧道。

## 故障切换时间

实测的典型值（第三方节点上的云服务器视角）：

| 场景 | 中断 |
|---|---|
| 主备网关，主节点故障，BGP 3 / 9 秒 | 约 9 秒 |
| 主备网关，主节点故障，BGP 默认 10 / 30 秒 | 约 30 秒 |
| 主隧道断开，BGP + BFD（1000 毫秒 × 3） | 约 2.4 秒 |
| 主隧道断开，BGP + BFD（300 毫秒 × 3） | 约 0.7 秒 |
| 主隧道断开，BGP 3 / 9 秒，不开 BFD | 约 7 秒 |
| 主隧道断开，静态路由 | 约 20 秒，取决于对端的失效检测 |
| 双活网关，一个节点断网，BGP + BFD | 1–2 秒 |

要快速切换就用 **BGP**，并缩短计时器或开 BFD。静态路由只能靠 DPD 发现隧道断开。

## 停用与删除

- **停用**（详情页「操作」菜单）：所有隧道和客户端立即中断，公网 IP 与全部配置保留，约 1 秒生效。启用后约 20 秒恢复流量。
- **删除**：网关下的站点连接和客户端一并删除，公网 IP 释放，隧道立即中断，不可恢复。

## 与 IBM Cloud VPN 对接

已实测互通（IKEv2、AES-256 / SHA-256 / DH 14）。IBM Cloud VPN 网关的几个特点决定了推荐配法：

- 一条连接只认一个对端地址，不同连接之间不能分担流量，跨连接切换回程要 30 秒以上。
- 没有 BFD，只有 DPD；发现隧道断开实际要 17–26 秒。
- 回程固定走它公网地址较小的那个成员。

推荐：

1. 用**主备网关、一条连接、两条隧道**，我方从同一个地址出发，分别连 IBM 的两个成员地址。
2. **主隧道对着 IBM 地址较小的成员**，否则去程和回程会走不同的隧道。对端配置弹窗在主隧道没对准时会提示。
3. 连接的 `distribute_traffic` 保持关闭（打开后 IBM 按源地址分流，备隧道断开时部分地址的回程会中断约 30 秒）。
4. 静态路由即可；BGP 学到的路由不会自动进 IBM 的 VPC 路由表。

## 限制

- 站点到站点只支持 IKEv2 + 预共享密钥，不支持 IKEv1、证书认证。
- 客户端只支持 WireGuard，不支持 OpenVPN、IKEv2 客户端，不支持全流量模式。
- 只支持 IPv4。
- 每个 VPC 一个网关；高可用模式创建后不能改。
- 双活网关每条连接最多 2 条隧道。
- 可用区只有一个可用计算节点时，主备网关只在这个节点上运行，没有高可用。

## 常见问题

**网关标着「单节点」**
创建时可用区里只有一个可用计算节点，网关只在这个节点上运行，该节点故障时 VPN 中断。给可用区加一个可用节点后，平台会在几分钟内自动补上备节点，标签随之消失，补的过程中不中断业务。

**网关一直是「创建中」**
节点还在下发配置，通常 1 分钟内完成。时间明显更长时，到「计算节点」页面看网关所在可用区的节点是否在线；配置失败时网关会变成「错误」并显示原因。

**连接一直「未连接」**
逐项核对：预共享密钥、两端的 IKE 标识、IKE / ESP 提议是否一致；对端防火墙是否放行我方公网地址的 UDP 500、UDP 4500 和 ESP；我方不主动发起时对端是否在主动发起。

**BGP 会话起不来**
核对两端 ASN、隧道内地址（同一 /30、两端互为对方）、BGP 口令；对端是否是基于路由的 VPN。

**对端通告的网段访问不到**
看连接展开行里被拒绝的前缀：落在远端汇总网段之外的前缀会被丢弃，需要放宽汇总网段。

**隧道通了但访问不到云服务器**
检查云服务器的安全组是否放行了远端网段。

**流量曲线是空的**
刚建好的隧道要等约 1 分钟；一直没有数据时请联系平台管理员检查监控采集（见部署手册「运维管理与故障排查」）。
