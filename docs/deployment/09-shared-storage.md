# 部署共享存储（GPFS）

共享存储让同一块云硬盘可以挂到**任何一台**能访问存储的计算节点上的云服务器：卷文件放在集群文件系统里，迁移云服务器时这块盘不用复制。本文讲如何在 CloudLand 界面上部署 IBM Storage Scale（GPFS）集群、建共享存储池，以及日常运维。

设计细节见 `docs/architecture/plan/shared-storage-design.md`（§16 S1、S2 有实施与验收记录）。

> **现在能做什么**（2026-10-03）：
>
> - **能**：部署三台及以上的 GPFS 副本集群；导入已有的 GPFS 集群；在集群上建共享存储池；共享池里的**数据盘**（建、挂、扩容、删）；带共享数据盘的云服务器迁移（共享盘不复制）；加节点、加盘、移除盘、移除节点、重新均衡
> - **还不能**：**系统盘放共享池**（选共享池建云服务器会被拒绝，属于后续阶段 S4）；GPFS 纠删码版的 ECE 布局；健康看护与告警（S5，现在只会自动拉起掉线的 NSD）
> - **Ceph** 见[部署共享存储（Ceph）](./10-ceph-storage.md)

---

## 概念

| 名词 | 是什么 |
|---|---|
| **软件包** | IBM 的 GPFS 安装包（自解压脚本），先上传到平台的软件包仓库，部署时各节点从仓库下载 |
| **存储集群** | 一组计算节点组成的 GPFS 集群。**托管**的由 CloudLand 部署和运维；**导入**的由存储管理员自己管，CloudLand 只使用 |
| **NSD** | 加进 GPFS 文件系统的一块盘，名字形如 `cl<集群号>h<节点号>d<序号>` |
| **共享存储池** | 集群文件系统上的一个目录，在托管集群上是一个独立 fileset（`cl_<池 UUID 前 8 位>`），挂在每个成员节点的同一路径（`/gpfs/<文件系统>/<fileset>`） |
| **任务** | 部署、加盘、建池等操作都是分步骤的任务，在「存储集群」页的「任务」标签和任务详情页里看每台节点每一步的进度与日志；失败后停在出错的那一步，可以重试或中止 |

一台计算节点**只能属于一个 GPFS 集群**。

## 前置要求

| 项目 | 要求 |
|---|---|
| 节点系统 | **Ubuntu 22.04 或 24.04**，GA 系列内核（`5.15.0-*-generic` / `6.8.0-*-generic`）。**26.04 不行**：GPFS 6.0 编不过 7.0 内核。同一区域可以混用，只有成员节点要求这两个版本 |
| 节点数 | 至少 **3 台**（仲裁节点必须是奇数、至少 3 个；磁盘至少分布在 3 台上）。测试布局可以 1 台，只用于测试 |
| 磁盘 | 每台 NSD 节点至少一块空闲盘（不是系统盘、没有挂载、没有被本地池占用） |
| 软件包仓库 | 控制面要配置 S3（`S3_ENDPOINT`，内置 MinIO 即可），安装包存在里面 |
| 网络 | 成员节点之间内网互通，端口 22、1191 |
| 空间 | 每台 `/var/mmfs` 所在文件系统至少 10 GiB 空闲 |
| 内存 | 每台成员从可分给云服务器的内存里预留 **pagepool + 1 GiB**（默认 2 GiB） |
| 其他 | Secure Boot 关闭（要加载自己编的内核模块）；时间已同步；内核头文件包能装上 |

GPFS 只有安装包里列出的发行版能装（6.0.0.2 是 Ubuntu 22.04 / 24.04）。

## 第一步：上传安装包

界面「存储 → 软件包」→「上传」：

1. 选存储类型（GPFS），选本地的安装包文件（如 `Storage_Scale_Erasure_Code-6.0.0.2-x86_64-Linux-install`，约 1.7 GB）。也可以填一个下载地址，由平台自己拉取。
2. 文件按 8 MiB 一片顺序上传，有进度条。**中途断网或点了「停止」，已传的部分保留**：按钮变成「继续上传」，从断点接着传；关掉弹窗后再选同一个文件也会接着传。没传完的包 24 小时后自动清理。
3. 传完后平台校验 SHA-256、解析版本、版本类型（数据访问版 / 数据管理版 / 纠删码版）、支持的发行版和许可证，状态变为「可用」。
4. 点该行的「许可证」，阅读全文后勾选并「接受许可证」。**没接受许可证的包不能用来部署。**

各节点部署时从仓库下载，缓存在 `/opt/cloudland/cache/storage-pkg/<SHA-256>/`，之后加节点、重装直接用缓存。

## 第二步：扫描磁盘

在每台要加入的节点上「扫描磁盘」（计算节点详情 → 存储，或 `POST /hypers/{uuid}/disks/scan`，约 10 秒），确认要用的盘显示为「空闲」。磁盘状态的含义见[配置本地存储池](./08-storage-pools.md)。

装了 GPFS 的节点上：

- 带 GPFS 分区类型（新格式 NSD）的盘显示为 `unknown_member`，不能选，也不能勾「擦除」拿去用
- 没有签名、但盘头 4 MiB 不全为零的盘也显示为 `unknown_member`（可能是旧格式 NSD）；全新的盘和 CloudLand 释放时擦过的盘（两端各清零 10 MiB）显示为空闲
- 已经属于某个集群的盘显示为 `gpfs_nsd`

## 第三步：创建集群

界面「存储 → 存储集群」→「新建集群」，按向导走：

| 步骤 | 内容 |
|---|---|
| 类型 | 「部署 GPFS」（托管）或「导入外部 GPFS」 |
| 软件 | 选已接受许可证的安装包 |
| 节点与磁盘 | 勾选节点、为每台选角色、选磁盘。默认第一台是「管理 + 仲裁 + NSD」，其余「仲裁 + NSD」 |
| 参数 | 文件系统名（默认 `fs1`）、块大小（1M–16M，默认 4M）、数据副本数（2 或 3，默认 2）、pagepool（默认 1024 MiB）；「测试布局」只用于单机测试 |
| 预检 | 在每台节点上检查一遍（下表），全部通过才能进入下一步 |
| 确认 | 填集群名（字母开头，最多 63 个字母、数字和 `. _ -`），开始部署 |

**角色规则**：仲裁节点奇数、至少 3 个；管理节点 1–2 个且必须同时是仲裁节点；NSD 节点至少一块盘；磁盘至少分布在 3 台节点上（每台一个失败组）；数据副本数不超过失败组数。元数据固定 3 副本。

**预检项**：系统与内核（`os`）、内核头文件（`kernel_headers`）、Secure Boot、时间同步、到其他成员的 22 / 1191 端口（`network`）、每块盘的身份与是否空闲（`disk <id>`）、`/var/mmfs` 的空间、内存（可分给云服务器的内存和将要预留的量）、包管理器没被占用、主机名、节点上是否已有不归 CloudLand 管的 GPFS（`existing`）。

**部署过程**（12 步，三台实测约 7–9 分钟）：预检 → 加入（写集群 SSH 密钥、预留内存）→ 下载安装包 → 安装 → 编译内核模块 → 集群内 SSH 信任 → 建集群 → 启动（GPFS 自己有约 90 秒的安全恢复等待）→ 核对磁盘身份 → 建 NSD → 建文件系统并全部挂上 → 收尾。部署后：

- 每台 `/gpfs/<文件系统>` 挂好，开机由 `mmautoload` 自动启动并挂载（`gpfs.service` 显示 disabled 是正常的）
- `/var/mmfs/etc/nsddevices` 只列本集群认领的盘，GPFS 看不到别的盘
- 内核相关的包被 `apt-mark hold`，避免升级内核后模块不匹配
- 设置了 `autoload=yes`、`autoBuildGPL=yes`、`restripeOnDiskFailure=yes`

**任务失败**：停在出错的那一步，任务详情里能看到每台节点的报错和日志末尾。修好原因（比如节点断网、包管理器被占用）后点「重试」，只重跑失败的那几台；或「中止」后删除集群重来。节点离线 5 分钟会把它的这一步判失败。

## 第四步：建共享存储池

界面「存储 → 存储池」→「新建共享池」：

| 字段 | 说明 |
|---|---|
| 集群、文件系统 | 只列就绪的集群 |
| 名称 | 区域内唯一 |
| 介质 | 文件系统有多种介质时，按介质放到对应的 GPFS 存储池；只有一种时选「不限」 |
| 配额（GB） | 设了配额的池容量就是配额（`df` 显示配额）。**0 表示不设**：不设配额的池与同一文件系统、同一 GPFS 存储池上其他不设配额的池**共用**容量 |
| inode 上限 | 云硬盘是少量大文件，默认 100000 足够 |
| 超分比例 | 已分配的总量最多为「容量 × 比例」 |

建池是集群上的任务（约 30 秒）：建 fileset、设配额、建 `volumes/ images/ nvram/ tmp/` 与 `.cloudland-pool` 标记文件，再把池清单发给所有成员节点。之后改配额（存储池详情或 `PATCH /storage_pools/{id}` 的 `quota_gb`）也是一个任务。

**删池**：池里还有卷时拒绝（409）；空池删除时先从各节点撤掉清单、再删 fileset。

## 使用共享池

- **建云硬盘**：选共享池即可。卷在建卷时就由任一能访问这个池的节点落盘（几秒内从「创建中」变「可用」），不属于任何一台机器
- **挂载**：可以挂给任何一台「这个池可用」的节点上的云服务器；卸下后可以换一台节点再挂，数据不变。磁盘以 `cache='none'`、`error_policy='stop'` 挂载
- **扩容**：挂着的卷在线扩容（虚拟机不重启，立即看到新容量），没挂的离线扩容；虚拟机内仍要自己扩展分区和文件系统
- **删卷**：异步（返回 202），由任一能访问池的节点删文件
- **迁移**：共享盘留在原地不复制，迁移计划里标为「共享，不复制」；系统盘仍按本地盘的方式复制。实测带 3 GB 共享数据盘的热迁移 9 秒完成
- **系统盘**：现在**不能**放共享池，指定了会被拒绝；创建云服务器时的「系统盘存储池」下拉里不列共享池
- **默认池**：共享池可以设为默认池，之后不指定池的云硬盘落在它上面；云服务器的系统盘不受影响，没指定池时仍落在内置池 `local`

**可用性**：每台节点每 30 秒探测一次池（文件系统类型、标记文件、能否写），状态变化或每 5 分钟上报。某台节点上的池不可用时（GPFS 没挂上、标记文件不对、探测卡住），往这台节点上的云服务器挂卷会被拒绝并说明原因；探测在池没挂上时**不会**往根文件系统上写任何东西。15 分钟没有上报的节点按不可用处理。

**开机**：节点重启后，磁盘在共享池上的云服务器先进「待启动列表」（界面显示「等待存储就绪」），等 GPFS 挂上、本次开机后的第一次探测通过再自动启动。实测重启一台节点后约 4–5 分钟全部恢复；重启期间集群保持另外两台在线，其他节点上的云服务器不受影响。

## 运维

在集群详情页操作（都是集群上的任务，一次只能跑一个）：

| 操作 | 说明 |
|---|---|
| 添加节点 | 新节点先预检，再安装软件、加入集群；选了盘的同时加进文件系统 |
| 添加磁盘 | 只列集群成员上的空闲盘；NSD 名接着已有的编号 |
| 移除磁盘 | 先把数据迁到其他盘（`mmdeldisk`），再从节点上擦掉盘。移除后剩下的布局仍要满足角色规则，否则拒绝 |
| 移除节点 | 节点上有本集群池里的卷挂着的云服务器时拒绝；有盘先移盘，仲裁节点先降为非仲裁，再删节点，最后清理节点上的 GPFS |
| 离线移除 | 节点已永久损坏时用，要求节点离线并输入主机名；盘以「已损坏」方式移除，节点上不做清理 |
| 重新均衡 | 加盘之后把数据分到所有盘（`mmrestripefs -b`），耗时且 I/O 重，按需手动做 |
| 删除集群 | 要输入集群名确认，可选同时卸载软件包；集群上还有池时拒绝。删除后节点上没有 GPFS 的进程、密钥、挂载、内存预留，盘被擦除、扫描为空闲 |

**掉线的 NSD**：节点重启后它的盘由 GPFS 自己的自动恢复拉起（`restripeOnDiskFailure`）；平台每分钟再检查一次，所有节点都 active 时把仍然 down 的盘启动（`mmchdisk start -a`，10 分钟最多一次），日志在管理节点的 `/opt/cloudland/log/storage/gpfs-disks-up.log`。

**导入外部集群**：节点已经是那个集群的成员（GPFS 由对方管理员装好、文件系统已挂载）。向导里选「导入外部 GPFS」、选节点、填文件系统名与挂载点，平台只检查不改动。之后建共享池时填文件系统上已有的目录（通常是独立 fileset 的入口），平台在里面建子目录；删池、删除集群都只是取消登记，不执行任何 `mm` 命令。

## 常见问题

- **预检不过**：任务详情里按节点逐项列出原因。常见的是内核不在支持列表（26.04、HWE 内核）、`existing`（节点上有别人装的 GPFS）、盘有数据（勾「擦除」）、包管理器被 unattended-upgrades 占着（等几分钟再预检）
- **部署卡在某一步**：任务详情看那台节点的日志末尾；节点上完整日志在 `/opt/cloudland/log/storage/run-<run id>.log`，GPFS 自己的日志在 `/var/adm/ras/mmfs.log.latest`
- **池在某台节点上不可用**：`mount -t gpfs` 看是否挂着、`/usr/lpp/mmfs/bin/mmgetstate -a` 看守护进程、`cat <池目录>/.cloudland-pool` 看标记文件；节点上的探测结果在 `/opt/cloudland/run/pools/<池 UUID>.state`
- **NSD 一直 down**：`/usr/lpp/mmfs/bin/mmlsdisk <文件系统>`；所有节点都 active 后平台会自动启动，也可以手工 `mmchdisk <文件系统> start -a`
- **新盘在 GPFS 节点上显示 `unknown_member`**：盘头有旧数据。确认盘上没有要的东西后在节点上 `wipefs -a` 并把开头 4 MiB 清零，再扫描
- **节点能不能装**：GPFS 节点只能是 Ubuntu 22.04 / 24.04 的 GA 内核；内核升级前确认 `mmbuildgpl` 能编过，部署时已经 hold 住内核包
