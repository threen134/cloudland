# 部署共享存储（GPFS）

共享存储让同一块云硬盘可以挂到**任何一台**能访问存储的计算节点上的云服务器：卷文件放在集群文件系统里，迁移云服务器时这块盘不用复制。本文讲如何在 CloudLand 界面上部署 IBM Storage Scale（GPFS）集群、建共享存储池，以及日常运维。

设计细节见 `docs/architecture/plan/shared-storage-design.md`（§16 S1、S2、S4 有实施与验收记录）。

> **现在能做什么**（2026-10-06）：
>
> - **能**：部署三台及以上的 GPFS 副本集群；导入已有的 GPFS 集群；在集群上建共享存储池；共享池里的**数据盘**（建、挂、扩容、删）与**系统盘**（S4：从池里的镜像副本克隆，建、重装、救援、捕获镜像、删除）；云服务器迁移时共享盘不复制，磁盘全在共享池里时只迁内存；加节点、加盘、移除盘、移除节点、重新均衡；健康检查与告警、监控曲线、任务的完整日志、换坏盘、改角色、新节点自动加为客户端、孤儿对账（S5）；节点宕机后的隔离与疏散、密钥轮换、滚动升级（S6）
> - **纠删码布局（ECE）**：第一版能部署、删除、建存储池、轮换密钥，加减节点和盘、换盘、升级还不行，见下面「纠删码布局（ECE）」一节
> - **Ceph** 见[部署共享存储（Ceph）](./10-ceph-storage.md)

---

## 概念

| 名词 | 是什么 |
|---|---|
| **软件包** | IBM 的 GPFS 安装包（自解压脚本），先上传到平台的软件包仓库，部署时各节点从仓库下载 |
| **存储集群** | 一组计算节点组成的 GPFS 集群。**托管**的由 CloudLand 部署和运维；**导入**的由存储管理员自己管，CloudLand 只使用 |
| **NSD** | 加进 GPFS 文件系统的一块盘，名字形如 `cl<集群号>h<节点号>d<序号>` |
| **共享存储池** | 集群文件系统上的一个目录，在托管集群上是一个独立 fileset（`cl_<池 UUID 前 8 位>`），挂在每个成员节点的同一路径（`/gpfs/<文件系统>/<fileset>`） |
| **任务** | 部署、加盘、建池等操作都是分步骤的任务，在「存储集群」页的「任务」标签和任务详情页里看每台节点每一步的进度与日志；失败后停在出错的那一步，可以重试或中止 |

一台计算节点**只能属于一个 GPFS 集群**。

## 前置要求

| 项目 | 要求 |
|---|---|
| 节点系统 | **Ubuntu 22.04 或 24.04**，GA 系列内核（`5.15.0-*-generic` / `6.8.0-*-generic`）。**26.04 不行**：GPFS 6.0 编不过 7.0 内核。同一区域可以混用，只有成员节点要求这两个版本 |
| 节点数 | 至少 **3 台**（仲裁节点必须是奇数、至少 3 个；磁盘至少分布在 3 台上）。测试布局可以 1 台，只用于测试 |
| 磁盘 | 每台 NSD 节点至少一块空闲盘（不是系统盘、没有挂载、没有被本地池占用） |
| 软件包仓库 | 控制面要配置 S3（`S3_ENDPOINT`，内置 MinIO 即可），安装包存在里面 |
| 网络 | 成员节点之间内网互通，端口 22、1191 |
| 空间 | 每台 `/var/mmfs` 所在文件系统至少 10 GiB 空闲 |
| 内存 | 每台成员从可分给云服务器的内存里预留 **pagepool + 1 GiB**（默认 2 GiB） |
| 其他 | Secure Boot 关闭（要加载自己编的内核模块）；时间已同步；内核头文件包能装上 |

GPFS 只有安装包里列出的发行版能装（6.0.0.2 是 Ubuntu 22.04 / 24.04）。

## 第一步：上传安装包

界面「存储 → 软件包」→「上传」：

1. 选存储类型（GPFS），选本地的安装包文件（如 `Storage_Scale_Erasure_Code-6.0.0.2-x86_64-Linux-install`，约 1.7 GB）。也可以填一个下载地址，由平台自己拉取。
2. 文件按 8 MiB 一片顺序上传，有进度条。**中途断网或点了「停止」，已传的部分保留**：按钮变成「继续上传」，从断点接着传；关掉弹窗后再选同一个文件也会接着传。没传完的包 24 小时后自动清理。
3. 传完后平台校验 SHA-256、解析版本、版本类型（数据访问版 / 数据管理版 / 纠删码版）、支持的发行版和许可证，状态变为「可用」。
4. 点该行的「许可证」，阅读全文后勾选并「接受许可证」。**没接受许可证的包不能用来部署。**

各节点部署时从仓库下载，缓存在 `/opt/cloudland/cache/storage-pkg/<SHA-256>/`，之后加节点、重装直接用缓存。

---

## 第二步：扫描磁盘

在每台要加入的节点上「扫描磁盘」（计算节点详情 → 存储，或 `POST /hypers/{uuid}/disks/scan`，约 10 秒），确认要用的盘显示为「空闲」。磁盘状态的含义见[配置本地存储池](./08-storage-pools.md)。

装了 GPFS 的节点上：

- 带 GPFS 分区类型（新格式 NSD）的盘显示为 `unknown_member`，不能选，也不能勾「擦除」拿去用
- 没有签名、但盘头 4 MiB 不全为零的盘也显示为 `unknown_member`（可能是旧格式 NSD）；全新的盘和 CloudLand 释放时擦过的盘（两端各清零 10 MiB）显示为空闲
- 已经属于某个集群的盘显示为 `gpfs_nsd`

## 第三步：创建集群

界面「存储 → 存储集群」→「新建集群」，按向导走：

| 步骤 | 内容 |
|---|---|
| 类型 | 「部署 GPFS」（托管）或「导入外部 GPFS」 |
| 软件 | 选已接受许可证的安装包 |
| 节点与磁盘 | 勾选节点、为每台选角色、选磁盘。默认第一台是「管理 + 仲裁 + NSD」，其余「仲裁 + NSD」 |
| 参数 | 文件系统名（默认 `fs1`）、块大小（1M–16M，默认 4M）、数据副本数（2 或 3，默认 2）、pagepool（默认 1024 MiB）；「测试布局」只用于单机测试 |
| 预检 | 在每台节点上检查一遍（下表），全部通过才能进入下一步 |
| 确认 | 填集群名（字母开头，最多 63 个字母、数字和 `. _ -`），开始部署 |

**角色规则**：仲裁节点奇数、至少 3 个；管理节点 1–2 个且必须同时是仲裁节点；NSD 节点至少一块盘；磁盘至少分布在 3 台节点上（每台一个失败组）；数据副本数不超过失败组数。元数据固定 3 副本。

**预检项**：系统与内核（`os`）、内核头文件（`kernel_headers`）、Secure Boot、时间同步、到其他成员的 22 / 1191 端口（`network`）、每块盘的身份与是否空闲（`disk <id>`）、`/var/mmfs` 的空间、内存（可分给云服务器的内存和将要预留的量）、包管理器没被占用、主机名、节点上是否已有不归 CloudLand 管的 GPFS（`existing`）。

**部署过程**（12 步，三台实测约 7–9 分钟）：预检 → 加入（写集群 SSH 密钥、预留内存）→ 下载安装包 → 安装 → 编译内核模块 → 集群内 SSH 信任 → 建集群 → 启动（GPFS 自己有约 90 秒的安全恢复等待）→ 核对磁盘身份 → 建 NSD → 建文件系统并全部挂上 → 收尾。部署后：

- 每台 `/gpfs/<文件系统>` 挂好，开机由 `mmautoload` 自动启动并挂载（`gpfs.service` 显示 disabled 是正常的）
- `/var/mmfs/etc/nsddevices` 只列本集群认领的盘，GPFS 看不到别的盘
- 内核相关的包被 `apt-mark hold`，避免升级内核后模块不匹配
- 设置了 `autoload=yes`、`autoBuildGPL=yes`、`restripeOnDiskFailure=yes`

**任务失败**：停在出错的那一步，任务详情里能看到每台节点的报错和日志末尾。修好原因（比如节点断网、包管理器被占用）后点「重试」，只重跑失败的那几台；或「中止」后删除集群重来。节点离线 5 分钟会把它的这一步判失败。

## 纠删码布局（ECE）

用 IBM Storage Scale **纠删码版**（Erasure Code Edition）的安装包，可以把 NSD 节点的盘组成一个**恢复组**，文件系统建在带纠删码的**纠删码卷**上：比如 4+2p，每 4 份数据配 2 份校验，坏 2 块盘数据仍完整，磁盘利用率约 2/3，比 2 副本、3 副本都高。之后在上面建共享存储池、云硬盘、系统盘，和副本集群一样用。

**IBM 支持的条件**（不满足时 IBM 不提供支持，CloudLand 只用它做功能验证）：

- 物理服务器（x86 不支持虚拟机），每台 16 核、64 GB 内存以上；
- 网络 25 Gbit/s 以上；
- 数据盘是 SAS 盘接在 LSI 等 SAS 卡上（直通），或直连的 U.2 NVMe，不支持 SATA；
- 每台还要至少一块 SSD / NVMe 放日志。

**CloudLand 的要求**（程序会检查）：

| 项目 | 要求 |
|---|---|
| 安装包 | **纠删码版**（只有它带 `gpfs.gnr*`）：选了纠删码布局时向导只能选纠删码版的包，其他版本置灰；直接调接口建集群也会被拒。装包时会顺带装 `lsscsi`、`sg3-utils` |
| 恢复组服务器 | 就是 NSD 节点，**3–32 台**；只有它们能给盘，其余节点作客户端 |
| 磁盘 | 每台**盘数相同**，暂时只支持**一种介质**；合计**至少 12 块**，并且比纠删码宽度多 2 块以上（8+3p 宽 11，要 13 块以上） |
| 内存 | 服务器的 pagepool **至少 8192 MiB**（`mmvdisk` 的硬性要求），每台服务器预留 pagepool + 2 GiB，客户端预留 2 GiB |
| 槽位映射 | 实体服务器先在每台上运行 IBM 的 `ecedrivemapping`（SAS 卡用 `--mode lmr`，NVMe 用 `--mode nvme`）生成槽位映射。虚拟机、模拟盘没有槽位，要勾选「不要求槽位映射（仅用于测试）」，它同时关掉恢复组的磁盘易失写缓存检查 |

**创建**：向导第一步选「GPFS 纠删码（ECE）」，参数页填：

- 文件系统名；
- 纠删码：4+2p、4+3p、8+2p、8+3p、三副本、四副本；
- 块大小：按纠删码限定；
- 纠删码卷占用：恢复组可用空间的百分比，默认 80；
- 服务器的 pagepool。

纠删码布局没有单机测试形态，也没有数据副本数（数据由纠删码保护，只存一份）。

**部署过程**（15 步）：前 8 步和副本集群相同，之后依次是：
1. 核对磁盘身份（不写 `nsddevices`）；
2. 配置服务器：建节点类，检查每台的磁盘拓扑一致，配置后 GPFS 逐台重启；
3. 槽位：检查槽位映射，或者按「不要求槽位映射」关掉槽位检查和写缓存检查并逐台重启；
4. **建恢复组**：要格式化每个日志组的日志盘，机械盘上要一两个小时，步骤超时 8 小时；
5. 建纠删码卷；
6. 建文件系统并全部挂上；
7. 收尾。

部署后集群详情显示「布局：纠删码 · 4+2p」、恢复组和纠删码卷的名字（`cl<集群号>_rg`、`cl<集群号>_vs`）；「磁盘」标签里每块盘的名字是它在恢复组里的物理盘名（`n001p001` 这种）。

**健康**：部署完成时如果集群健康是 warning、原因是「GPFS has 1 degraded」，多半是 `ess_config_mismatch`：GPFS 的组件库里没有这些服务器（`mmlscomp` 为空），组件只能登记 IBM / Lenovo 的已知型号，其他服务器和模拟盘上这个警告消不掉，不影响使用。每块物理盘的状态进健康检查。坏盘、拔掉的盘会显示为 `diagnosing`、`missing` 等并告警，纠删码在剩下的盘上自动重建，读写不受影响；盘回来后自动恢复。

**第一版的限制**：
- 不能加减节点、加盘、移除盘、换盘、改角色、重新均衡、升级，界面上不显示这些按钮，接口返回 400；
- 删除集群照常（先拆文件系统、纠删码卷、恢复组，再删集群）。建到一半的恢复组（比如建恢复组那一步被中止）普通删除会失败，这时先停掉恢复组服务器上的 GPFS，再强制从配置里删掉；这些盘上的旧数据不清，下次认领要勾「清除旧数据」。

**用模拟盘测试**（只用于测试，IBM 不支持）：每台节点只有一块数据盘时，可以在节点上用 LIO（`targetcli`，`tcm_loop`）把 fileio 文件做成多块带 WWN 的 SCSI 盘，`mmvdisk` 认作机械盘。每块盘都要 `set attribute emulate_write_cache=1`：GNR 诊断盘时的读命令带 DPO 位，LIO 只在盘声明了写缓存时接受，不打开时盘一慢就卡在诊断里、建恢复组挂住。部署时勾「不要求槽位映射」，平台会关掉 GNR 对写缓存的检查（`nsdRAIDDiskCheckVWCE=no`，否则 GNR 会把声明了写缓存的盘的数据迁走）。模拟盘都在同一块物理盘上、写直通每次同步，建恢复组很慢：试验虚拟机里每台 5 块盘建了 3.5 小时。健康检查里 `mmhealth` 的历史事件（以前的节点被驱逐、服务器 panic 等）会让整体一直是 warning，要在节点上 `mmhealth event hide` 或 `resolve` 掉。

## 第四步：建共享存储池

界面「存储 → 存储池」→「新建共享池」：

| 字段 | 说明 |
|---|---|
| 集群、文件系统 | 只列就绪的集群 |
| 名称 | 区域内唯一 |
| 介质 | 文件系统有多种介质时，按介质放到对应的 GPFS 存储池；只有一种时选「不限」 |
| 配额（GB） | 设了配额的池容量就是配额（`df` 显示配额）。**0 表示不设**：不设配额的池与同一文件系统、同一 GPFS 存储池上其他不设配额的池**共用**容量 |
| inode 上限 | 云硬盘是少量大文件，默认 100000 足够 |
| 超分比例 | 已分配的总量最多为「容量 × 比例」 |

建池是集群上的任务（约 30 秒）：建 fileset、设配额、建 `volumes/ images/ nvram/ tmp/` 与 `.cloudland-pool` 标记文件，再把池清单发给所有成员节点。之后改配额（存储池详情或 `PATCH /storage_pools/{id}` 的 `quota_gb`）也是一个任务。

**删池**：池里还有卷时拒绝（409）；空池删除时先从各节点撤掉清单、再删 fileset。

---

## 使用共享池

- **建云硬盘**：选共享池即可。卷在建卷时就由任一能访问这个池的节点落盘（几秒内从「创建中」变「可用」），不属于任何一台机器
- **挂载**：可以挂给任何一台「这个池可用」的节点上的云服务器；卸下后可以换一台节点再挂，数据不变。磁盘以 `cache='none'`、`error_policy='stop'` 挂载
- **扩容**：挂着的卷在线扩容（虚拟机不重启，立即看到新容量），没挂的离线扩容；虚拟机内仍要自己扩展分区和文件系统
- **删卷**：异步（返回 202），由任一能访问池的节点删文件
- **迁移**：共享盘留在原地不复制，迁移计划里标为「共享，不复制」；本地系统盘仍按本地盘的方式复制。磁盘全在共享池里的云服务器开机时只迁内存、关机时只转移定义，用时与磁盘大小无关。实测带 3 GB 共享数据盘的热迁移 9 秒完成
- **系统盘**（S4）：创建云服务器时「系统盘存储池」选共享池即可，云服务器可以放在可用区里任何能访问这个池的节点上，容量按池准入。系统盘不是从镜像下载，而是从**池里的镜像副本**克隆（GPFS `mmclone`，池的 `clone_mode` 为 `copy` 时整盘复制）：某个镜像**第一次**在这个池里使用时，平台先挑一台节点把镜像复制进池（`<池>/images/image-<ID>-<前缀>.qcow2`，只读的克隆父文件），这期间云服务器停在「创建中」，原因写着在等镜像复制；之后同一镜像建云服务器是秒级。UEFI 的变量放在 `<池>/nvram/`，迁移不复制
- **镜像副本的清理**：删除镜像时，池里还有系统盘从副本克隆就保留副本，最后一块删掉后自动删除；删池时副本随池删除。有镜像正在复制进池时不能删池，也不能删这个镜像（3 小时没回报的复制不算）。副本在池里被手工删掉时，下一台云服务器创建失败、副本记录转为出错，再下一台会重新复制
- **默认池**：共享池可以设为默认池，之后不指定池的云硬盘**和系统盘**都落在它上面；某个可用区（或指定的宿主机）用不了这个池时，不指定池的系统盘退回内置池

**可用性**：每台节点每 30 秒探测一次池（文件系统类型、标记文件、能否写），状态变化或每 5 分钟上报。某台节点上的池不可用时（GPFS 没挂上、标记文件不对、探测卡住），往这台节点上的云服务器挂卷会被拒绝并说明原因；探测在池没挂上时**不会**往根文件系统上写任何东西。15 分钟没有上报的节点按不可用处理。

**开机**：节点重启后，磁盘在共享池上的云服务器先进「待启动列表」（界面显示「等待存储就绪」），等 GPFS 挂上、本次开机后的第一次探测通过再自动启动。实测重启一台节点后约 4–5 分钟全部恢复；重启期间集群保持另外两台在线，其他节点上的云服务器不受影响。

## 运维

在集群详情页操作（都是集群上的任务，一次只能跑一个）：

| 操作 | 说明 |
|---|---|
| 添加节点 | 新节点先预检，再安装软件、加入集群；选了盘的同时加进文件系统 |
| 添加磁盘 | 只列集群成员上的空闲盘；NSD 名接着已有的编号 |
| 移除磁盘 | 先把数据迁到其他盘（`mmdeldisk`），再从节点上擦掉盘。移除后剩下的布局仍要满足角色规则，否则拒绝 |
| 移除节点 | 节点上有本集群池里的卷挂着的云服务器时拒绝；有盘先移盘，仲裁节点先降为非仲裁，再删节点，最后清理节点上的 GPFS |
| 离线移除 | 节点已永久损坏时用，要求节点离线并输入主机名；盘以「已损坏」方式移除，节点上不做清理 |
| 重新均衡 | 加盘之后把数据分到所有盘（`mmrestripefs -b`），耗时且 I/O 重，按需手动做 |
| 换盘 | 只对健康检查报告不是 `up` 的盘（磁盘表「报告的状态」）出现；选同一台节点上的空闲盘。先建新 NSD，再以「已损坏」方式移除坏盘（`mmdeldisk -p`，不搬数据），加入新盘，最后 `mmrestripefs -r` 补齐副本。移除前节点上再查一次 GPFS 的状态：坏盘此刻必须是 `down`（或 `unrecovered`），`up` 或 `recovering`（正在被拉起）时任务失败，提示按正常方式移除。磁盘状态超过 10 分钟没更新时不让换。坏盘不擦除，换完再拆 |
| 改角色 | 节点表的「改角色」：增减仲裁节点（连同 manager）与管理节点，在线进行（去掉仲裁前先把集群管理器、文件系统管理器挪到别的仲裁节点）。仲裁节点要保持奇数，管理节点 1–2 台且是仲裁节点。NSD 角色跟着磁盘走 |
| 自动加为客户端 | 概览「自动加为客户端 → 设置」选可用区：这些可用区里不在集群中的在线节点（开启时已有的也算）在集群空闲时逐台以客户端加入。预检不过的节点（例如系统不受支持）标为「加入失败」不再重试，它在节点表里是「异常」，移除后点「重试失败的节点」 |
| 删除集群 | 要输入集群名确认，可选同时卸载软件包；集群上还有池时拒绝。删除后节点上没有 GPFS 的进程、密钥、挂载、内存预留，盘被擦除、扫描为空闲 |
| 轮换密钥 | 换掉管理节点登录各成员用的集群 SSH 密钥，每台成员都要在线。分三轮：所有节点先同时接受新旧两把（`authorized_keys` 里多一行 `…-rotate`）→ 管理节点换用新私钥并逐台登录核对 → 去掉旧的。中途中止也不会登录不了：中止的轮换留下的第二行在下一次写信任时删掉 |
| 升级 | 选「软件包」里比当前版本新、已接受许可、同一版本类型的安装包。先下发到所有节点，再逐台（不在仲裁里的先）：把这台上用本集群存储、正在运行的云服务器迁走（与维护模式相同，迁不走时任务失败并写出原因，处理后重试）→ 把这台的文件系统管理节点 / 集群管理节点角色交给另一台 → 停 GPFS → 装新包 → 重新编译 → 启动、挂载、拉回这台的盘，所有盘 up 才轮到下一台。其他节点上的云服务器不出错，每台节点离开 / 回来时写盘会停几秒（GPFS 恢复与拉盘；实测 4–8 秒）。2026-10-06 在 work-x 上从 5.2.3.8 升到 6.0.0.2 实测：三台 11.5 分钟。全部完成后集群版本换成新的（之后加入的节点装新版本）。中途中止时已升级的节点跑新版本（GPFS 允许混跑），再升级一次就接着做完 |
| 完成升级 | 「升级」里勾选「完成升级（不可逆）」：所有节点都跑新版本后，`mmchconfig release=LATEST`、每个文件系统 `mmchfs -V full`。之后旧版本的节点不能再加入，无法回退 |

**掉线的 NSD**：节点重启后它的盘由 GPFS 自己的自动恢复拉起（`restripeOnDiskFailure`）；平台每分钟再检查一次，所有节点都 active 时把仍然 down 的盘启动（`mmchdisk start -a`，10 分钟最多一次），日志在管理节点的 `/opt/cloudland/log/storage/gpfs-disks-up.log`。

**健康检查与告警**：平台每分钟让管理节点检查一次集群（`mmgetstate`、`mmlsdisk`、本机挂载、`mmhealth`），结果在概览「健康检查」卡片里。六种告警发到**系统组织**的通知渠道（「告警事件」页也能看到）：集群不健康、节点离线、磁盘离线、文件系统没挂上（这四种持续「告警延迟」才发，默认 2 分钟）、存储池用量过高（默认 80% 警告、90% 严重，立即发）、Ceph 容量接近满。延迟和两条用量线在「系统设置 → 常规 → 存储告警」里改。超过 5 分钟没有检查结果时健康显示「未知」，再过告警延迟会发「集群不健康：can not be checked」（critical，管理节点全离线、或检查一直没有结果），看管理节点是否在线、`/opt/cloudland/log/storage/health-<集群UUID>.log`。报告里没有列出的节点或磁盘（查询超时）保持原来的告警状态，不算恢复

**监控曲线**：集群详情的「监控」标签，有存储池用量、容量、吞吐、IOPS、节点（GPFS 运行中的节点数、每个文件系统挂载的节点数）。数据来自各成员的 node_exporter：心跳每分钟在后台写 `/var/lib/node_exporter/cloudland_storage_<集群UUID>.prom`（挂载、容量、`mmpmon` 读写计数、`mmhealth` 组件），池探测写 `cloudland_shared_pool_<池UUID>.prom`。node_exporter 要开 textfile 采集（部署脚本已配好）

**任务的完整日志**：任务详情里回调只带回每次运行日志的最后 64 KiB；展开一次运行点「下载完整日志」，平台让那台节点把日志（最后 16 MiB）传回来再下载。要求 `.env` 里有 `CAPTURE_UPLOAD_SECRET`，节点能访问 clapi 的内部地址（与从云服务器创建镜像相同）

**孤儿对账**：共享池详情页的「孤儿对象 → 检查」，由一台能访问池的节点列出池里的文件，平台比对记录后列出没有记录的（无记录的卷、记录已删除的卷、镜像副本、NVRAM、临时文件、其他）。**只列出、不删除**：确认确实是遗留的再到节点上手工删。最近一小时改过的文件、不到一天的临时文件不列

**节点宕机后的恢复**（设计文档 §11）：

- **对账**：节点开机后、或和控制面断开超过 60 秒又连上后，先把本机定义的云服务器报给平台，平台说仍归它的才启动（开机时磁盘在共享池里的先显示「等待对账」），已经在别处恢复的、已删除的只清掉定义（`virsh destroy`、取消定义），**不碰盘**。节点详情「宕机恢复」卡片显示上次对账时间
- **疏散**：节点离线（状态「离线」）满 5 分钟后，节点详情「操作 → 疏散」：全部磁盘都在共享池里的云服务器在同可用区、能访问其存储池的其他节点上用原来的盘重新定义（原来运行的启动、关机的保持关机），本地盘的列为「不能恢复」。**先隔离**：另一台管理节点 `mmexpelnode -N` 把宕机节点驱逐出集群（持久，节点回来也挂不上文件系统），确认后才在别处启动，避免两边同时写同一块盘。迁移列表里是「疏散」类型的记录，隔离完成前显示「隔离中」
- **确认已断电**：能执行隔离的管理节点只有宕机的那台、或导入的集群（平台不对它执行管理命令）时，疏散要勾选「已确认这台节点已断电」——先经 IPMI 或云平台确认它真的关了。勾选后也不等满 5 分钟。记入审计（`hyper.evacuate_confirmed`）
- **驱逐活着的节点**（只断了管理网）：GPFS 要等被驱逐节点的租约过期才恢复，这段时间（最长约一分钟）其他节点上的文件系统会卡住；平台的隔离步骤等文件系统重新响应后才算完成，然后才下发疏散
- **解除隔离**：节点回来、对账清掉了被疏散走的云服务器，**再过 5 分钟**平台自动 `mmexpelnode -r`（先让节点做完开机同步：开机约一分钟就解除时，GPFS 加入撞上节点重建网络，曾把内核网络锁卡死、拖住整个文件系统）。也可以在「宕机恢复」卡片上「解除隔离」立即解除（节点刚开机时最好等它跑完开机同步），或「已手工解除」只删记录。驱逐期间 `mmexpelnode -l` 能看到它，格式是 `<地址> (<节点名>)`。隔离失败的记录（驱逐可能已经生效）同样会在节点回来后撤销，撤销失败的每 5 分钟重试；节点被移出集群（含离线移除）后它在该集群的隔离自动撤销，节点上还有隔离记录时不能删除这台节点
- **万一节点卡在 GPFS 里**（sshd 报 `Exceeded MaxStartups`、文件系统在其他节点上也卡住）：在管理节点上 `mmexpelnode -N <节点>` 先把它驱逐，其他节点几十秒内恢复；被系统卸载的节点 `mmmount <fs>` 重新挂上，上面打开着文件的云服务器要强制重启；卡住的节点断电重启后，等它开机完成再 `mmexpelnode -r -N <节点>`

**导入外部集群**：节点已经是那个集群的成员（GPFS 由对方管理员装好、文件系统已挂载）。向导里选「导入外部 GPFS」、选节点、填文件系统名与挂载点，平台只检查不改动。之后建共享池时填文件系统上已有的目录（通常是独立 fileset 的入口），平台在里面建子目录；删池、删除集群都只是取消登记，不执行任何 `mm` 命令。

## 常见问题

- **预检不过**：任务详情里按节点逐项列出原因。常见的是内核不在支持列表（26.04、HWE 内核）、`existing`（节点上有别人装的 GPFS）、盘有数据（勾「擦除」）、包管理器被 unattended-upgrades 占着（等几分钟再预检）
- **部署卡在某一步**：任务详情看那台节点的日志末尾；节点上完整日志在 `/opt/cloudland/log/storage/run-<run id>.log`，GPFS 自己的日志在 `/var/adm/ras/mmfs.log.latest`
- **池在某台节点上不可用**：`mount -t gpfs` 看是否挂着、`/usr/lpp/mmfs/bin/mmgetstate -a` 看守护进程、`cat <池目录>/.cloudland-pool` 看标记文件；节点上的探测结果在 `/opt/cloudland/run/pools/<池 UUID>.state`
- **告警没发出来**：先看「告警事件」页有没有；没有时看概览「健康检查」的检查时间是否在更新、告警延迟是否还没到；有事件但没收到，检查系统组织有没有启用的通知渠道
- **监控标签没有曲线**：Prometheus 里 `prometheus_node_exporter` 的目标是否 up、节点上 `/var/lib/node_exporter/cloudland_storage_*.prom` 是否每分钟更新
- **NSD 一直 down**：`/usr/lpp/mmfs/bin/mmlsdisk <文件系统>`；所有节点都 active 后平台会自动启动，也可以手工 `mmchdisk <文件系统> start -a`
- **新盘在 GPFS 节点上显示 `unknown_member`**：盘头有旧数据。确认盘上没有要的东西后在节点上 `wipefs -a` 并把开头 4 MiB 清零，再扫描
- **节点能不能装**：GPFS 节点只能是 Ubuntu 22.04 / 24.04 的 GA 内核；内核升级前确认 `mmbuildgpl` 能编过，部署时已经 hold 住内核包
