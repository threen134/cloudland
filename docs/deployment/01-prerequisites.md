# 前置要求

在开始部署 CloudLand 前，请确保您的物理机及操作系统满足以下最低要求。根据控制面与计算面（分层部署）的不同，资源需求有所区别。

---

## 控制节点 (Control Node)

控制节点负责集群管理、认证、数据库及监控告警，建议配置如下：

### 1. 硬件资源
- **CPU**: 至少 4 核心（建议 8 核心以上）。
- **内存**: 至少 4GB（建议 8GB 或更高，监控与数据库组件较为占用内存）。
- **磁盘**: 至少 20GB（生产环境建议准备 100GB 以上 SSD，用于存放系统镜像、日志和监控 TSDB 数据）。

### 2. 操作系统
- **推荐**: **Ubuntu 22.04 LTS** (Jammy Jellyfish)。
- **内核**: 5.15+。
- **软件依赖**:
  - `Docker Engine`: v24.0+
  - `Docker Compose`: v2.20+
  - `openssl` & `gnutls-bin`: 用于本地自签名证书生成。
  - `git`: 源码克隆与版本同步。

### 3. 网络配置
- **固定 IP**: 必须为控制节点配置静态 IP 地址，防止元数据同步失败。
- **公网/管理网**: 
  - `PUBLIC_IP`: 最终用户访问 Web UI 的入口。
  - `INTERNAL_IP`: 组件间内部通信（Database, Gateway to API）使用的私有 IP。

---

## 计算节点 (Compute Node)

计算节点负责运行工作负载（虚拟机），资源需求取决于业务量级：

### 1. 硬件资源
- **虚拟化支持**: **CPU 必须支持硬件虚拟化** (Intel VT-x 或 AMD-V)。在执行部署前，请确保 BIOS 中已开启虚拟化。
- **外挂存储**: 建议在 `/opt/cloudland` 目录下挂载专用的大容量磁盘或分布式存储。

### 2. 操作系统与软件
- **推荐**: **Ubuntu 22.04 LTS**。
- **内核参数**: 需开启 `ip_forward` 以支持路由模式。
- **环境检查**: 执行 `ls /dev/kvm` 应当返回结果。

---

## 网络拓扑建议

为确保集群稳定，我们建议将网络划分为以下三个平面：

1. **管理平面 (Management)**：控制面与计算面通信的私有网络。建议带宽 1Gbps 以上。
2. **数据平面 (Data)**：虚拟机业务流量。根据需求可采用 VLAN 或 VxLAN。
3. **公共平面 (Public)**：管理系统出口。

---

## 防火墙端口要求

若您开启了防火墙或使用安全组，请放行以下关键端口：

| 组件 | 端口 | 协议 | 范围 | 用途 |
| :--- | :--- | :--- | :--- | :--- |
| **Nginx** | 80, 443 | TCP | 全网/堡垒机 | Web 管理及 API 入口 |
| **ConsoleProxy** | 9443 | TCP | 全网 | VNC 远程控制台代理 |
| **CloudLand** | 9988 | TCP/UDP | 管理网 | SCI 南向核心控制通信 |
| **CLand (API)** | 5006 | TCP | 管理网 | clapi 向主控下发指令 |
| **Prometheus** | 9090 | TCP | 管理网 | 监控指标查询 |
| **Grafana** | 3000 | TCP | 管理网 | 监控看板展示 |

> [!TIP]
> 后端数据库 (5432) 和内部鉴权 (8255/8000) 默认应仅在 `127.0.0.1` 或容器内部网络中可见，不建议直接对外暴漏。
