## 2. VPC 与子网

### 2.1 VPC

- `POST /vpcs {name}`：自动建 `<name>-native` 安全组（预置对全网开放的 22 / 3389）
- 删除：还有子网、浮动 IP、端口映射、负载均衡、VPN 网关或中转网关挂载时拒绝（按这个顺序检查，先报 VPN 网关与中转网关）；删除后各节点上的路由器 netns 一起清掉
- VPC 网关是 anycast：每个承载该 VPC 的节点的路由器都持有同一个网关地址（MAC 按节点不同）；所以从一个节点的路由器访问另一个节点上的云服务器必然不通，验证连通性要在云服务器所在节点或从另一台云服务器发起

### 2.2 子网类型与校验

- 类型：`internal`（VPC 内，VXLAN，VNI 自动分配）、`public` / `private`（VLAN，只有系统管理员能建，不能放进 VPC）、`site`。建子网接口的 `type` 只接受这四种，不填按 `internal`，别的值 400（2026-10-16；原先填 `vrrp` 或任意字符串能绕过下面的网段与 VXLAN 校验，填 `vrrp` 的子网删掉时还会把 VPC 的 VRRP 子网记录清零）。VRRP 子网（`vrrp`）只由负载均衡 / VPN 网关在内部建（§7.7）
- 名称 2–64；`network_cidr` 是 IPv4 CIDR，地址数要在 5–1000 之间；`gateway` 必须是纯 IP（带掩码 400）；起止地址与网关要在网段内
- 内部子网必须带 VPC；新环境要先建 `public` 子网，系统路由器从中取公网地址
- VPC 里的子网（不管类型）的网段，下面任一条冲突就 400（131111）（2026-10-16 起；原先只有中转网关成员之间查重叠，同一 VPC 能建出重叠的子网，两个口的直连路由互相压、其中一个在节点上不通）：
  - 与本 VPC 的任何子网重叠（含 VRRP 子网）
  - 落在路由器自用的保留网段里：VRRP 子网 `192.168.196.0/24`、中转网关互联 `169.254.254.0/24`、路由器互联口 `169.0.0.0/8`（VRRP 子网自己不查这一条）。这份保留网段子网、中转网关挂载（`vpc-transit-gateway-plan.md` §2.5，133014）、VPN 网段（`vpn-gateway-plan.md` §10）共用
  - 与本 VPC 的 VPN 网关路由的网段重叠：对端网段、BGP 汇总网段、客户端地址池（反方向——VPN 网段与已有子网——在 VPN 网关那边查）
  - VPC 挂在中转网关上时，与其他成员的网段或它们的 VPN 网段重叠：这一条报 400 133014（VRRP 子网不查，`vpc-transit-gateway-plan.md` §2.5）
- 指定 VXLAN（`vlan`）：内部子网与 VRRP 子网的 VXLAN 必须在 4096–16777215（400），而且不能被任何子网用着——别的 VPC 的、本 VPC 的都不行（409 131112）；不指定时自动分配（2026-10-16 起；原先任意值都能建成）。原因：节点上同一个 VNI 的东西共用网桥与上联口，用别的 VPC 的 VNI 就接进了它的二层网络，4095 以下落到物理 VLAN 上；同一 VPC 两个子网共用一个 VNI 时，节点上已经有这个口就不再建，第二个子网的网关地址配不上。界面三处新建子网弹窗的 VXLAN 输入从 4096 起
- 并发：建 VPC 里的子网先锁 VPC 那一行（与中转网关挂载同一顺序：先 VPC、后网关），同一 VPC 同时建的子网互相看得到；指定了 VXLAN 时再取一把全局的 PostgreSQL 咨询锁，两个 VPC 同时用同一个 VXLAN 只有一个成功

### 2.3 节点侧对象

- 内部子网：VXLAN 上联口 `v-<vni>`（dstport 固定 8472）挂在网桥 `br<vni>` 上，路由器 netns 里的网关口 `ns-<vni>`（经 veth 对端 `ln-<vni>` 接到网桥）；VXLAN 没有泛洪条目，跨节点的转发与邻居条目由平台按网卡所在节点写入
- 网关口不只在有云服务器的节点上：VRRP 子网的口在负载均衡 / VPN 网关的两个节点和经它们转发的第三节点上，中转网关成员 VPC 的口在中转网关涉及的节点上。每个节点的路由器各有一份，删子网时要逐个节点清（§2.4）
- 同一路由器里不会留下网段重叠的两个口：建口时（`set_subnet_gw.sh`）先拆掉与新网段重叠的旧口（删除时没清到的残留），连同它的 dnsmasq、DHCP 目录、网桥与 `ln-` 的 FORWARD 规则，新口照常加 `fip-` 表路由；拿不到路由器锁时不拆，只记日志（2026-10-16）
- 建、删 VPC 里的子网后，本 VPC 的 VPN 网关配置（本端网段）与中转网关状态（VRRP 子网不触发）在最外层事务**提交之后**才重新下发，回滚就不发；VPN 下发出错只记日志，子网操作照常成功（2026-10-16；原先在事务里下发，回滚后节点上留着错误的配置，网关没有公网地址这类状态还会让子网建不出来）
- 内部子网自带 DHCP：路由器 netns 里每个 VNI 一个 dnsmasq，按 MAC 静态绑定；删云服务器时释放租约
- 普通 VLAN 子网按设计不提供 DHCP（见 `compute-behavior.md` §2.2）

### 2.4 删除

子网里还有被占用的地址（云服务器网卡、浮动 IP 等）或被 VPN 连接列为本端网段时拒绝。

删除提交之后（是删负载均衡 / VPN 网关的一部分时等最外层事务提交，回滚就不发），clapi 向**所有节点**下发 `clear_subnet_gw.sh <路由器> <vni> <网段> <网关> port|address`，节点上持路由器锁执行（2026-10-16；原先这一步从不下发，网关口只在整个路由器回收时才消失，之后同一 VPC 用同一网段——或下一个 VRRP 子网，固定是同一网段——建的子网在留着旧口的节点上不通、DHCP 起不来）：

- 本 VPC 没有别的子网用这个 VXLAN（`port`）：拆掉网关口与它的 dnsmasq、DHCP 目录、`nonat` 条目、网桥、VXLAN 上联口、`ln-<vni>` 的 FORWARD 规则；路由器在这台节点上没有别的使用者时一起回收（`clear_local_router.sh` 自己判断）
- 本 VPC 还有别的子网用这个 VXLAN（`address`，只有 2026-10-16 之前建的数据会这样）：口留下，只摘这个网段的网关地址、`fip-` 表里的路由与 DHCP 范围；同一 VPC 两个这样的子网同时删时，先锁 VPC 行，后一个看得到前一个已删、发 `port`
- 只清本路由器的东西：没有这个口、也没有它留下的 DHCP 目录的节点什么都不做；`ln-<vni>` 的另一端在**别的路由器**（有名字的 netns）里时，这个 VNI 归别的 VPC（共用 VXLAN 的旧数据）：只停本路由器这个 VNI 的 dnsmasq、删本路由器的 DHCP 目录，别的 VPC 的口、dnsmasq 与网桥、上联口都不动（2026-10-16；第一版按 VXLAN 清，拆掉过别的 VPC 的口）。另一端在没有名字的 netns 里（刚 `ip netns del`、内核还在拆 veth，或名字被删、还被 dnsmasq 占着的 netns）不算别人的
- 节点重启后口已经没了（路由器还没重建，或重建了但没有这个子网的口）：凭留下的 DHCP 目录认定这个 VNI 归本路由器，照样清网桥、上联口与 FORWARD 规则；路由器 netns 也不在时不会因此建出路由器
- 删 VPC 里最后一个负载均衡 / VPN 网关时，VRRP 子网按同一流程删除，第三节点上的 VRRP 口一起清掉
- 下发失败（cland 不可用）只记日志、删除照常成功；离线节点收不到这条命令，见 §8

### 2.5 编辑

`PATCH /subnets/:id` 只改名称（公网子网另可改优先级）；`priority` 不传不清零；类型、IP 组、DHCP 不开放（只改数据库，不会重新下发到节点）。

### 2.6 地址

- `GET /addresses/:subnet` 列出子网的地址与已分配 / 空闲；网关那一行不算空闲
- 子网网关地址不能被指定分配给云服务器或浮动 IP（400）；界面的地址下拉排除网关

## 3. 可用区

系统管理员建、改、删；全区域只有一个默认可用区；有节点或放置组时不能删。负载均衡、VPN 网关不指定可用区时落到默认可用区。

## 4. IP 组与字典

- IP 组：组织编辑者建、改、删；子网与浮动 IP 可以指定 IP 组，子网列表可按 IP 组过滤；**还有子网或浮动 IP 引用时不能删**（`ErrIpGroupInUse`，与「有子网时不能删 VPC」一致）
- 字典：系统管理员建、改、删，`value` 不能为空

## 5. 弹性公网 IP

### 5.1 申请

`POST /floating_ips {name, public_subnet(s), public_ip, instance, inbound, outbound, activation_count, group}`：可以指定地址、可以一次申请多个（`activation_count` 0–64），可以不挂实例；名称 2–32；地址不够 409；公网子网的云服务器自带 `native` 公网地址，随云服务器释放、不能单独删。配额按 `public_ips` 计。

### 5.2 挂载与节点规则

挂到云服务器后，路由器 netns 里有 DNAT / SNAT、策略路由（`ip rule pref 32000 lookup fip-<vlan>`，**新加的策略规则一律显式写 pref**）、公网口 `te-<router>-<vlan>` 上的地址；公网可达。

### 5.3 卸载与释放

卸载后 DNAT / SNAT / MARK / tc 规则全部清掉；同一路由器同一 VLAN 的浮动 IP（含负载均衡、VPN 网关的）共用 `te-` 口，只在这台路由器已经没有 `lookup fip-<vlan>` 规则时才删口。释放后地址回到空闲。

### 5.4 修改与带宽

`PATCH /floating_ips/:id`：请求体里**没有** `instance` 键时不动挂载（`{}` 不卸载），显式 `null` 才卸载；入 / 出方向限速（Mbps，0–20000）在节点上生效，`0` 表示取消限速；负载均衡的与 native 公网地址改带宽 400。

### 5.5 没有浮动 IP 的云服务器出网

经系统路由器 router-0 SNAT 出网，有意限速（默认 120 包 / 秒，节点 `cloudrc.local` 的 `system_packet_rate_limit`，只在新建路由器时生效）。有浮动 IP 的不受影响。

## 6. 安全组

### 6.1 组与默认组

- 新建的组带 7 条默认规则（出方向全放、DHCP、ICMP）；只有系统自动建的默认组（系统默认组、组织默认组、VPC native 组）预置对全网开放的 22 / 3389，用户建的组不预置
- 默认组不能删（141007）；有网卡在用的组不能删（141008）；只改描述不清名称、描述可清空
- 列表服务端分页、名称搜索、按 VPC 过滤

### 6.2 规则

- `direction` ingress / egress，`protocol` tcp / udp / icmp / gre / ipv6，`remote_cidr` 必填 IPv4 CIDR
- tcp / udp 的 `port_min` / `port_max` 是端口范围（显式传入必须 1–65535，不传表示全部端口）；icmp 复用这两个字段存 type（0–254）/ code（0–255），-1 表示任意，**0 是有效值**
- 修改时不传端口沿用原值；协议在端口类与非端口类之间切换、改成 tcp / udp 时必须传端口；重复规则拒绝

### 6.3 在节点上生效

规则下发到用这个组的网卡所在的节点（`secgroup-in-tap*` / `secgroup-out-tap*` 链）；入方向未放行的端口被丢弃（客户端超时，不是 connection refused）。FORWARD 链里安全组跳转在网桥内部放行之前，节点重启后由心跳的 `sync_instance` 重建。

## 7. 负载均衡

### 7.1 结构

每个负载均衡一个 VRRP 实例，主备各在可用区里的一个节点；VPC 路由器 netns 里跑 keepalived（浮动 IP 挂在 `te-` 口）和 haproxy。两端都以 `state BACKUP` + `nopreempt` 启动，按角色给优先级，拉起的进程不抢主。

### 7.2 创建与浮动 IP

- `POST /load_balancers {name, description, vpc, zone}`：可用区不填用默认；配额按 `load_balancers` 计
- 创建时节点上只建 VRRP 网卡与地址，**不起 keepalived / haproxy**：绑了浮动 IP（`POST /load_balancers/:id/floating_ips`，计入 `public_ips`）之后两个进程才起来
- 改名称与描述要写权限；没有启用 / 停用

### 7.3 监听器与后端

- 监听器：`mode` http / tcp，端口 1–65535，可带 PEM 证书与私钥（clapi 自己 base64 后下发）做 TLS 终结；只能改名；删除要写权限，连带删掉它的后端
- 后端：地址必须是 IPv4:端口（防止注入 haproxy 配置），可勾 `ssl` 用 TLS 连接后端；地址或 ssl 变化才重新下发
- 列表按 id 排序

### 7.4 后端健康状态

持有浮动 IP 的节点经 haproxy `admin.sock` 读状态，结果变化或满 5 分钟才回报（`backends.health`：up / down / 空 = unknown）；haproxy 启动或重载 15 秒内不报；后端改了地址后清空。

### 7.5 重载与进程守护

- haproxy 重载带 `-x <admin.sock>` 接管监听 socket，重载期间请求不失败
- 心跳每次检查并拉起异常退出的 keepalived / haproxy（先摘掉残留浮动 IP）；守护与配置脚本用 `flock` 互斥

### 7.6 单节点可用区

可用区只有一个可用节点时只在主节点上运行，接口返回 `single_node: true`、界面标「单节点」；有了第二个可用节点后自动补上备节点。

### 7.7 VRRP 子网与 VRID

- 每个 VPC 一个 VRRP 子网 `192.168.196.0/24`（第一次用到时建，最后一个实例删掉时回收），每个 VRRP 实例分一对地址；同一 VPC 同一节点的 VRRP 网卡与 MAC 共用（负载均衡与 VPN 网关同样）
- VRID 按 VRRP 子网分配 1–255；删掉一个实例后平台重发同路由器的转发条目，不误伤同 VPC 的其他实例

### 7.8 节点重启后恢复

按 boot_id 触发重建：先建 VRRP 网卡、再重发转发与邻居条目（顺序不能反），重启的节点以备节点身份加入、不抢主。

### 7.9 删除

删除后两个节点上的配置目录、进程、浮动 IP 全部清掉；连带释放挂着的浮动 IP 的配额。

## 8. 已知限制

- 普通 VLAN 子网没有 DHCP，不带 cloud-init 的镜像拿不到地址（设计如此）
- 主备节点之间断链、两台都活着时是双主（VRRP 的固有限制）
- 子网的类型、IP 组、DHCP 创建后不能改
- 删子网时离线的节点收不到清理命令，也不补发：它的残留口要等那台节点上建与它网段重叠的口时（§2.3）、或路由器在那台节点上整个回收时才清掉；在那之前这台节点的路由器里留着这个网段的一条直连路由
- 地址备注 / 锁定（`/addresses/remark`、`/addresses/update-lock`）与 site 子网的浮动 IP 挂载（`/floating_ips/site_attach|site_detach`）在 clapi 里有，但没有对外开放
