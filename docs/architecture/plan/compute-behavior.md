## 1. 权限

clapi 只按网关转发来的身份判断（`X-Org-Role`、`X-System-Role`，网关每次按数据库取，见 `cpgateway-go-migration-plan.md` §13）。组织角色：只读 1、编辑 2、管理员 3；系统管理员在所有组织都按管理员算。

| 操作 | 要求 |
|---|---|
| 列表、详情、监控曲线 | 本组织只读及以上；读不到的资源与不存在的资源回同样的错误 |
| 创建云服务器、云硬盘、镜像（含捕获）、密钥 | 本组织编辑及以上 |
| 改、删、开关机、设密码、救援、结束救援、重装、调整规格、增删改网卡、挂卸与扩容云硬盘 | 资源所属组织的编辑及以上（捕获镜像另要求对源云服务器有这个权限） |
| 创建云服务器时指定宿主机 | 系统管理员；在按 UUID 查节点之前拒绝，不能凭错误探测节点 |
| 规格的增删 | 系统管理员 |
| 镜像设为公共 | 系统管理员（系统管理员建的镜像一律公共） |
| 迁移（列表、详情、发起、候选目标） | 系统管理员（网关白名单与 clapi 都限制） |
| 主机监控曲线 | 系统管理员 |

## 2. 创建云服务器

### 2.1 参数与校验

- 主机名 2–32 字符，主机名或域名格式；批量 `count` 1–16，主机名加 `-N` 后缀，带后缀的最长主机名也不能超过 32
- 镜像必须 `available`，规格的磁盘不能小于镜像；批量创建时不能指定公网地址
- 引用不存在的密钥 400（`Invalid key`），不会建出空密钥
- 新实例记下规格（`flavor_id`），只有尺寸与规格一致时才记；用到的规格不能删（111905）
- 配额由网关预扣、成功才结算（`cpgateway-go-migration-plan.md` §13）

### 2.2 IP 地址怎么配到虚拟机里

- 地址由 clapi 分配（`addresses` 表）
- **所有子网**：config drive 的 `network_data.json`（静态地址、网关、DNS、MTU），由镜像里的 cloud-init 应用；Windows 由 guest agent 设置
- **VPC 内部子网（VNI > 4095）** 另有 DHCP：路由器 netns 里每个 VNI 一个 dnsmasq，按 MAC 静态绑定，作为不支持 cloud-init 的镜像的兜底
- 普通 VLAN 子网（public / private）**按设计不提供 DHCP**：不带 cloud-init 的镜像（如 cirros）在这类子网拿不到地址，是预期行为

### 2.3 系统盘放在哪

- 在「系统盘存储池」里选；不选用默认池，默认池是共享池而可用区（或指定的宿主机）用不了它时退回内置池
- 本地池的行为见 `local-multi-disk-storage-plan.md` §5.6；共享池见 `shared-storage-design.md` §9
- 创建后不能在本地与共享之间搬

### 2.4 下发失败

- 创建命令没能下发（cland 不可达等）时实例置 `error`，并释放系统盘的存储预留

## 3. 生命周期

### 3.1 磁盘占用时的互斥

救援（救援域挂着原系统盘）、重装与调整规格（节点脚本在改盘或定义）、迁移（在复制盘）期间，下面这些操作一律 400（`ErrInstanceInvalidState`），在任何下发之前：

- 开关机（开机、关机、重启、强制关机 / 重启、暂停 / 恢复）
- 救援、重装、调整规格
- 迁移中另外拒绝改名与删除

理由：两件事同时动一块盘会起两个 QEMU 用同一块盘（本地 qcow2 有镜像锁挡着，共享池的 RBD 盘没有）或者改写正在复制的盘。重装排队等镜像副本时（有等待记录）同样拒绝这些操作。

- **先查权限再查状态**：没有写权限的人得到 403，看不到实例处于什么状态
- **在行锁下复核**：请求在事务里 `SELECT ... FOR UPDATE` 锁住实例那一行、按锁下读到的状态再判断一次，两个同时到达的请求（例如救援与开机、两次结束救援）不会都通过
- **卡住时由系统管理员恢复**：命令被丢弃、脚本没回调就死了时，状态会一直停在 `resizing` / `reinstalling` / `rescuing`（虚拟机一直在运行时心跳不纠正）。系统管理员带 `force: true` 发电源操作（`PATCH /instances/:id {"power_action":"start","force":true}`）越过这个拦截，由他确认已经没有别的东西占着盘；其他人带 `force` 403，`force` 不带电源操作也 403。不按时间自动放开：正常的重装可能很久，按时间猜会在重装途中放进第二个 QEMU
- **界面**：这四种状态下电源菜单置灰；界面不提供 `force`

### 3.2 电源操作

`PATCH /instances/:id {"power_action": ...}`，取值 start、stop、hard_stop、restart、hard_restart、pause、resume；状态以节点回报为准。`force: true`（只给系统管理员、必须带电源操作）越过 §3.1 的拦截，用来恢复卡住的实例。审计按动作细化（`instance.start` 等）。

### 3.3 改名

`PATCH /instances/:id {"hostname": ...}`，2–32 字符、去首尾空格，审计 `instance.rename`。

### 3.4 设置登录密码

`POST /instances/:id/set_user_password`：经 guest agent 设置，用户名限 `[A-Za-z0-9._-]`、密码限可打印 ASCII；虚拟机关机时 400；节点上设不成功时原因记 `password_failed`，界面显示「密码未设置成功」。

### 3.5 登录端口

`login_port` 只改虚拟机里 sshd / RDP 的端口，**不自动放行安全组**；留空按镜像类型取 22 / 3389。

### 3.6 救援与结束救援

- `POST /instances/:id/rescue`：用镜像指定的救援镜像（或请求里的）起救援域，挂上原系统盘与数据卷，设救援系统的 root 密码；实例状态 `rescuing`
- 救援中拒绝迁移、扩容、挂卸云硬盘与 §3.1 的操作
- `POST /instances/:id/end_rescue`：只在 `rescuing` 时可用，结束后节点按实际状态回报
- 救援在关机之前就失败时，按节点回报的原状态恢复

### 3.7 重装

`POST /instances/:id/reinstall`：换镜像（可换规格、密钥、密码、登录端口），系统盘重建；共享池里先做临时盘、域停下后替换。

### 3.8 调整规格

`POST /instances/:id/resize`：只改 CPU 与内存，节点上关机改定义再开机；状态 `resizing`。

### 3.9 删除

- 删除后节点上的域、系统盘、tap、iptables 规则清掉；挂着的数据卷改回 `available`、文件保留
- 同节点同 VPC 还有别的云服务器（含关机的）、负载均衡或 VPN 网关时，VPC 路由器与网桥保留
- 共享池里的系统盘见 `shared-storage-design.md` §9

## 4. 网卡

- `GET / POST /instances/:id/interfaces`、`GET / PATCH / DELETE /instances/:id/interfaces/:interface_id`
- 每台最多 8 块；新网卡的子网 VLAN 不能与已有网卡重复，不能在 site 子网，VPC 内必须同一个 VPC
- 可指定地址与 MAC、限速、`allow_spoofing`、安全组、辅助地址数；`site_subnets` 只给主网卡
- 主网卡不能删

## 5. 显示与监控

### 5.1 状态原因

`reason` 的取值与界面文案：`storage_pending`「等待存储就绪」、`start_failed`「开机后启动失败」、`storage_full`「存储空间不足」（已暂停，空间回落后自动恢复）、`password_failed`「密码未设置成功」。开机同步的控制字 `sync` 不写进 `reason`。

### 5.2 监控曲线

- 云服务器：`POST /metrics/instances/{cpu,memory,disk,network,traffic}/his_data`，按实例 UUID 查，每个实例都要可读（同 §1，读不到 404；一次查询取全部实例，空串忽略）；网卡名、磁盘名限 `[A-Za-z0-9._-]`（最长 64），一次最多 50 个；拼进 PromQL 正则时 `.` 转义，名字只匹配它自己
- 主机：`POST /metrics/hypers/{cpu,memory}/his_data`，只给系统管理员，主机名同样限字符
- 时间参数是 Unix 秒；数据来自 Prometheus
- 关联的告警规则：`GET /instances/rule-links?instance_ids=<uuid>,<uuid>` 返回各实例关联的 VM 告警规则组与网卡；每个实例都要可读（读不到 404），最多 50 个，空项忽略

## 6. 规格与密钥

- 规格：名称 2–32，CPU ≥ 1、内存 ≥ 16 MB、磁盘 ≥ 1 GB；按名称取（`GET /flavors/:name`）、删除；系统管理员增删；在用的不能删
- 密钥：导入公钥（名称 2–32、公钥 4–4096 字符）或由平台生成；只能看到本组织的；在用的不能删；**密钥不能修改**（要换就删了重建，网关不开放 `PATCH /keys/:id`）

## 7. 迁移

### 7.1 流程

`POST /migrations` → 目标节点 `target_migration.sh`（target_prepared）→ 源节点 `source_migration.sh`（source_prepared）→ 目标 `complete_migration.sh`（completed，回传实际状态）→ 源节点清理。失败走 `source_rollback` → 目标清理 → 源节点回滚。不指定目标时由调度器选，实际节点在 target_prepared 回调里落库。

### 7.2 热迁移、冷迁移与 force

- 热 / 冷由后端判定：源节点在线即热迁移，虚拟机开着用 `--live`、关着用 `--offline`，用户不选
- `force` 不是「冷迁移」，是「源节点已离线时强行迁移」，要共享存储；本地存储 400（`Force migration is not supported with local storage`）
- 源节点离线（status 10）且是本地存储时 400

### 7.3 本地存储

- 运行中用 `--copy-storage-all`（目标预建同路径同大小的空盘），关机时先复制盘再 `--offline`；目标上已有同名盘则中止；完成后删源节点的盘
- 默认留在原池，可逐盘换池；目标没有原池时只在同一个 `fallback_group` 内自动替换（`local-multi-disk-storage-plan.md` §7）

### 7.4 网络切换

- 目标节点按元数据预建网卡与安全组，clapi 预写同 VPC 其他网卡的转发条目；源节点在 `virsh migrate` 之前预置切换用的转发条目
- 网关宣告在 completed 之后、目标重建浮动 IP 之后才发
- 源节点清理（`finish_source_migration.sh`）对 VPC 内部子网的每块网卡删掉这台在源节点 dnsmasq 里的 DHCP 绑定并释放租约（`del_host.sh`），在回收路由器之前做。原先不释放，dnsmasq 把租约留 2 小时，之后在源节点拿到同一地址的云服务器被分到平台不认识的地址、谁都连不上（2026-10-16 补测修 R2-13，`f031f9c5`；只影响靠 DHCP 拿地址的镜像）
- 实测中断：公网子网约 0.5–0.6 秒，VPC 内约 0.6 秒，浮动 IP completed 阶段再断约 1.1 秒（只丢包不断连接，决定不改）

### 7.5 进度

每 3 秒上报已传量与总量（含内存与本地盘），百分比单调不回退，completed 置 100；`GET /migrations{,/:id}` 返回 `progress`、`transferred`、`total`，阶段带失败原因。

### 7.6 心跳

迁移中（有 24 小时内更新过的进行中记录）心跳不改实例状态与所在节点，否则 6 分钟兜底。迁移卡死后心跳不会纠正，要手工恢复。

### 7.7 拒绝与失败

- cland 资源不够时回 `error=resource`，迁移失败、实例恢复迁移前的状态
- 命令没能下发时迁移失败、实例恢复
- 救援中拒绝迁移

## 8. 云硬盘

### 8.1 创建

`POST /volumes {name, size, storage_pool}`：本地池的卷创建时不落盘（`available`、不在任何节点），首次挂载时在云服务器所在节点落盘（`local-multi-disk-storage-plan.md` §5.1–5.2）；共享池的卷建卷时落盘。

### 8.2 挂载、卸载与 PATCH 语义

- `PATCH /volumes/:id`：按请求体里**有没有** `instance` 键区分——没有就不动挂载（只改名不会卸载），`instance: {id}` 挂载，`instance: null` 卸载；审计 `volume.attach` / `volume.detach`
- 已落盘的本地卷只能挂给同节点、有这个池的云服务器（400 121007）
- 系统盘不能卸载；正在挂载 / 卸载 / 扩容的卷拒绝；已挂着的卷要先卸载再挂到别处
- 救援、迁移中的云服务器不能挂卸

### 8.3 扩容

- `POST /volumes/:id/resize`；未落盘只改记录；挂着时在线扩容（`virsh blockresize`）不停机，关机或未挂载时 `qemu-img resize`
- 云服务器救援、迁移、回滚、重装、调整规格、创建、删除中拒绝
- 节点上失败时按实际大小改回容量、恢复原状态
- 虚拟机里的分区与文件系统要自己扩，界面给出步骤

### 8.4 删除

挂着的卷不能删；已落盘的卷返回 202、进入 `deleting`，节点回调后删记录，30 分钟没回调转 `delete_failed`（可以重删）；节点离线拒绝；网关把 202 当成功释放配额。`lost` 卷可以强制卸下（`force_detach`）。

### 8.5 列表

`GET /volumes` 默认只列数据盘，`type=all` / `boot` 过滤。

## 9. 镜像

### 9.1 导入

`POST /images`（`name`、`download_url`、`os_code`、`os_family`、`os_version`、`user`、`boot_loader`）：配置了 S3 时下载并上传到 S3，S3 不可用直接报错、不退回本地；`download_url` 禁止空白与控制字符；状态 `creating` → `available`，格式自动识别。

### 9.2 可见性与配额

系统管理员建的是公共镜像、不计配额；其他人建的是私有镜像、计入组织的镜像配额；只有系统管理员改 `public`。

### 9.3 从云服务器捕获

`POST /images {instance_uuid, ...}`：云服务器必须关机；要对它有编辑权限（别的组织的云服务器与不存在的回答相同）；节点用按镜像签发的上传令牌经 https 上传到 clapi。

### 9.4 修改与删除

可改名称、系统信息；有云服务器在用的镜像不能删（`ErrImageInUse`）；删除释放配额；共享池里的副本见 `shared-storage-design.md` §9。

## 10. 已知限制

- 规格名只对新建实例生效：存量实例不回填 `flavor_id`，重装、调整规格把它清成 0（`CLAUDE.md` 待办 B18）
- 同一实例几秒内连改两次密码，第一次的回调可能落到第二次上（待办 B19）
- 本地池的孤儿文件没有对账（待办 B8）
- 迁移卡死后心跳不纠正（§7.6）
