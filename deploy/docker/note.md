# CloudLand 通信架构笔记

## 核心通信矩阵

| 通信双方 | 端口 | 协议 | 范围 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| **计算节点 <-> 控制器 (Cland)** | **9988** | SCI | **跨物理机** | CloudLand 的核心命脉，用于心跳与指令分发 |
| **控制器 (Cland) <-> Web (Clbase)** | **5006** | RPC | **本地/管理网** | **下行通道**：Web 端向 Cland 下发操作指令 |
| **Web (Clbase) <-> 控制器 (Cland)** | **5005** | RPC | **本地/管理网** | **上行通道**：Cland 向 Web 端反馈由于任务产生的状态变化 |
| **Web (Clbase) <-> 数据库 (Postgres)** | **5432** | SQL | **本地/管理网** | **数据持久化**：所有的资源、配置数据存储 |

## 形象比喻
- **6188 是“对讲机”**：控制节点拿它和各地的“前线士兵”（计算节点）喊话。
- **5005/5006 是“室内内部电话”**：控制节点内的“指挥部”（cland）和“前台值班”（clbase）在交流，前线士兵无法接入。

## 网络安全隔离原则
1. **公网层**：仅暴露 80, 443 (Web 访问) 和 6188 (计算节点接入)。
2. **管理层**：5005, 5006, 5432 等高敏感端口绑定在 `INTERNAL_IP` (10.x.x.x 网段)，不对外网开放。
3. **隔离层**：计算节点无法直连数据库或 RPC 端口，所有操作必须经由 Cland 鉴权与转换。
